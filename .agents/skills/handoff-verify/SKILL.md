# 핸드오프 verify 작성

## 이 스킬의 위치

- **문서 뼈대** = [`verify.template.md`](verify.template.md) (같은 디렉토리). `docs/handoff/<NNNN-slug>/verify.md`
  로 복사해 채운다.
- **협업 규칙·상태 머신·검증 책임 분리표** = `docs/handoff/AGENTS.md`. **여기서 재서술하지
  않는다** — 먼저 읽어라.
- **이 문서** = 그 위의 **"인수 기준만 따라가면 못 잡는 것을 어떻게 잡는가"**.

## 원칙 0 — FAIL 은 정상 결과다

상태 머신이 FAIL → 재구현 → 재검증을 **전제**한다. PASS 를 목표로 삼는 순간 검증이 무의미해진다.
미충족은 plan 의 `[검증자 기입] 파생 이슈` 챕터로 이관해 라운드를 넘긴다.

특히 **설계·구현·검증이 같은 에이전트면** 그 사실을 verify 상단에 적고 §1 을 더 강하게 적용한다
(0117: "설계·구현·검증 전부 동일 에이전트 — **교차 검증 부재가 구조적 한계**", 0123 동일).

---

## 1. 역방향 탐색을 **먼저** 한다 ★핵심

**인수 기준을 읽고 코드를 찾는 순서를 뒤집는다.** 변경된 코드에서 미사용·미검증 표면을 먼저
뽑고, 그 다음에 기준과 대조한다.

0157 에서 이 순서가 **어느 인수 기준에도 걸리지 않던 인증 오판 결함**을 잡았다 — `probe` 가
`redirect:'follow'` 로 ADFS 로그인 페이지 302→200 을 따라가 "인증됨" 으로 읽었다. 기준만
따라갔으면 그대로 나갔다. 경위는 [`references/0157-case.md`](references/0157-case.md).

번들 스크립트로 출발점을 만든다:

```bash
bash .agents/skills/handoff-verify/scripts/scan-surface.sh <base>..<head>
```

커밋 범위는 **어떤 파일을 볼지**만 정하고 심볼·참조는 **워킹트리 현재 내용**에서 센다 —
검증 대상 커밋이 체크아웃된 상태에서 돌려라.

세 가지를 후보로 뱉는다 — **스크립트는 후보만 주고 판정은 네가 한다**:

| 출력 | 의미 | 오탐 판정 |
|---|---|---|
| **미사용 export** | 프로덕션 참조 0건 | 골격 API·향후 확장점이면 정상. 단 **plan 이 "지금 배선한다" 고 한 것**이면 미배선 결함 |
| **테스트에만 등장** | 정의 + 테스트 참조만, 프로덕션 호출 0 | 대개 죽은 코드. "테스트가 있으니 검증됨" 이 아니라 **아무도 안 쓴다** 는 뜻 |
| **형제 파일 정책 비대칭** | 같은 디렉토리에서 `redirect:`·`credentials:`·`sandbox:` 등이 파일마다 다른 값 | 의도된 차이면 근거를 verify 에 적는다. **근거를 못 대면 결함이다** |

스크립트 밖에서 추가로:

- **인수 기준의 핵심 동사가 테스트 파일에 등장하는가.** 안 나오면 그 기준은 미검증이다.
- **plan 이 "N곳" 이라 적은 것을 다시 grep 해 N 이 맞는지.**

## 2. 구현 보고를 증거로 취급하지 않는다

0157 의 `Criteria-Met: 16/16` 은 실제로 **14 ✅ / 1 부분 / 1 ❌** 였다.

- **테스트가 있는 기준만 충족으로 센다.** 코드가 존재하는 것은 충족이 아니다.
- 매트릭스의 증거 칸에 `파일:라인` 만 적혀 있고 테스트가 없으면 그건 **"구현됨" 이지 "검증됨"이
  아니다** — 그렇게 구분해 적는다.
- 자기 보고 일반이 그렇다. 0125: 버그리포트의 "모델이 다음 턴에 바뀐다고 답변" 은 에이전트
  자기 보고이므로 **`turn_model_usage` 원장으로 판정할 것(자기 보고 무시)**.
- 0147: "매트릭스는 '해당 인용이 그 위치에 **존재하는가**' 만 확인했지 '그 **해석이 옳은가**' 는
  사람 몫이다" — 존재 확인과 정확성 판정을 섞지 마라.

## 3. 숫자는 기계로 재측정한다

문서가 인용한 채널 수·파일 수·테스트 수를 **직접 세어본다**. 0157 은 변경 전 문서가 이미
틀려 있었고(헤더 73 / 내역 합 72 / 실측 74) 그것을 승계했다.

**내역의 합 = 총계인지 검산**한다. 이것만으로 대부분의 stale 숫자가 잡힌다.

## 4. 환경 기인 실패를 기계적으로 분리한다

이 저장소는 **better-sqlite3 ABI 가 egress 차단 환경에서 실패**하는 알려진 베이스라인이 있다
(`app/AGENTS.md` §better-sqlite3 ABI). 서명: `Could not locate the bindings file` ·
`Response code 403` · `[sqlite-abi] ensure failed`.

"변경 무관" 을 주장하려면 **실패 목록에서 베이스라인 파일을 제외했을 때 0건임을 명령으로
보여야** 한다. 실패 파일 목록을 그대로 붙이고, 각각이 DB 로드 스위트임을 표시한다.

게이트는 ABI-중립인 `npm run lint` + `npm run typecheck` 를 기본으로 삼고, 테스트는
`./node_modules/.bin/vitest run` 으로 pretest 를 우회한다(ABI 를 뒤집지 않는다).

## 5. "테스트 불가" 판정 전에 "무엇을 떼면 가능한가" 를 묻는다

0157 verify r1 이 `browser-session-store.ts` 를 "electron 의존이라 미테스트" 로 결론짓고 멈췄다.
r2 에서 떼어보니 **가능했을 뿐 아니라 `isAllowedOrigin` 이중 구현까지 드러났다**.

그리고 반복되는 특정 형태가 있다 — **renderer 순수 로직을 "UI=시각 검증" 관례로 넘기는 것**:

- 0150: "AC3·AC4 는 시각이 아니라 **로직**(`collapsedAtCount` 파생)이라 순수 함수로 추출해
  테스트할 수 있었다 … repo 관례를 근거로 넘겼으나 **관례를 방패로 썼다는 자각은 있다** → D4"
- 0151: "`chatStore` reducer 와 조건부 렌더는 순수 로직인데 테스트를 붙이지 않았다
  (**0150 verify 의 D4 와 같은 종류의 누락 — 반복하고 있다**)"
- 0157: renderer `features/auth` 의 `stepPatch`·`applyPlatformState` 가 순수한데 두 라운드
  모두 미테스트 → D8

**시각은 사람 몫이지만 로직은 아니다.** 순수 함수를 시각 관례로 넘기지 마라.

## 6. 검증 못 하는 것은 정직하게 못 한다고 쓴다

**이 저장소가 가장 잘 지켜온 관행이다 — 유지한다.** verify 가 시각·실기·레이스·SDK 런타임을
판정할 수 없다는 것은 결함이 아니라 **경계**다. PASS 를 위해 얼버무리지 말고 책임 분리표로
사람에게 넘긴다.

좋은 형태:

- 0153: "F1 의 실제 발화는 **순수 함수 수준까지만** 기계 검증했다 … 증거는 '판정 함수 + 호출
  지점' 이고, 사용자가 본 증상이 이 경로였다는 로그 대조로 뒷받침되지만 **실기 확인은 남는다**."
- 0084: "3 suite 를 직접 green 확인하지 못하고 **'환경 무관' 추론에 의존**했다."
- 0074: "W7·W8·W9 는 직접 fetch 하지 않고 W1 교차 커버에 의존 — **100% 원문 대조는 아님
  (정직하게 표기)**."
- 0094: "전수 drift 보장은 불가(**스팟 스캔**)."
- 0145: "합성 trace 단위 테스트는 분석 산식만 검증하며 **실제 성능 증거가 아니다.**"

나쁜 형태: 못 본 것을 안 적고 ✅ 를 주는 것. 대리 검증을 했으면 **무엇의 대리인지** 적는다.

## 7. 자기 리뷰 — 다음 설계로 되먹인다

템플릿의 `## 검증 자기 리뷰` 는 형식이 아니다. **여기 적힌 문장이 `handoff-plan` 스킬의
`references/failure-patterns.md` 로 축적된다.** 그러니:

- **설계 단계**: 이번 FAIL/갭의 뿌리가 설계 어디였는지 구체적으로. "인수 기준 #N 이 검증
  수단 없이 쓰였다" 처럼 *다음 plan 이 따라 할 수 있는 형태*로.
- **구현 단계**: 선조치 경계를 지켰는지, 설계를 그대로 받아쓴 곳은 없는지.
- **검증 단계**: **이번 verify 가 못 본 것.** 대리 검증한 항목과 그 한계.

새 패턴이면 `.agents/skills/handoff-plan/references/failure-patterns.md` 에 한 줄 추가한다.
