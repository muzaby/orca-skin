# chats/ — 사용자 의도 트랜스크립트 (역사적 증거)

Claude Design 핸드오프 트랜스크립트 원본. **기본 세션에서 읽지 않는다** — 어떤 결정의 *기원*을
거슬러 확인해야 할 때만 연다.

## 이것은 현재 규칙이 아니다

```text
Transcript ≠ 현재 요구사항
Transcript ≠ 아키텍처
Transcript ≠ 코딩 규칙
```

트랜스크립트의 결론 중 **지금도 유효한 것은 이미 승격돼 있다** — 제품 요구는 [`../docs/PRD.md`](../docs/PRD.md),
시스템 구조는 [`../docs/arch/`](../docs/arch/), 디자인 시스템 규칙은
[`../project/versions/v5-orca-skin/DESIGN.md`](../project/versions/v5-orca-skin/DESIGN.md) 가 갖는다.
여기서 결론을 다시 요약해 관리하지 않는다 — 요약본을 두면 정본과 갈라지고, 갈라진 요약이
현재 규칙으로 오인된다.

승격되지 않은 것은 **채택되지 않았거나 뒤집힌 것**이다. 트랜스크립트에 있다는 이유로 되살리지 않는다.

## 읽는 법

- 도구 호출은 `_[tool: name]_` 마커로 구분된다(`snip`·`read_file`·`write_file`·`view_image` 등).
  본문이 아니므로 의도 추출 시 무시한다.
- **결정 키워드**가 진실이다 — "A로 진행"·"확정"·"OK"·"Continue" 같은 **짧은 사용자 응답**이
  최종 결정 신호다. 어시스턴트의 긴 제안보다 이쪽이 우선한다.
- **시간 순서로 누적되며 후반이 전반을 덮어쓴다.** chat1 전반의 결정이 chat1 후반·chat2 에서
  뒤집힌 사례가 있다 — 한 대목만 읽고 결론짓지 않는다.
- 한국어 트랜스크립트지만 코드·UI 라벨은 영어 혼용. 도메인 용어(SNR·dark current·Bayer→RGB)는 그대로.

## 규칙

1. **트랜스크립트를 요약·번역·재포맷하지 않는다.** 원문 보존이 의도 추출에 가장 안전하다.
2. **HTML 산출물만 보고 구현하지 않는다.** `project/` 는 *결과물* 이다.
3. 트랜스크립트와 현재 코드가 어긋나면 — 대개 **트랜스크립트가 낡은 것**이다. 제품 의도 자체가
   불명확하면 사용자에게 묻는다.
