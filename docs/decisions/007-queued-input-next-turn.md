# ADR-007 — 응답 중 입력의 다음 턴 대기와 즉시 보내기

## 문제

도구 경계에서 대기 입력을 자동 흡수하면 사용자가 취소할 수 있는 시간이 도구 실행 간격에 종속된다. 사용자는 응답 종료까지 입력을 취소할 수 있고, 필요하면 현재 응답을 끊어 대기를 즉시 전달하는 선택을 요구했다.

## 검토한 선택지

| 선택지 | 판단 |
|---|---|
| 도구 경계 자동 흡수 유지 | 기각 — 응답 종료까지 취소 가능해야 한다는 사용자 결정과 충돌 |
| CLI의 즉시 전송 단계 판정·백그라운드 전환·유예에 위임 | 기각 — 사용자는 항상 현재 응답 interrupt 후 전달을 선택 |
| 응답 종료 후 flush 재사용 + 즉시 보내기는 interrupt 후 같은 flush | 채택 — 전달·병합·커밋 경로를 공유하며 기존 중단과 구분 가능 |

## 결정

응답 중 입력은 held로 보관하고 도구 경계에서 회수하지 않는다. 응답이 끝나면 대기 전부를 입력 순서대로 한 턴에 병합해 전달한다. 대기 버블의 '즉시 보내기'는 진행 중 응답만 interrupt한 뒤 같은 턴 종료 flush를 사용한다.

즉시 보내기는 대기 항목·세션 체인·백그라운드 작업을 유지한다. 기존 '중단'은 대기를 전량 취소해 draft로 복원하며, 항목별 '취소'도 전달 전까지 유지한다. 끊을 응답이 없거나 준비·종료 중이면 즉시 보내기는 무동작이다.

## 포기한 것

Claude Code의 도구 경계 자동 흡수와 단계별 즉시 전송 판정은 사용하지 않는다. 별도 `[Request interrupted by user]` 표식과 개별 대기 버블 전송도 도입하지 않는다. 화면은 기존 중단 표시를 사용하며 대기 전부를 병합하는 기존 연속 턴 형상을 유지한다.

## 불변식

- held 입력은 응답 종료 전까지 자동 전달되지 않는다.
- 즉시 보내기는 응답 interrupt 후 대기 전부를 입력 순서대로 한 턴으로 전달한다.
- 즉시 보내기는 세션 체인을 취소하거나 백그라운드 작업을 중지하지 않는다.
- 전달 예약 전 취소는 가능하며, 예약 후 거부는 renderer에 전달됨을 재동기화한다.
- 중단 후 재개 표식은 새 연속 턴에 상속되지 않는다.
