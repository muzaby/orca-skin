# ADR-009 — 하네스 원본 경로를 유지하고 Orca 설정은 오버라이드한다

상태: **사용자 결정 확정, 구현 전** (2026-10-16). 구현 범위·미정 항목은 [0265](../handoff/0265-harness-native-storage/plan.md), OpenCode 실행 경로는 [0262 ΔV15](../handoff/0262-opencode-harness/plan.md)에서 관리한다.

## 문제

Orca가 OpenCode의 XDG 데이터·설정·상태·캐시 루트를 자체 userData 아래로 바꾸므로 일반 터미널과 서로 다른 native 저장소를 사용한다. 같은 native session ID를 보존해도 터미널은 그 세션을 찾지 못한다. Orca DB를 대화의 유일한 진실로 정한 ADR-001도 이번 사용자 정책과 다르다.

## 결정

Orca 전용 native 저장소를 계속 쓰는 안은 일반 CLI와 경로가 갈라져 기각한다. Orca 설정까지 native 파일에 옮기는 안은 사용자가 유지하도록 한 실행 오버라이드와 달라 채택하지 않는다. **native 원본 경로 + Orca 보관 DB + 실행 오버라이드**를 선택한다.

- 세션과 하네스 소유 리소스의 원본은 해당 하네스가 정한 기본 저장 경로와 작업 디렉터리에 있다. 사용자 환경으로 명시한 native 경로도 하네스 규칙대로 존중한다. Orca가 별도 저장 루트를 자동 주입하지 않는다.
- Orca DB의 대화 저장은 유지한다. GUI 표시·검색·앱 메타데이터와 보관 사본에 사용하며 native 실행 컨텍스트를 대체하지 않는다.
- 엔진&모델 페이지의 설정 등 Orca가 제공하는 값은 실행 시 오버라이드한다. 이를 이유로 native 저장 루트를 바꾸거나 사용자 native 설정 파일을 덮어쓰지 않는다. Orca 설정 저장·리소스 주입 기능을 일괄 제거하는 결정이 아니다.
- Orca의 대화 제거는 Orca 목록에서만 제거한다. 하네스 세션·관련 파일·실제 작업 폴더는 보존한다.
- Claude·OpenCode와 향후 하네스에 같은 소유권 원칙을 적용한다. 실제 native 경로·형식·조회는 각 하네스 모듈이 해석한다.

터미널에서 추가한 대화도 Orca에서 같은 세션을 다시 열 때 transcript에 반영한다(사용자 확인). 기본 경로 공유와 이력 재수입은 다른 구현이며, 경로 수정만으로 양방향 이어보기가 완성됐다고 주장하지 않는다.

## 이전 결정과의 관계

[ADR-001](001-orca-db-session-ssot.md)의 **Orca DB가 native 대화보다 우선한다**는 정책을 대체한다. DB 유지·FTS·append-only migration·Orca 자체 dev/prod 데이터 격리는 유지한다. 이전 문서는 과거 선택의 근거로 보존하며 현재 구현이 새 정책을 이미 만족한다고 해석하지 않는다.

0230의 앱 임시 입력/출력과 권한 범위, Orca 전용 UI 설정·통계·게시 사본은 native 세션 원본과 구별한다. 네이티브 영속 리소스와 임시 실행 오버라이드의 경계는 구현 전 전수 조사하며, 기존 명시 권한 정책을 경로 변경에 섞어 조용히 없애지 않는다.

이 선택으로 Orca DB만 읽어 최신 대화라고 단정하는 단순함을 포기한다. 외부 CLI 변경·native 압축·원본 접근 실패를 다뤄야 하며, 그 비용을 하네스별 조회와 공통 보관/표시 경계에서 관리한다.

## 필요한 검증

같은 실제 작업 디렉터리에서 Orca가 만든 native ID로 CLI 재개가 가능해야 한다. 기본 환경과 사용자 지정 native 환경을 각각 검사하고, 사용자 native 설정 파일 불변과 Orca 모델 오버라이드 적용을 동시에 관측한다. 기존 격리 세션은 원본을 보존하며 이관 범위를 검증하고, Orca 목록 제거 뒤에도 CLI 조회가 성공해야 한다.
