# ADR-008 — 로컬 날짜 경계에서 게이트 통과만 해제

## 문제

로그인 게이트를 통과한 앱을 하루 넘게 켜 두면 새 로그인 이벤트가 없어 서버의 일별 사용
집계에서 빠진다. 사용 집계만을 위해 주기적인 health check·fetch를 추가하면 불필요한 서버
자원을 쓰므로, 기존 로그인 경로에서 날짜마다 로그인 기회를 만들어야 한다.

사용자는 실행 중 00:00이 지나면 로그인 화면을 표시하되, 해제 범위를 게이트 통과로 한정했다.
일일 정책이 저장된 자격증명·플러그인 연결·진행 중 응답을 직접 바꾸지 않고, 앱 시작은 기존
부팅 확인으로 유효한 저장 로그인을 자동 통과시키는 정책을 유지한다.

## 검토한 선택지

| 선택지 | 판단 |
|---|---|
| 사용 집계용 주기적 health check·fetch | 기각 — 로그인 기회 대신 추가 서버 호출에 의존 |
| 날짜 경계에서 Auth를 만료·해제 | 기각 — 자격증명·Plugin·Harness와 진행 중 응답 유지 결정에 충돌 |
| 날짜 경계에서 부팅 probe만 재실행 | 기각 — 사용자의 로그인 동작 없이 통과할 수 있어 재로그인 요구를 충족하지 못함 |
| 날짜 경계에서 게이트 통과만 해제하고 실제 로그인 커밋을 요구 | 채택 — Auth lifecycle을 유지하며 기존 로그인 경로를 사용 |
| 매 앱 실행마다 무조건 수동 로그인 또는 일일 표식 영속 | 기각 — 유효한 저장 로그인을 확인해 자동 통과하는 부팅 정책과 충돌 |

## 결정

업무일 기준은 main 프로세스의 로컬 날짜다. 다음 로컬 자정 타이머와 절전 해제·잠금 해제·창
포커스에서 날짜를 다시 확인하며, 날짜가 앞뒤 어느 쪽으로 바뀌어도 게이트 통과를 해제한다.
진행 중 응답이 있어도 로그인 화면을 즉시 표시한다.

게이트 멤버마다 경계 당시 credential revision과 확인 여부를 메모리 표식으로 둔다. 이미
확인된 멤버는 경계 뒤 실제 로그인 커밋과 `valid ∧ verified`가 모두 있어야 다시 통과한다.
자동 refresh도 credential revision을 올리므로 커밋 원인을 구분해 로그인 증거에서 제외한다.

경계에서 미확인인 멤버는 이후 첫 확인 성공을 그날의 통과로 인정한다. 앱 시작에는 실행 중
표식이 없어 기존 부팅 확인을 그대로 사용한다. 게이트 동안 채팅 이벤트와 nav 주의 표시
구독을 유지해 밤사이 끝난 작업과 응답 요청도 재로그인 후 확인할 수 있게 한다.

해제 범위는 일일 정책의 직접 변경에 한정한다. snapshot 조회에서 관측한 자연 만료는 기존
Auth 상태 전이와 Plugin/Harness 무효화를 유지한다. 일일 정책이 만료 정착을 억제하면 이미
죽은 자격증명을 소비자가 계속 사용할 수 있으므로, 정책의 직접 방송과 자연 만료 방송을 구분한다.

## 포기한 것

서버 시각·고정 시간대·마지막 로그인부터 경과한 시간을 기준으로 삼지 않는다. 23:59에
로그인해도 00:00 이후 다시 로그인해야 하며, 날짜를 되돌리면 같은 날 재로그인을 더 요구할
수 있다. 별도 서버 호출과 영속 표식을 도입하지 않는다.

자정 직전 미전송 Composer 초안 보존은 이 결정 범위에 포함하지 않는다. 메인 셸이
언마운트되므로 초안은 사라질 수 있으며, 초안 저장 또는 셸 수명 변경은 별도 설계 대상이다.

## 불변식

- 일일 날짜 정책은 게이트 통과만 해제하고 Auth 상태·자격증명·연결·진행 중 턴을 직접 변경하지 않는다.
- snapshot 조회에서 관측한 기존 자연 만료 정착과 Auth 방송·Plugin/Harness 무효화는 유지한다.
- 이미 확인된 멤버의 재통과에는 경계 이후 실제 로그인 커밋이 필요하며 자동 refresh는 대신하지 못한다.
- 부팅 확인과 실행 중 일일 재로그인은 같은 Auth 경로를 사용하되 통과 근거를 구분한다.
- 일일 판정은 main이 소유하고 renderer는 전달된 `dailyRelogin`으로 단계와 안내만 표시한다.
- 게이트 미요구·DEV 우회는 일일 재로그인으로 차단되지 않는다.
- 날짜 감지를 위한 서버 요청과 일일 표식 영속은 없다.
