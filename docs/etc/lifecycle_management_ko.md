# LLM 기반 채팅 애플리케이션의 라이프사이클 관리 구조

LLM‑기반 채팅 앱(예: OpenAI Codex 앱, Claude Code, GitHub Copilot CLI, OpenAI Agents SDK 등)의 설계는 **“대화 경험을 어떻게 지속적으로 관리하고 안전하게 도구를 실행할 것인가”**라는 문제를 해결하기 위해 계층화되어 있다. 다양한 프레임워크의 사례를 통해 공통적인 상위→하위 계층을 분석하고 일반적인 라이프사이클을 정리한다.

## 1. 애플리케이션 계층 – 사용자를 위한 인터페이스

* **대화 UI**: 사용자는 CLI, IDE 플러그인(예: Claude Code의 VS Code 확장), 웹 UI 또는 모바일 앱을 통해 LLM 에이전트에 메시지를 보내고 결과를 받는다. 프레임워크는 이 계층을 표준화하면서 사용자 경험을 단순하게 유지하는 것을 목표로 한다【188358856908134†L45-L50】.
* **연결 계층**: GitHub Copilot CLI와 같은 일부 SDK는 **전송 레이어** 역할을 하여 프론트엔드가 보낸 프롬프트를 JSON‑RPC 프로토콜로 변환하고, CLI 서버에서 발생한 이벤트를 애플리케이션에 전달한다【445479827067379†L582-L600】. 이 계층은 도구 호출 결과와 상태 변경 이벤트를 사용자에게 스트리밍한다.

## 2. 리소스/인프라 계층 – 프로세스 감시 및 분산

* **프로세스 감시**: Sagents 프레임워크는 애플리케이션 supervision 트리 아래에 `ProcessRegistry`와 `ProcessSupervisor`를 두고, 각 대화에 대해 `AgentSupervisor` 프로세스를 동적으로 시작한다【630248551550715†L1596-L1643】. 이 구조는 **동적 에이전트 라이프사이클**을 통해 필요한 때에만 에이전트를 시작하고 종료할 수 있도록 한다【630248551550715†L1637-L1654】.
* **리소스 스코핑**: Sagents는 대화와 독립된 **파일시스템 스코프**를 별도의 `FileSystemSupervisor`로 관리하여 사용자·프로젝트·조직 범위에 맞는 파일 시스템을 제공한다【630248551550715†L1642-L1647】. 이는 에이전트가 소스코드를 읽거나 파일을 작성할 때 적절한 저장소를 사용할 수 있게 한다.
* **분산 확장**: Sagents는 Horde Registry를 사용하여 노드 간 프로세스 재배치를 지원하고, 에이전트 상태를 클러스터 전반에 복제한다【630248551550715†L1704-L1724】. OpenAI Agents SDK는 Temporal과 통합하여 **내구성 실행**을 지원하는데, 이는 네트워크 중단이나 프로세스 크래시 후에도 중단한 지점에서 작업을 재개할 수 있게 한다【170687104934235†L88-L100】.
* **Inactivity 및 presence 관리**: 일정 시간 동안 작업을 하지 않으면 에이전트를 자동으로 종료하는 **비활성 타임아웃**과, 대화 뷰어가 없을 때 종료하는 **presence 기반 종료**가 제공된다【630248551550715†L1656-L1680】. 이는 리소스 낭비를 방지한다.

## 3. 세션 관리 – 대화 기록과 상태 유지

* **세션 ID**: 각 대화는 고유한 세션 ID와 매핑된다. GitHub Copilot CLI는 `session.send()` 호출로 세션을 생성하며, `session.idle` 신호를 통해 루프가 끝났음을 알려준다【445479827067379†L643-L652】.
* **대화 히스토리**: Copilot CLI와 Claude Code는 **도구 호출과 결과를 포함한 이전 메시지 내역**을 매 LLM 호출 시 함께 전달한다【445479827067379†L596-L623】. 이렇게 하면 모델이 이전 작업을 기억하고 다음 작업을 결정할 수 있다.
* **저장 백엔드**: OpenAI Agents SDK는 SQLite, Redis, SQLAlchemy, MongoDB 등 다양한 세션 구현을 제공하여 대화 기록과 메모리를 지속적으로 저장할 수 있게 한다. TechAhead 블로그는 엔터프라이즈용 장기 에이전트를 위해 **컨텍스트 관리자, 메모리 라우터, 장기 스토어, 통합 엔진, 접근 제어, 관측성**으로 분리된 계층적 아키텍처를 제안한다【387374410494226†L742-L760】.
* **메모리 상태 관리**: LLM은 본질적으로 무상태(stateless)이므로, 에이전트는 별도의 메모리 인프라를 통해 상태를 유지한다. TechAhead 자료는 **인메모리 캐시(작업 중 세션), 벡터 데이터베이스(대화 검색), 관계형 DB(사용자 프로필), 콜드 스토리지**의 3‑계층 구조가 효과적이라고 설명한다【387374410494226†L769-L784】. 또한 컨텍스트 창이 80% 이상 찼을 때 요약(summarization)을 수행하여 중요한 정보를 장기 메모리에 이동시키는 것이 좋다고 강조한다【188358856908134†L54-L60】.
* **세션 재개**: Claude Agent SDK는 세션 재개를 기본 기능으로 제공하고, OpenAI Agents SDK는 run context 및 지속성을 통해 중단된 세션을 복원한다. Copilot CLI에서도 `session.idle` 상태에서 이후 메시지를 이어 보낼 수 있다.

## 4. 에이전트 코어 – 도구 호출과 계획/반복 루프

* **단일 에이전트 루프**: Claude Code와 Copilot CLI는 **간단한 “도구 호출 → 결과 피드백 → 반복” 루프**를 유지한다. Claude Code의 메인 루프 `nO`는 도구 호출이 있는 한 반복하며, 도구를 호출하지 않는 텍스트 답변을 생성하면 루프가 종료된다【188358856908134†L76-L82】. Copilot CLI에서도 `session.send()` 호출 후 도구 사용 요청이 발생하면 CLI가 도구를 실행하고 결과를 모델에 다시 전달하는 식의 **multi‑turn 루프**가 실행된다【445479827067379†L589-L623】.
* **도구 엔진과 스케줄러**: Claude Code는 **ToolEngine & Scheduler**를 통해 도구 호출을 큐에 넣고 실행 순서를 관리한다【188358856908134†L54-L60】. Copilot CLI는 각 **턴(turn)**이 단일 LLM 호출과 도구 호출 실행으로 구성된다고 명시한다【445479827067379†L603-L621】.
* **하위 에이전트 및 병렬성**: Claude Code는 하나의 메인 루프를 유지하면서 필요할 때만 서브 에이전트를 생성한다. 서브 에이전트는 깊이 제한이 있고 자신의 서브 에이전트를 생성할 수 없다【188358856908134†L87-L90】. Copilot CLI는 읽기 전용 도구(Grep, Glob 등)를 한 턴 안에서 병렬로 실행하지만, 상태를 변경하는 도구(Edit, Bash 등)는 순차적으로 실행한다【992483930287803†L192-L195】.
* **플래닝과 TODO 리스트**: Claude Code는 다단계 작업을 수행할 때 TodoWrite 도구를 호출하여 구조화된 JSON 작업 목록을 생성하고, 진행 상황에 따라 항목 상태를 업데이트한다【188358856908134†L159-L167】. 이는 사용자가 에이전트의 계획을 투명하게 볼 수 있게 한다.

## 5. 도구와 권한 관리

* **도구 인터페이스**: Claude Code의 도구는 JSON 형식으로 호출되며, 결과를 일반 텍스트로 반환한다. 기본 도구로는 파일 읽기(View), 디렉터리 탐색(LS), 정규식 검색(Grep), 코드 수정(Edit/Write), 쉘 실행(Bash) 등이 있고, 각 도구는 샌드박스 환경에서 실행된다【188358856908134†L115-L147】.
* **권한 시스템**: Claude Code와 Claude Agent SDK는 위험한 Bash 명령에 대한 확인을 요구하고, 웹 페치도 특정 URL만 허용한다【188358856908134†L143-L147】. OpenAI Agents SDK는 **가드레일(guardrails)** 프리미티브를 제공하여 도구 호출 전·후에 사용자 정의 검증을 실행할 수 있고, RunHooks/AgentHooks로 라이프사이클 이벤트에 코드를 삽입할 수 있다【561497616358250†L46-L58】【561497616358250†L103-L114】.
* **Hook 시스템**: OpenAI Agents SDK의 RunHooks는 에이전트 시작·종료, 도구 실행 시작·종료, 에이전트 간 handoff 등의 이벤트를 모니터링할 수 있게 해 준다【561497616358250†L104-L116】. AgentHooks는 특정 에이전트에만 적용되는 로컬 후킹을 제공한다【561497616358250†L118-L131】. 이는 관측성, 감사 로그, 사용자 맞춤 동작 구현에 사용된다.

## 6. 상태 및 메모리 관리

* **작업 메모리와 장기 메모리**: TechAhead 자료는 **단기 세션 컨텍스트**(최근 대화 및 도구 결과), **벡터 DB**(의미론적 검색), **관계형 DB**(구조화된 사용자 프로필), **콜드 보관**(규정 준수/감사 로그)로 나뉜 3‑계층 메모리 모델을 권장한다【387374410494226†L769-L784】. Claude Code는 컨텍스트 창이 92% 이상 찰 때 `Compressor wU2` 모듈이 대화 내용을 요약해 Markdown 형식의 장기 메모리에 저장한다【188358856908134†L54-L60】.
* **메모리 라우팅**: TechAhead 보고서는 **메모리 라우터**가 요청을 적절한 저장소로 보내며, **컨텍스트 관리자**가 세션 내 단기 메모리를 관리하고, **통합 엔진**이 단기 메모리를 장기 스토어로 승격하거나 삭제하는 역할을 한다【387374410494226†L742-L760】.
* **요청별 메모리 주입**: 효과적인 메모리 관리는 각 요청에 필요한 기억만 삽입하여 LLM 컨텍스트 창을 절약하고, 요약 시 80% 임계값을 넘으면 요약을 트리거해야 한다【387374410494226†L740-L760】.

## 7. 관측성, 이벤트 및 종료

* **상태 이벤트**: Sagents는 `AgentServer`가 `:status_changed` 메시지를 브로드캐스트하여 **idle, running, interrupted, paused, cancelled, error** 상태 변화를 알려 준다【630248551550715†L1730-L1744】. 이는 UI가 실시간으로 에이전트 상태를 표시할 수 있게 한다.
* **세션 이벤트**: Copilot CLI는 `assistant.turn_start`와 `assistant.turn_end` 이벤트를 통해 각 LLM 호출을 구분하며, `session.idle`과 `session.task_complete` 신호로 완료 여부를 구분한다【445479827067379†L643-L704】. Autopilot 모드에서는 모델이 `task_complete`를 호출하지 않을 경우 CLI가 새 사용자 메시지를 삽입하여 작업 완료를 유도한다【445479827067379†L670-L688】.
* **후킹과 로그**: OpenAI Agents SDK의 RunHooks/AgentHooks를 사용하면 사용자가 에이전트 시작·종료, 도구 실행, handoff 등의 이벤트를 로깅하거나 커스텀 로직을 실행할 수 있다【561497616358250†L104-L116】.
* **종료와 복구**: Sagents는 비활성 타임아웃과 presence 기반 종료를 제공하고, Temporal 통합으로 내구성 있는 실행을 지원한다【170687104934235†L62-L100】. Copilot CLI는 세션 재개를 지원하지만, 기본적으로 루프가 종료되면 `session.idle`만 발행해 완전한 작업 완료를 보장하지 않는다【445479827067379†L643-L704】. Claude Agent SDK는 별도의 오케스트레이션 없이도 세션 재개 기능을 제공하지만, 자동 재시도나 내구성 실행은 외부 프레임워크가 필요하다【992483930287803†L50-L61】.

## 8. 서브 에이전트와 에이전트 협력

* **핸드오프**: OpenAI Agents SDK는 **핸드오프(handoff)** 프리미티브를 통해 한 에이전트가 다른 에이전트로 제어를 넘길 수 있게 한다. Triaging agent가 사용자 요청을 분류한 뒤 해당 작업을 담당하는 다른 에이전트에게 전달하는 사례가 소개된다【170687104934235†L128-L149】.
* **오케스트레이션**: 여러 에이전트를 연결하여 복잡한 업무를 처리할 때, Runner 또는 외부 오케스트레이터(예: Temporal, LangGraph)가 각 에이전트를 순차적 또는 병렬로 호출하고 결과를 전달한다【170687104934235†L175-L183】. Claude Code는 제한된 서브 에이전트 파생을 허용하고, PromptLayer 블로그에서는 결과를 메인 루프에 통합하여 단일 메시지 히스토리를 유지하도록 설계했다【188358856908134†L87-L90】.

| **애플리케이션** | 사용자와 상호작용하는 UI/CLI/IDE 플러그인. 프롬프트를 전송하고 스트리밍 결과를 표시한다. | Claude Code의 인터페이스 층에서 CLI, VS Code, 웹 UI가 사용자 상호작용을 담당한다【188358856908134†L45-L50】. |

## 10. 결론

LLM‑기반 채팅 애플리케이션의 라이프사이클 관리는 단순히 LLM API를 호출하는 것을 넘어선 **포괄적인 시스템 설계**다. 사용자 인터페이스부터 시작하여 프로세스 관리, 세션 저장소, 반복적인 도구 호출 루프, 서브 에이전트 오케스트레이션, 권한과 메모리 관리, 관측성과 회복성에 이르기까지 각 계층을 체계적으로 설계해야 안정적이고 확장 가능한 에이전트형 애플리케이션을 구축할 수 있다. Claude Code, GitHub Copilot CLI, Sagents, OpenAI Agents SDK 등 최신 프레임워크는 이러한 계층을 서로 다른 방식으로 구현하지만, 공통적으로 **단순한 루프와 명시적인 상태 관리**를 중심에 두고 있다. 이는 개발자가 디버깅 가능하고 견고한 시스템을 구축할 수 있게 하며, 앞으로 등장할 더 복잡한 에이전트 시스템의 기반이 된다.
