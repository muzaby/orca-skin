# 8. 종합 평가

## 강점

- **통제권을 코어에 남긴 설계**. AI SDK 를 폴백으로 격하하고 자체 프로토콜 패키지를 기본
  경로로 둔 덕에, 프로바이더 신기능·툴콜 동작·재시도·둠루프 등을 직접 통제한다. 자작 에이전트가
  보통 포기하는 통제력을 확보했다(5.1).
- **실전에서 데인 흔적이 종료/복구 로직에 박혀 있음**. `hasToolCalls` 보정(5.2),
  content-filter/구조화출력 실패의 타입드 표면화, 인터럽트 마감 — 데모 코드에는 없는 디테일들.
- **메모리·권한·복구가 1급 모듈**. 장기 자율이라는 비전의 필요조건을 회피하지 않고 정면으로
  구현(7장).
- **Effect 로 동시성/자원/취소가 구조적으로 일관**. ad-hoc try/catch·수동 정리의 누수 위험을
  타입과 이펙트로 봉쇄.

## 트레이드오프 / 비용

- **높은 진입장벽**. 전 코드가 Effect 제너레이터·Layer DI 위에 있어, Effect 에 익숙지 않으면
  `prompt.ts`(67KB)·`processor.ts`(43KB) 같은 거대 파일을 읽는 비용이 크다. 단순 기여자에게는
  가파른 학습곡선.
- **이중 런타임의 유지비**. 네이티브 11종 프로토콜 + AI SDK 폴백 = 두 경로가 같은 `LLMEvent`
  계약을 영원히 만족시켜야 한다. 계약이 어긋나면 "네이티브에선 되는데 폴백에선 안 됨" 류 버그가
  생길 표면적이 크다.
- **거대 파일/거대 함수**. `runLoop` 한 함수가 250줄(`prompt.ts:1134-1384`)에 서브태스크·압축·
  오버플로·종료·구조화출력을 다 담는다. 응집도는 높지만 한 함수가 너무 많은 책임을 진다.
- **v1/v2 메시지 이중 쓰기 과도기**. 코드 곳곳 `mirrorAssistant` 분기와 `TODO(v2)` 주석
  (`processor.ts:475`,`487`,`594` 등). 마이그레이션 중간 상태라 중복 경로가 존재.

## 설계가 깨질 수 있는 지점

- **종료 조건의 미묘함**. 3장의 종료 판정은 프로바이더의 `finish`·툴콜 동작에 의존한다. 새
  프로바이더가 예외적 `finish` 의미를 주면 루프가 일찍 끝나거나(툴 결과 미반환) 못 끝날(무한)
  위험이 잠재. 보정 로직(`hasToolCalls`, orphan 처리)이 이를 막지만 신규 프로바이더마다
  검증 필요.
- **압축의 토큰 추정 의존**. `Token.estimate(JSON.stringify(...))`(`compaction.ts:195`) 기반
  예산 계산은 추정치다. 실제 토크나이저와 괴리가 크면 오버플로 직전 압축이 빗나갈 수 있다.
- **권한 Deferred 의 영속성**. 승인 대기는 인메모리 `pending` 맵(`permission/index.ts:110`).
  서버 재시작 시 대기 중이던 승인은 휘발된다(턴은 인터럽트 복구로 마감되지만, "그 순간의 ask"는
  사라짐). 비전상 영속화될 법한데 코드상 인메모리다.

## 분석의 정직한 한계

- `packages/llm` 의 라우팅/엔드포인트/트랜스포트 내부(`route/executor.ts`, `route/transport`,
  `route/framing.ts`)는 **공개 표면만 확인**하고 깊게 추적하지 않았다. 네이티브 런타임의
  프로토콜별 세부 동작(스트림 프레이밍, 인증 흐름)은 본 보고서 범위 밖이다.
- 분석은 **세션/에이전트 코어 경로**에 집중했다. TUI(Go), 데스크톱, 콘솔, 엔터프라이즈,
  share/sync, snapshot, LSP 통합 등 주변 패키지는 루프에 직접 닿는 한도에서만 언급했다.
- 토큰/비용 계산, 텔레메트리(span) 세부, 플러그인 시스템 전체 표면은 부분적으로만 봤다.
- 본 보고서의 모든 함수명·라인 참조는 grep/파일 정독으로 실재 확인했으나, 거대 파일 특성상
  인용하지 않은 분기·엣지케이스가 존재할 수 있다.

## 한 줄 결론

opencode 는 "최소 투명 데모"의 정반대인 **프로덕션 멀티모델 자율 코딩 에이전트 플랫폼**이며,
그 모든 복잡도(자체 LLM 프로토콜, 3단 컴팩션, 권한 게이트, Effect 동시성)는 비전이 강제한
필요조건에 대한 일관된 답이다. 통제권을 코어에 남기는 대가로 높은 학습·유지 비용을 지불하는,
의도가 또렷한 설계다.
