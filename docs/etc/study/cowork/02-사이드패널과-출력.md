# cowork — 사이드패널과 출력 패널

대화록이 *무슨 일이 있었는가* 를 시간순으로 담는다면, 사이드패널은 *지금 상태가 무엇인가* 를
담고 출력 패널은 *결과물 자체* 를 담는다. 같은 이벤트가 세 곳에 서로 다른 책임으로 투영된다.

## 1. 사이드패널 — 접히는 3섹션

한 카드 안에 섹션 셋이 구분선으로 나뉘고, 각 섹션 헤더는 `제목 + chevron` 이며
`aria-expanded` 를 갖는다. 본문은 `max-height: 24rem` 안에서 스크롤한다.

### 진행 상황

| 요소 | 값 |
|---|---|
| 항목 | 24px 원형 아이콘(완료=체크) + 제목 한 줄 |
| 완료 표시 | 제자리에서 `line-through` + 흐린 색 — 그룹 이동 없음 |
| 순서 | 관측 순(= Task id 순). 상태 그룹 헤더 없음 |
| 행 hover | `이 항목에 댓글 달기` 버튼이 우측에서 그라디언트와 함께 나타난다 |

이 턴의 4항목은 대화록의 `Added task:` 행 4건과 같은 제목이다 — 목록의 원천이 `TaskCreate` 의
`subject` 이고 상태는 `TaskUpdate` 가 옮긴다.

### 출력

| 요소 | 값 |
|---|---|
| 헤더 | `출력` + 개수(`1`) |
| 항목 | 파일 타입 아이콘 + 파일명 버튼(`downloads_analysis.md`) |
| 동작 | 클릭 시 출력 패널이 그 파일을 연다 |

### 컨텍스트

| 요소 | 값 |
|---|---|
| 형태 | 겹쳐 놓인 칩 스택(`--chip-stack-overlap: 6px`), 겹침만큼 왼쪽 여백을 준다 |
| 그룹 라벨 | `폴더 및 파일 1개` |
| 이 턴의 값 | `Downloads` 칩 하나 — `aria-disabled="true"` (표시 전용) |

원천은 권한 승인이다 — `device_request_folder_access` 가 반환한 경로가 칩이 된다.

## 2. 산출물 카드 (대화록 끝)

결론 Prose 바로 뒤에 붙는 전폭 카드다.

| 요소 | 값 |
|---|---|
| 썸네일 | 68px 폭 문서 페이지 모양 SVG |
| 제목 | `Downloads analysis` — 파일명이 아니라 **문서 제목** |
| 부제 | `문서` · `MD` |
| 트레일링 | `Drive에서 열기` split 버튼 + `더 많은 열기 방법` |
| 접근성 | 카드 전체를 덮는 `aria-label="… 보기"` 버튼 |

## 3. 출력(미리보기) 패널

| 요소 | 값 |
|---|---|
| 좌상단 | `미리보기` / `코드` 세그먼티드 컨트롤(`aria-label="파일 보기 모드"`) |
| 제목 영역 | 문서 제목 + `문서 · MD` |
| 우측 | 복사 · `Drive에서 열기` split · 더 많은 열기 방법 · 펼치기 · 닫기 |
| 본문(코드 모드) | 줄번호 거터 + 본문, 줄마다 `data-diff-type`·`data-diff-line` |
| 코멘트 층 | `data-prose-review-dockey="file:|::/tmp/downloads_analysis.md"` + `data-prose-review-counts` |

줄 단위 `data-diff-*` 는 이 파일이 신규 생성이라 전부 `normal` 이지만, 같은 뷰어가 diff 를
그리는 구조를 갖고 있음을 뜻한다. 코멘트 층은 사이드패널 항목의 `댓글 달기` 와 같은 계열이다.

## 4. 같은 이벤트의 3중 투영

| 이벤트 | 대화록 | 사이드패널 | 그 외 |
|---|---|---|---|
| `TaskCreate` / `TaskUpdate` | 상태 전이마다 행이 남는다 — `Added`·`Started`·`Completed` 12행 | `진행 상황` — **현재 상태만**, 완료는 취소선 | — |
| `Write` / `SendUserFile` | 클릭 가능한 정보 행 (`… 생성됨`·`파일 표시됨`) | `출력` — 개수 배지 + 파일 버튼 | 턴 끝 산출물 카드 + 출력 패널 |
| 폴더 권한 승인 | 도구 행 (`Requesting access…`) | `컨텍스트` — 칩 스택 | — |

핵심은 **책임이 다르다**는 것이다. 대화록은 이력을 버리지 않아 실패한 시도까지 행으로 남기고
(`파일 표시됨` 2회), 사이드패널은 이력을 버리고 현재만 보인다(`출력` 은 1건). 두 표면이 같은
이벤트를 세는 방식이 다르므로, 한쪽 수치로 다른 쪽을 검증할 수 없다.
