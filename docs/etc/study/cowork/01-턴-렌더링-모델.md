# cowork — 한 턴의 렌더링 모델

조사 대상은 `task create 및 update를 사용하여 다운로드 폴더를 분석하고 요약하여 md 파일로
만들어라` 한 턴이다. 도구 행 23 · 타임라인 텍스트 21 · 본문 Prose 2 · 산출물 카드 1.

## 1. 턴의 골격

```text
h2.sr-only  "Claude 응답: {첫 문장}"        ← 문서 개요용 heading, 페이지 내 찾기에서 제외
├ pill  "사고 과정"                          접힘 · 내용 미마운트
├ Prose  서문
├ pill  "작업 업데이트됨, 도구 7개 사용함, 로드된 도구 · 7 노트"
│   └ 타임라인 — 20px 레일 + 1px 커넥터선, 도구·사고·텍스트가 한 덩어리
├ Prose  결론
├ artifact-block  "Downloads analysis / 문서 · MD / Drive에서 열기"
└ 액션바(복사·읽어주기·좋아요·싫어요) + 상대시각
```

- 한 턴이 `transcript-row` **하나**다. 텍스트↔도구로 메시지가 갈려도 렌더 단위는 턴이다.
- 사고 pill 의 `Collapsible` 은 접힌 상태에서 **자식이 DOM 에 없다** — 펼칠 때 마운트한다.
- pill 문자열은 `sr-only role="status" aria-live="polite"` 로 같이 방송된다.

## 2. 타임라인의 행 3종

| 종류 | 모양 | 펼침 | 관측 |
|---|---|---|---|
| 도구 행 | `[글리프] [한 줄 truncate 라벨] [caret]` | `Request` / `Response` / `Error` 3섹션 카드 | 19/23 |
| 정보 행 | caret 없음. 산출물이면 클릭 가능, 아니면 `disabled` | 없음 | 4/23 |
| 노트 행 | 레일 글리프 + 흐린 본문(`text-text-300`) | `max-height:200px` + `더 보기` | 21 |

- 펼침 본문은 `bg-surface-1 rounded-md p-3` 카드에 11px 섹션 라벨 + 구문 강조 JSON(`pre-wrap`).
- 노트 행의 레일 글리프는 21건 **전부 같은 코드포인트**다 — DOM 은 사고와 텍스트를 구분하지 않는다.

## 4. 강등 경계 규칙

**런(작업 타임라인)은 첫 도구 호출에서 열리고, 턴의 마지막 텍스트 블록 직전에서 닫힌다.**

| 위치 | 사고 | 텍스트 |
|---|---|---|
| 런이 열리기 전 | 자기 `사고 과정` pill (#1) | 서문 Prose (#2) |
| 런 안 | 노트 (14건) | 노트 (7건) |
| 런 뒤 | — | 결론 Prose (#48) |

텍스트 블록만 놓고 보면 **첫 것과 마지막 것만 승격, 나머지 텍스트와 모든 사고는 강등**이다.

경쟁 가설 둘은 이 턴이 직접 반증한다.

| 가설 | 반증 |
|---|---|
| "뒤에 도구 호출이 오는 텍스트는 강등" | #2 뒤에 도구 행이 23개 오는데도 Prose 로 남아 있다 |
| "마지막 도구 호출 뒤의 텍스트는 승격" | #47(사고)은 마지막 도구 행 #46 뒤인데도 강등돼 있다 |

두 번째가 규칙의 형태를 정한다. 런의 꼬리는 `[#46 행] → [#47 사고] → [#48 결론]` 인데 밖으로
나온 것은 #48 하나다 — **사고는 어떤 위치에서도 승격되지 않는다.** 그래서 경계를 "마지막 도구
호출" 이 아니라 "마지막 텍스트 블록" 으로 정의해야 한다.

단조 형태로 다시 쓰면: **런은 자기가 열린 뒤의 것만 삼키고, 턴이 끝나면 꼬리의 텍스트 블록
하나만 꺼낸다.** 이 형태가 서문 면제를 규칙에서 자동으로 낳는다.

## 5. 노트 21건의 분류

DOM 으로는 안 갈린다(§2). 문체로 가른다 — 사고는 사용자를 3인칭으로 부르고 도구 이름·실패
원인을 쓰며, 텍스트는 사용자에게 직접 말한다.

| 구분 | 개수 | # | 예 |
|---|---|---:|---|
| 사고 | 14 | 5·11·15·17·22·25·27·30·32·36·38·43·45·47 | "device_bash는 Linux 셸인데, Windows 경로를 사용하려고 했습니다" |
| 텍스트 | **7** | 6·12·18·23·28·33·39 | "작업 계획을 수립했습니다. 이제 다운로드 폴더 접근 권한을 요청하겠습니다." |

**텍스트 7건이 pill 라벨의 `· 7 노트` 와 정확히 일치한다.** 즉 "노트" 는 강등된 텍스트만 세고
사고는 세지 않는다 — 분류가 독립적으로 확인된다.

## 6. 요약 pill 라벨의 계산

`작업 업데이트됨, 도구 7개 사용함, 로드된 도구 · 7 노트` 는 **활동 종류별 절을 콤마로 잇고
노트 수를 `·` 뒤에 붙인** 형태다.

| 절 | 세는 대상 | 값 |
|---|---|---|
| `작업 업데이트됨` | Task 도구 행 (Added/Started/Completed) | 카운트 없음 — 12행 |
| `도구 7개 사용함` | **서로 다른 도구 수**(호출 수 아님) | `device_request_folder_access` · `device_list_dir` · `device_bash` · `Read` · `Bash` · `Write` · `SendUserFile` = 7 |
| `로드된 도구` | 도구 로딩(`Found tools`) | 카운트 없음 — 1행 |
| `· 7 노트` | 강등된 **텍스트** 노트 | 7 (§5) |

`도구 7개` 가 호출 수가 아니라는 것은 산술이 정한다 — 해당 행은 10개이고(재시도 2건 포함)
실패를 빼도 6이다. 서로 다른 도구로 세야 7이 된다.

## 7. 라벨의 원천은 도구 이름이 아니다

| 라벨 | 도구 | 언어 |
|---|---|---|
| `Added task: {subject}` | TaskCreate | 영어 + 인자 |
| `Started task` / `Completed task` | TaskUpdate(status) | 영어 |
| `Requesting access to a folder on your computer` | MCP `device_request_folder_access` | 영어(서버 제공) |
| `Listing files on your computer` | MCP `device_list_dir` | 영어(서버 제공) |
| `Running a command on your computer` | MCP `device_bash` | 영어(서버 제공) |
| `…txt 읽음` | Read | 한국어 |
| `명령 실행됨` | Bash | 한국어 |
| `downloads_analysis.md 생성됨` | Write | 한국어 |
| `파일 표시됨` | SendUserFile | 한국어 |

내장 도구는 한국어, MCP 도구는 서버가 준 영어 문장 그대로다 — **언어 혼재를 감수하고 도구
메타 문장을 우선**한다. `TaskCreate` 는 긴 `description` 이 아니라 짧은 `subject` 를 붙인다.

## 8. 실패는 타임라인 안에 남는다

`InputValidationError`(경로를 JSON 문자열로 감싸지 않음)는 그 행의 `Error` 섹션 안에만 있다.
붉은 배너도 카드 승격도 없다.

- 같은 라벨의 행이 **두 번** 나온다 — #14 실패 → #16 성공, #42 실패 → #44 성공.
- 복구 서사는 그 사이의 강등된 노트(#15·#43)가 담는다.
- 결과적으로 턴 전체는 성공으로 읽히고, 실패는 펼쳐야 보인다.

## 9. 절단 정책

| 대상 | 규칙 |
|---|---|
| 노트 본문 | `max-height:200px` + `더 보기` — 이 턴에서 1건만 넘쳤다 |
| 행 라벨 | 한 줄 `truncate` |
| 펼침 코드 | `white-space: pre-wrap`, 절단 없음 |
| 거대한 도구 출력 | 런타임이 파일로 대체하고 경로를 응답에 싣는다(#21 → #29 가 그 파일을 읽는다) |

## 10. 접근성

| 장치 | 값 |
|---|---|
| 메시지 heading | `<h2 class="sr-only">` — `입력 내용: …` / `Claude 응답: …` |
| 목록 의미 | `aria-setsize` · `aria-posinset` · `aria-label="2개 메시지 중 1번째"` |
| 진행 방송 | pill 문자열을 `role="status" aria-live="polite"` 로 |
| 펼침 상태 | pill·도구 행 모두 `aria-expanded` |
| 스트리밍 표식 | 어시스턴트 컨테이너의 `data-is-streaming` |
