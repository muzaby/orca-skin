# 6. 구현 디테일

[← 5. 특장점](05-특장점.md) · [목차](README.md) · [다음: 7. 큰 그림 →](07-큰그림-비전과-필요조건.md)

---

- **메시지 표현**: 내부 표준은 **OpenAI chat 포맷**(`role`/`content`/`tool_calls`/`tool_call_id`).
  프로바이더 네이티브 포맷으로의 변환은 전적으로 Transport가 담당(base.py:26-32). 이 "OpenAI를
  허브 포맷으로 삼는" 결정이 멀티 프로바이더 지원의 비용을 낮춘다.

- **`ToolEntry` 데이터 구조**(registry.py:77, `__slots__` 사용):
  `name, toolset, schema, handler, check_fn, requires_env, is_async, description, emoji,
  max_result_size_chars, dynamic_schema_overrides`. `dynamic_schema_overrides`는 런타임 설정에
  따라 스키마를 보정하는 zero-arg 콜러블(예: delegate_task가 현재 동시성 한도를 모델에게 정확히
  알리도록) — 정적 스키마의 한계를 우회하는 트릭(registry.py:99-106).

- **레지스트리 패턴**: 각 툴 모듈은 import 시 `tools.registry.register()`를 호출해 자기 스키마/핸들러를
  등록(model_tools.py:6, "Tool Discovery ... importing each module triggers its registry.register calls"
  L177). `ToolRegistry`는 `threading.RLock`과 **단조 증가 `_generation` 카운터**로 MCP 동적 리프레시
  중에도 reader가 안정적 스냅샷을 보게 하고, 외부 캐시가 generation으로 무효화하게 함(L162-167).
  `check_fn`(Docker/Modal/playwright 가용성 같은 외부 상태 프로브)은 **30초 TTL 캐시**로 매
  정의 조회마다 재실행되는 낭비를 막음(L121-141).

- **디스패치**: `registry.dispatch`(registry.py:390)는 `get_entry(name)` → `entry.handler(args)`,
  async 핸들러는 `_run_async`로 브리지, 모든 예외는 `{"error": ...}` JSON으로 캡처. 인자는
  사전에 `coerce_tool_args`로 스키마 선언 타입에 맞춰 강제 변환(`"42"→42`, model_tools.py:917).

  ```python
  # tools/registry.py:390  ToolRegistry.dispatch (요약)
  entry = self.get_entry(name)
  if entry is None:
      return json.dumps({"error": f"Unknown tool: {name}"})
  if entry.is_async:
      from model_tools import _run_async
      return _run_async(entry.handler(args, **kwargs))
  return entry.handler(args, **kwargs)
  ```

- **상태 머신으로서의 루프**: 루프는 다수의 카운터로 *부분 상태*를 추적 —
  `length_continue_retries`(출력 토큰 한계 재개), `truncated_tool_call_retries`,
  `compression_attempts`, `codex_ack_continuations`, `_empty_content_retries`/`_thinking_prefill_retries`
  (빈 응답/사고-only 응답 복구), `_budget_grace_call`(예산 소진 시 1회 유예). `_turn_exit_reason`은
  종료 원인을 문자열로 라벨링하는 진단 채널.

- **컨텍스트 엔진**: `ContextEngine` ABC(context_engine.py:32)는 usage 추적 → `should_compress()`
  → `compress()` 사이클(주석 L16-23). 기본 엔진은 `ContextCompressor`, `threshold_percent=0.75`
  (L64). 보조 모델의 컨텍스트 창이 메인 임계치보다 작으면 세션 임계치를 자동 하향 조정
  (conversation_compression.py:176-190).

- **영속성 스키마**: `SessionDB`(hermes_state.py:657)는 SQLite. FTS5 가상 테이블 `messages_fts`(L602)
  + CJK 부분문자열용 trigram FTS5 `messages_fts_trigram`(L631). FTS5 미가용 시 경고 후 graceful
  degrade(L773-791).
