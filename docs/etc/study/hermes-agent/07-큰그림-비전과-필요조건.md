# 7. 큰 그림: 비전과 그 필요조건의 구현

[← 6. 구현 디테일](06-구현-디테일.md) · [목차](README.md) · [다음: 8. 종합 평가 →](08-종합평가.md)

> 운영체제론이 "OS가 되기 위한 필요조건"을 먼저 규정하고 각 OS가 그것을 어떻게 구현하는지 설명하듯,
> 이 장은 Hermes의 비전을 먼저 규정하고 → 그 비전이 *필연적으로* 요구하는 조건을 도출하고 →
> 각 조건을 어떤 골격으로 구현했는지(1~6장 코드 근거)를 매핑한다.

---

## 7.1 이 프로젝트의 비전 / 철학 / 방향

Hermes의 비전은 README가 명시하고 코드가 뒷받침한다: **"the self-improving AI agent ... the only
agent with a built-in learning loop"**(README L18)이며, 동시에 **모델에 종속되지 않고(any model,
no lock-in)**, **노트북에 묶이지 않은(runs anywhere, not just your laptop)**, **무인으로 오래 사는
(scheduled automations, $5 VPS, hibernate-when-idle)** 개인 에이전트다.

이 비전을 코드가 실제로 무엇에 최적화하는지로 검증하면 일관된다: (a) 학습을 본 대화 밖 데몬으로
격리(background_review), (b) LLM 경계를 Strategy로 추상화(transports), (c) 세션을 SQLite+FTS5로
영속화하고 cross-session 검색을 제공(hermes_state, session_search), (d) 자율·무인 실행을 견디는
방어적 복구·인터럽트·체크포인트·가드레일. 즉 Hermes의 "되기 위한 조건"은 *오래 살고, 스스로
나아지고, 어디서든 어떤 모델로든 도는* 에이전트라는 점에서 도출된다.

## 7.2 비전이 요구하는 필요조건과 그 구현

| 후보 조건 (OS 주제) | 이 비전에 필요한가? | 어떤 골격·구조로 구현했나 (코드 근거) |
|---|---|---|
| 부팅 / 초기화 | **필요** (어디서든 일관 기동) | `hermes_bootstrap.py` / `agent/process_bootstrap.py` / `agent/agent_init.py::init_agent`(L154)이 모델·프로바이더·툴셋·예산(max_iterations=90)·시스템프롬프트를 세팅. 턴마다 `build_turn_context`가 "프롤로그"로 stdio 가드·프롬프트 복원·압축 프리체크 수행(conversation_loop.py:508). |
| 프로세스 & 수명주기 | **필요** (턴=작업 단위, 서브에이전트=자식) | 턴의 수명은 `run_conversation` 루프 → `finalize_turn`. 자식 프로세스 격리는 `delegate_task`가 서브에이전트를 스폰하고 `_register_subagent`/`interrupt_subagent`로 추적·중단(delegate_tool.py:177/190). |
| 스케줄링 | **필요** (다음 행동 결정 + 무인 자동화) | 턴 내: 모델이 tool_call로 다음 행동을 정하고 루프가 디스패치(스케줄러는 곧 모델 자신). 턴 간: `cron/` 빌트인 스케줄러가 자연어 작업을 무인 실행. 예산 스케줄은 `IterationBudget.consume/remaining`(iteration_budget.py:37/57)로 강제. |
| 메모리 관리 | **필요·1급** (유한 컨텍스트로 오래 살기) | `ContextEngine`/`ContextCompressor`(threshold 0.75)로 임계치 초과 시 보조 모델 요약 압축(context_engine.py, conversation_compression.py). 큐레이트 메모리는 `MemoryManager`+`curator`(stale/archive/prune 자동 전이, curator.py:276). cross-session 회상은 FTS5 검색. |
| I/O & 시스템콜 | **필요** (외부 세계 경계) | "시스템콜"에 해당하는 것이 **툴 레지스트리**: `registry.dispatch`가 유일한 능력 호출 경계이고 모든 부작용(파일/터미널/브라우저/네트워크)이 이를 통과(registry.py:390). 상위(메시징 플랫폼)는 `gateway/`. |
| 동시성 & 동기화 | **필요** (속도 + 병렬 워크스트림 + 무오염 학습) | 독립 배치만 병렬 실행(`_should_parallelize_tool_batch`, run_agent.py:5137). 레지스트리는 `RLock`+generation 스냅샷으로 동시 변이 안전(registry.py:161). 학습 리뷰는 별도 **데몬 스레드**로 본 캐시와 분리(background_review.py). |
| 보호 & 권한 | **필요** (자율 툴 사용의 blast radius 제한) | 명령 승인/allowlist + 보조 LLM 자동승인(`tools/approval.py:7-8`), 경로 보안(`path_security.py`), 툴 가드레일 정지(conversation_loop.py:3968), 파일 안전(`file_safety.py`), 서브에이전트 auto-deny(delegate_tool.py:73). |
| 파일시스템 & 영속성 | **필요·1급** (idle 시 hibernate, 세션 넘어 누적) | `SessionDB`(SQLite + FTS5/trigram, hermes_state.py:657). 작업 디렉터리는 `checkpoint_manager`의 git 섀도 스냅샷으로 버전·롤백. 메모리는 MEMORY.md/USER.md 파일. 트라젝토리 JSONL 저장. |
| 에러 처리 & 복구 | **필요·1급** (무인·약한 모델 내성) | 매 호출 전 메시지 시퀀스/인자 수리(conversation_loop.py:681/703), 깨진 JSON은 tool 에러 주입으로 복구(L3856), 빈/사고-only 응답 nudge·prefill 재시도, 스트림 부분복구(L4086), 프로바이더 fallback 체인, 외부 루프 예외 캡처(L4401). |

> 위 표에서 "해당 없음"으로 둘 항목은 없었다 — 이 비전(오래 살고·자율·자가개선)은 OS 주제 거의
> 전부를 *필연적으로* 요구하기 때문이다. 이것 자체가 Hermes가 왜 이렇게 무거운지를 설명한다.

## 7.3 종합: 왜 이렇게 만들어졌는가

Hermes의 구조는 "자가개선·무인·모델무관·어디서나"라는 비전이 부과하는 필요조건들에 대한
*의도적 답변의 집합*으로 읽힌다. **자가개선**은 본 대화를 오염시키지 않는 격리된 학습 프로세스
(background_review의 포크-데몬)와 영속 스토어(메모리/스킬/SessionDB)를 *필연적으로* 요구했고,
그래서 turn_finalizer가 응답 전달 후에 리뷰를 스폰하는 비대칭 구조가 나왔다. **모델무관**은 LLM
경계를 단일 호출이 아닌 Strategy 전송체 계층으로 *필연적으로* 밀어냈다(transports/base.py).
**무인·오래살기**는 메모리 압축, git 체크포인트, 방어적 시퀀스 복구, 인터럽트/steer, 가드레일을
1급 시민으로 만들었다 — 이들은 부가기능이 아니라 비전의 생존조건이다.

반대로, Hermes가 *의식적으로 단순하지 않기로* 한 것도 드러난다. "minimal transparent agent"였다면
루프 한 함수와 얇은 툴 디스패치로 충분했겠지만, Hermes의 루프(`run_conversation`, 4480줄)는
종료 사유 라벨링·부분상태 카운터·프로바이더별 검증 분기로 두껍다. 이는 *투명성보다 신뢰성과
적응성*을 택한 결과다. 즉 단일 문장으로 요약하면: **"학습을 본 대화에서 떼어내고, 모델을 경계
뒤로 추상화하고, 모든 외부 작용을 되돌릴 수 있게 한다"** — 이 세 결정이 나머지 구조 대부분을
연역한다.
