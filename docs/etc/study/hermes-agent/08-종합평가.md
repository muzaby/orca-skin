## 강점
- 자가개선 루프의 *격리 설계*(본 캐시 불변)는 학습 에이전트 중에서도 드물게 깔끔하다.
- LLM 경계의 Strategy 추상화가 "200+ 모델, no lock-in" 비전을 코드로 실증한다.
- 무인 실행에 필요한 신뢰성 메커니즘(복구·체크포인트·가드레일·인터럽트)이 빠짐없이 갖춰져 있다.

## 트레이드오프 / 깨질 수 있는 지점
- **거대 단일 파일**: `cli.py`(639KB), `run_agent.py`(243KB), `conversation_loop.py`(4480줄),
  `hermes_state.py`(206KB)는 forwarder 패턴으로 일부 분해됐으나 여전히 인지 부하가 크다. 루프의
  부분상태 카운터가 많아 한 분기의 회귀가 다른 분기를 깨기 쉽다(코드 곳곳의 `#issue` 주석이 방증).
- **학습 루프의 비결정성**: 백그라운드 리뷰가 스킬/메모리를 자율 갱신하므로, 시간이 지나며 스킬
  라이브러리 품질이 모델 판단에 좌우된다. curator의 stale/archive/prune 자동 전이가 안전망이지만,
  잘못된 학습이 영속화될 리스크는 구조적으로 존재.
- **약한 모델 의존 복잡도**: 빈 응답/깨진 JSON/사고-only 응답에 대한 다층 재시도·nudge는 강력하지만,
  이 휴리스틱들이 서로 간섭할 여지가 있다(예: prefill 카운터 리셋 로직, conversation_loop.py:3943-3945).

## 분석의 정직한 공백
- `cli.py`의 REPL 세부(슬래시 커맨드, 자동완성)와 `gateway/`의 플랫폼별 어댑터는 루프 본질과
  무관해 깊이 추적하지 않았다 — 진입 경로만 확인.
- Honcho 기반 dialectic 사용자 모델링(`memory_provider`)은 외부 시스템 연동이라 내부 동작은
  이 분석에서 코드로 끝까지 확인하지 못함.
- `codex_app_server`/ACP 등 선택적 런타임 경로(conversation_loop.py:554)는 기본 경로가 아니므로
  분기 존재만 확인하고 내부는 생략했다.
