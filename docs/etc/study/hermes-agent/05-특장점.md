# 5. 특장점 (코드 근거 포함)

[← 4. 핵심 모듈](04-핵심-모듈.md) · [목차](README.md) · [다음: 6. 구현 디테일 →](06-구현-디테일.md)

---

1. **턴-종료 자가개선 루프(가장 차별적)** — `turn_finalizer.finalize_turn`은 응답을 사용자에게
   전달한 *뒤* `_should_review_memory`/`_should_review_skills`이면 `_spawn_background_review`를
   호출(turn_finalizer.py:393-401). `background_review.py`는 **에이전트를 포크한 데몬 스레드**가
   "이 대화에서 저장/갱신할 스킬·메모리가 있는가?"를 평가하고 스토어에 직접 쓴다. 핵심 설계:
   *"Main conversation and prompt cache are never [touched]"*(background_review.py:6-7) — 학습이
   본 대화의 토큰/캐시를 오염시키지 않는다. 리뷰 에이전트는 메모리/스킬 툴만 허용(L13). 스킬 nudge는
   `_skill_nudge_interval`(기본 10, agent_init.py:1210) 만큼 툴 반복이 쌓이면 발화.
   *왜 중요한가*: 대부분의 from-scratch 에이전트는 학습 루프가 없거나, 있어도 본 대화에 끼워 넣어
   캐시를 깬다. Hermes는 학습을 **부수 프로세스로 격리**해 비용 없이 누적한다.

2. **프로바이더 어댑터 Strategy 계층** — LLM 경계가 단일 호출이 아니라 `ProviderTransport` ABC
   (transports/base.py:16): `convert_messages/convert_tools/build_kwargs/normalize_response/
   validate_response/map_finish_reason`. api_mode별 구현(`anthropic`, `bedrock`, `chat_completions`,
   `codex`)을 `_get_transport`가 캐시(run_agent.py:4465). 베이스 주석이 책임 경계를 명시:
   *"It does NOT own: client construction, streaming, credential refresh, prompt caching..."*
   (base.py:5-7). *왜 중요한가*: "Use any model you want"라는 비전(README L20)을 코드 변경 없이
   실현하는 구조적 토대 — 응답 정규화/포맷 변환만 전송체에 위임하고, 재시도·캐시·인터럽트는 공통화.

3. **인터럽트 + /steer (실행 중 방향 전환)** — 루프 매 반복마다 `agent._interrupt_requested`를
   확인(conversation_loop.py:568)하고, API 호출 중 도착한 `/steer`를 다음 반복 *시작 시*
   마지막 tool 메시지에 주입(L624-673 "Pre-API-call /steer drain"). *왜 중요한가*: 장시간
   자율 실행 중에도 사용자가 모델을 멈추거나 재조준할 수 있어, 무인 실행의 통제권을 유지.

4. **방어적 메시지 시퀀스 자가복구** — 매 API 호출 전 `_sanitize_tool_call_arguments`(L681)와
   `repair_message_sequence_with_cursor`(L703)로 손상된 tool_call 인자/역할 교대 위반을 수리.
   잘못된 JSON tool_call은 *툴 에러 결과를 주입*해 역할 교대를 보존하며 모델이 복구하게 함
   (L3856-3883). *왜 중요한가*: 200+ 모델(약한 모델 포함)을 지원하므로, 모델별 깨진 출력에
   대한 내성이 곧 신뢰성이다.

5. **선택적 병렬 툴 실행** — `_execute_tool_calls`는 `_should_parallelize_tool_batch`로 배치가
   독립적일 때만 동시 실행(run_agent.py:5137). 읽기 전용 툴은 항상 병렬, 파일 읽기/쓰기는 경로가
   겹치지 않을 때만(docstring L5128-5130). *왜 중요한가*: 안전(쓰기 충돌 방지)과 속도를 동시에.

6. **턴당 git 체크포인트** — `checkpoint_manager`가 파일 변경 전 섀도 git 스냅샷을 턴당 1회 생성하고
   임의 시점 롤백을 제공(checkpoint_manager.py:5-7). 루프는 매 반복 `agent._checkpoint_mgr.new_turn()`
   로 디덥(conversation_loop.py:565). *왜 중요한가*: 자율 파일 수정의 blast radius를 되돌릴 수 있게 함.
