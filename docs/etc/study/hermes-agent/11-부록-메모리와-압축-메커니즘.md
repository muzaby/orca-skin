## A. 메모리 — 차별점은 파일이 아니라 *파이프라인*

`MEMORY.md`/`USER.md`라는 **포맷 자체는 차별점이 아니다**(Claude Code 등도 동일). Hermes의 차별점은
그 파일을 *누가·언제·어떻게* 채우고 정리하느냐다.

| 구분 | 일반적 메모리 | Hermes |
|---|---|---|
| 누가 쓰나 | 사람 수동작성 / 모델이 본 대화 *안*에서 write | 턴 종료 후 **포크된 데몬이 자동 평가·기록**(`background_review.py`) |
| 언제 | 대화 도중 (응답 토큰·캐시 소모) | 응답을 보낸 *뒤*, 본 대화 캐시 불침범 |
| 수명관리 | 보통 무한 누적(사람이 삭제) | `curator.py`가 stale→archive→prune 자동 전이 |
| 회상 | 매 세션 통째 주입 | `SessionDB` FTS5로 필요시 검색 |

> 핵심: "MEMORY.md가 있다"가 아니라 **사람·본대화 개입 없이, 비용 없이, 스스로 쓰고·정리하고·되찾는
> 루프**가 차별점. 파일은 출력물일 뿐이고 본질은 *자동화된 학습 파이프라인*이다.

## B. 압축 — messages[]를 "교체"한다 (보여주기만 하는 게 아니다)

흔한 오해: *"압축하면 이전 대화를 append만 안 하고 이력에는 남겨두는 것 아닌가?"*
→ **실제로는 더 공격적이다. 모델로 가는 `messages[]` 자체를 물리적으로 재조립해 교체한다.**

caller가 결과를 받아 in-memory 리스트를 **reassign**한다 (`conversation_loop.py:2740` 등):

```python
messages, active_system_prompt = agent._compress_context(...)
```

`compress()`(`context_compressor.py:2151~`)가 만드는 새 리스트 구조:

```
compressed = [ 보호된 head ] + [ summary 메시지 1개 ] + [ 보호된 tail ]
                  │                    │                      │
   system+첫 교환   중간 N턴을 LLM으로  최근 ~20K 토큰은 원문 그대로
   (head 보호)      1개로 요약·대체     (token budget로 tail 경계)
```

- **중간 턴은 `messages[]`에서 삭제**된다 — 다음 API 호출에 들어가지 않고 summary 1개로 대체.
- **head**(system+첫 교환)와 **tail**(최근 ~20K 토큰)은 원문 유지.
- summary 메시지엔 `COMPRESSED_SUMMARY_METADATA_KEY=True`. 역할 교대가 깨지지 않게 role을
  자동 선택하거나 tail 첫 메시지에 prepend 병합(`_merge_summary_into_tail`).

### "이력에만 보여준다"는 부분은? — 컨텍스트와 영속 이력의 분리

원본 전체는 `SessionDB`(SQLite+FTS5)에 그대로 영속된다. 따라서:

| 용도 | 무엇을 보나 |
|---|---|
| 모델에 보내는 컨텍스트 | 압축된 `messages[]` (head + summary + tail) — 중간 원문 없음 |
| 사용자 대화 이력 / 표시 | `SessionDB`의 원본 전체 |
| cross-session 검색·회상 | `SessionDB` FTS5로 원본 검색 (압축과 무관) |

> 정리: 압축은 **모델이 보는 뷰만 줄이는 게 아니라, 모델로 가는 `messages[]`를 head+summary+tail로
> 실제 교체**한다. 잘려나간 중간 원문은 사라지지 않고 `SessionDB`에 남아 표시·검색에 쓰인다.
> = **휘발성 컨텍스트(압축됨)** 와 **영속 이력(원본, SQLite)** 의 분리.

### 부가 디테일
- Phase 1: 오래된 tool 결과를 LLM 없이 먼저 prune(`_prune_old_tool_results`).
- 재압축 시 이전 summary를 반복 갱신(iterative update, `_find_latest_context_summary`).
- 압축 후 orphan된 tool_call/tool_result 쌍 정리(`_sanitize_tool_pairs`).
- 과거 이미지 페이로드를 placeholder로 치환(`_strip_historical_media`)해 body 크기 폭증 방지.
- anti-thrashing: 압축이 무효(`compress_start >= compress_end`)면 카운트해 no-op 루프 방지.
