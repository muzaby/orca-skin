# 8. 컨텍스트 한도 · 파일/이미지 정책 — 모델 종류별 (CLI 2.1.267)

> 분석 대상: **`@anthropic-ai/claude-agent-sdk@0.3.267`** 이 동봉한 Claude Code CLI **`2.1.267`** (Orca 고정 버전).
> 1~7장(0.3.220 기준)과 버전이 다르다. 이 장의 수치·식별자는 **2.1.267 에서만** 확인한 값이다.
> 근거: CLI linux-x64 바이너리 문자열 정독(3급 — 식별자는 미니파이 이름이라 버전마다 바뀐다) ·
> 공식 문서 Vision / Coordinates / PDF / Context windows(1급) · LiteLLM 소스 1.65 / 1.72 / 1.76 / 1.80 / 1.103.1.
> Orca 적용 설계는 [`handoff/0245`](../../../handoff/0245-context-policy-cli-parity/plan.md) 가 갖는다 — 이 장은 **증거**다.

## 8.1 30초 요약

- **CLI의 파일·이미지 상한은 대부분 모델과 무관한 고정값이다.** 모델에 따라 달라지는 것은 **컨텍스트 창 · 요약 시점 · 요청당 미디어 수** 셋뿐이다.
- **창 크기는 모델명만으로 정해지지 않는다.** 1M은 `[1m]` 접미사 · 1M beta 헤더 · "1st-party 직결 + 네이티브 1M 모델" · 3P의 `native_1m_3p` 중 하나일 때만이다.
- **`ANTHROPIC_BASE_URL` 이 `api.anthropic.com` 이 아니면 네이티브 1M을 인정하지 않는다**(`go()`). 게이트웨이 뒤의 Opus 4.7+·Fable도 `[1m]` 없이는 200k다.
- **카탈로그에 없는 모델명은 "미확인 모델"이다** — 창 200k, 약 167k에서 선제 요약. 게이트웨이가 모델명을 바꾸면 Claude도 여기에 든다.
- **초과 복구는 오류 문구에 걸려 있다** — `prompt is too long` / `input is too long for requested model` 이 아니면 자동 요약·재시도가 시작되지 않는다.
- **LiteLLM은 `claude` 이름 Bedrock·Anthropic·Vertex 모델을 원형 그대로 넘긴다** — 도구 결과 이미지와 초과 오류 원문이 보존된다. 커스텀 백엔드는 OpenAI 형식 변환을 거쳐 둘 다 깨진다.

## 8.2 컨텍스트 창 결정 — `rp` → `Ez`

`rp(model)` 은 `DISABLE_COMPACT`+`CLAUDE_CODE_MAX_CONTEXT_TOKENS` 강제값을 먼저 보고, 없으면 `Ez` 를 부른다. `Ez` 는 위에서부터 첫 일치로 정한다.

| 순서 | 조건 | 창 | 식별자 |
|---:|---|---|---|
| 1 | 모델 문자열에 `[1m]` (대소문자 무시) — `CLAUDE_CODE_DISABLE_1M_CONTEXT` 이면 무시 | 1,000,000 | `dc` → `yf` = `/\[1m\]/i` |
| 2 | 설정 betas 에 `context-1m-2025-08-07` 이 있고 모델이 1M beta 지원 | 1,000,000 | `gnt(n)?.includes(lM.header) && HT(e)` |
| 3 | 모델 지식(`tl`)이 창을 선언 — 200k 초과인데 1M 미인정이면 200k로 "믿음" | 선언값 또는 200,000 | `HHn` · `Zie` |
| 4 | 네이티브 1M 인정(`jg`) | 1,000,000 | 아래 표 |
| 5 | 미확인 모델(`_z`)이고 `CLAUDE_CODE_MAX_CONTEXT_TOKENS` 설정 | 그 값 | `_z` = 카탈로그에 없고 이름이 `claude-` 정식명이 아님 |
| 6 | 그 밖 | 200,000 | `mye` |

**네이티브 1M 인정(`jg`)** — 카탈로그 `native_1m:true` 모델이어야 하고, 제공자별로 추가 조건이 붙는다.

| 제공자 판정 `Ie()` | 조건 | 결과 |
|---|---|---|
| `firstParty` | `go()` = `ANTHROPIC_BASE_URL` 미설정 **또는 host 가 `api.anthropic.com`** (내부 `_CLAUDE_CODE_ASSUME_FIRST_PARTY_BASE_URL` 예외) | 인정 |
| `firstParty` + 게이트웨이 URL(LiteLLM 등) | `go()` 거짓 | **불인정 → 200k** |
| `bedrock` / `vertex` / `foundry` | 카탈로그 `native_1m_3p[제공자]` | 2.1.267 카탈로그에선 Sonnet 5만 셋 다 참 |
| `anthropicAws` · `anthropicGoogleCloud` · `mantle` | 무조건 | 인정 |

`Ie()` 는 `CLAUDE_CODE_USE_BEDROCK` 등 환경변수로 정해지고, 없으면 `firstParty` 다. `gateway` 값은 Anthropic 관리형 게이트웨이 자격 슬롯에서만 나오며 LiteLLM과 무관하다.

### 카탈로그 (2.1.267) — 창·1M 속성

| 모델 | 창 | 1M 속성 |
|---|---|---|
| Haiku 4.5 | 200k | `[1m]` 접미사 지원 |
| Sonnet 4 · 4.5 · 4.6 | 200k | 1M beta · 접미사 지원 |
| Opus 4 · 4.1 · 4.5 · 4.6 | 200k | 접미사 지원(4.6은 beta도) |
| **Opus 4.7 · 4.8 · 5** | **1M** | `native_1m` · beta · 접미사 |
| **Sonnet 5** | **1M** | `native_1m` · `native_1m_3p` 전부 |
| **Fable 5 · 5.1 · Mythos 5 · 5.1** | **1M** | `native_1m` · beta |

`[1m]` 은 창만 바꾸지 않는다. 모델 beta 목록(`pse`)에 `context-1m-2025-08-07` 을 넣고, 요청 모델 ID에서는 접미사를 뗀다(`pR` → `er` = `/\[(1|2)m\]/gi` 제거). **게이트웨이가 바꾼 이름에 `[1m]` 을 붙여도 게이트웨이에는 원래 이름이 간다.**

## 8.3 자동 요약 창 — `AS`

요약 창 = `min(모델 창, 출처별 값)`. 출처는 위에서부터 첫 일치다.

| 출처 | 조건 | 선제 요약 |
|---|---|---|
| `env` | `CLAUDE_CODE_AUTO_COMPACT_WINDOW` | 켜짐 |
| `settings` | 설정 `autoCompactWindow` | 켜짐 |
| `clientdata` · `experiment` | 1st-party 서버값 · 실험 | 켜짐 |
| `model-default` | 창<1M 이고 `{sonnet-4-6, opus-4-6, opus-4-8, opus-5}` 등(`ZBo`) → 200k / Sonnet 5 기본표 / 창≥1M 이고 네이티브 1M 인정 | 켜짐 |
| `unknown-model` | 자동요약 켜짐 · 미확인 모델 · `[1m]`/1M beta 아님 | 켜짐 |
| `auto` | 위 모두 아님 (예: 인정된 Haiku 4.5 · `[1m]` 모델) | **꺼짐 — 초과 후 복구만** |

- 유효 창 = 요약 창 − min(최대 출력, 20,000). 선제 요약 시점 = 유효 창 − 13,000 → **200k: 167,000 · 1M: 967,000**.
- `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` 는 시점만 바꾸고 출처를 바꾸지 않는다 — `auto` 출처면 PCT만으로는 선제 요약이 켜지지 않는다.
- 판단 입력 = 직전 응답 실측 사용량 + 이후 메시지 추정치(텍스트 글자÷4, JSON ÷2, **이미지·문서 블록은 크기 무관 2,000**).

## 8.4 요청 단위 — 미디어 수

- 요청 전체의 이미지·문서 블록이 한도를 넘으면 **오래된 것부터** `[media removed: request limit]` 텍스트로 바꾼다(`cxs`).
- 한도는 `dc || jg || betas에 1M beta || …` 이면 **600**, 아니면 **100**. 게이트웨이에서는 `[1m]` 이 있어야 600이다.

## 8.5 이미지

| 단계 | 정책 | 근거 |
|---|---|---|
| CLI 축소 | 카탈로그 `image_limits` = **모든 모델 2000×2000**. 넘으면 비율 유지 축소 | `nl` · `pA` |
| CLI 용량 | 축소 후 **512,000바이트** 예산 초과면 재압축(PNG 팔레트 → JPEG 80→20 …). Read·붙여넣기·SDK 입력 공통 | `aGe` · `MAn` |
| 처리 불가 | `[Image could not be processed: …]` 텍스트로 대체 | `SCe` |
| 축소 메모 | `[Image: original WxH, displayed at wxh. Multiply coordinates by r to map to original image.]` | `CBe` |
| API 등급 — 표준 (4.6 이하) | 긴 변 1568px · 시각 토큰 1568. 넘으면 서버가 축소 | Vision 문서 |
| API 등급 — 고해상도 (4.7 이상) | 긴 변 2576px · 시각 토큰 4784 | Vision 문서 |
| API 토큰 | `⌈w/28⌉ × ⌈h/28⌉`. 축소 크기는 공식 `resizedSize` 참조 구현(이분 탐색, short edge half-to-even) | Coordinates 문서 |

예: 2000×1500 → 표준 등급 1270×952(1,564토큰 — 짧은 변 952.5 가 half-to-even 으로 952) · 고해상도 등급 축소 없음(3,888토큰). CLI 추정은 둘 다 2,000이다.

## 8.6 텍스트·PDF·도구 출력

| 대상 | 상한 | 넘으면 |
|---|---|---|
| Read 텍스트 전체 읽기 | 256KB | 오류 — offset/limit 로 나눠 읽어라 |
| Read 토큰 | 25,000 (`CLAUDE_CODE_FILE_READ_MAX_OUTPUT_TOKENS` 로 변경) | 처음부터 전체 읽기면 앞부분만 + 이어읽기 안내, 범위 읽기면 오류 |
| Read PDF | 10쪽 초과는 `pages` 필수 · 한 번 20쪽 · 전체 20MB | 오류/안내 |
| Bash · TaskOutput · MCP | 30,000자 · 32,000자 · 25,000토큰 | 파일 저장 + 미리보기 |
| 기타 도구 결과 | 50,000자 (한 턴 병렬 합계 200,000자) | `<persisted-output>` 경로 + 2KB 미리보기 |
| `@` 멘션 텍스트 | 256KB · 25,000토큰 | 256KB 초과는 첨부 안 함 / 25,000토큰 초과는 앞 2,000줄 + "Read 로 더 읽어라" 메모. SDK 입력에서는 사용자 메시지의 마지막 블록이 텍스트일 때만 `@` 를 확장한다 |

Orca의 텍스트 첨부는 원본을 저장하고 `@"<저장 경로>"`를 마지막 텍스트 블록에 전달해 이 CLI 멘션 경로를 사용한다. Orca에서 내용을 잘라 넣지 않으며 이미지 블록은 텍스트보다 앞에 둔다. 현재 구현 계약은 [adapters — 컨텍스트 모델과 파일 입력](../../../arch/backend/adapters.md#컨텍스트-모델과-파일-입력)을 참조한다.

## 8.7 초과 후 복구

1. **감지** — HTTP 400 이고 메시지에 `prompt is too long` · `input is too long for requested model`(`FDe`) · ``input length and `max_tokens` exceed context limit``(`Aut`). 413 은 `context window`(`$De`).
2. **자동 요약 후 재시도** — 이미지·문서를 `[image]`/`[document]` 로 바꿔 요약하고 같은 턴을 다시 요청한다.
3. **요약 요청도 넘치면** — `prompt is too long: N tokens > M` 에서 초과분을 읽어 그만큼, 못 읽으면 오래된 메시지 20%를 잘라 재시도(`[… truncated for compaction retry]`).
4. **최종 실패** — `Conversation too long. Press esc twice to go up a few messages and try again.` (되돌리기 안내).
5. **반복 방지** — 요약 뒤 3턴 안에 다시 차는 일이 3번 연속이면 `Autocompact is thrashing …` 로 멈춘다.
6. **자동요약 꺼짐** — 차단 한도(창 − 23,000 부근)에서 `Context limit reached · /compact or /clear to continue`.

API 오류가 결과로 끝나면 SDK `result` 는 `subtype:"success"` · `is_error:true` · `result` = 오류 문장 · `api_error_status` 이고, 같은 문장이 assistant 메시지(`error` 필드 동반)로도 온다. 일반 400 은 `API Error: <status> <본문 message>` 형식이다.

## 8.8 게이트웨이(LiteLLM) 뒤에서 달라지는 것

| 항목 | Claude 모델 (Bedrock·Anthropic·Vertex 경유) | 커스텀 모델 (OpenAI 호환 백엔드) |
|---|---|---|
| `/v1/messages` 처리 | 이름에 `claude` 가 있으면 Anthropic 형식 원형 전달(1.76·1.80·1.103.1 확인). `bedrock/converse/…` 명시 경로만 예외 | completion 변환 — 구버전은 `tool_result` 속 이미지를 **base64 텍스트**로 바꾼다(1.76·1.80), 1.103.1은 `image_url` |
| 초과 오류 | `AnthropicError - …prompt is too long…` / `BedrockException: Context Window Error - …Input is too long…` — **CLI가 알아본다** | `litellm.ContextWindowExceededError: …maximum context length…` — **CLI가 모른다** |
| CLI 모델 인식 | 이름이 바뀌면 미확인 모델(200k) · 정식명이어도 네이티브 1M 불인정 | 미확인 모델(200k) |

텍스트로 바뀐 이미지는 GPT 계열 토크나이저 실측 약 1.4자당 1토큰이다 — 512KB 이미지 한 장이 약 47만~49만 토큰이 되고, CLI 는 이를 2,000으로 추정한다.

- 관측(폐쇄망, 사용자 보고): OpenRouter 경유 내부 모델에서 PNG 2장(427KB·327KB)을 Read 하자 입력 700,342토큰으로 400. base64 약 100만 자를 약 1.4~1.5자/토큰으로 센 값과 맞는다. LiteLLM 1.76·1.80·1.103.1 모두 OpenRouter 를 `/v1/messages` 원형 전달하지 않고 completion 변환으로 보낸다 — 이름이 Claude 여도 같다.
- 같은 환경의 Claude Haiku 200k 에서는 큰 이미지도 컨텍스트 증가가 작다(사용자 관측). Orca 는 이 문제를 서버 쪽 문제로 두고 CLI 정책만 따른다([handoff 0245 ΔV1](../../../handoff/0245-context-policy-cli-parity/plan.md)).
