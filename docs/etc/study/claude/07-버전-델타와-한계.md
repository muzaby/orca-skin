# 7. 버전 델타와 한계

> 이 장은 두 가지를 한다. ① 이번 bump 구간 **0.3.215 → 0.3.220** 에서 tool/subagent/턴 영역이 움직였는지 **실측 비교**. ② 본 분석이 무엇을 확인했고 무엇을 못 했는지, 그리고 못 한 것을 **재현으로 좁히는 방법**.

## 7.1 실측 방법

두 버전의 타입 선언을 나란히 놓고 diff 했다.

```bash
npm pack @anthropic-ai/claude-agent-sdk@0.3.215
tar xzf anthropic-ai-claude-agent-sdk-0.3.215.tgz
diff package/sdk-tools.d.ts  <0.3.220>/sdk-tools.d.ts   #  10 줄
diff package/sdk.d.ts        <0.3.220>/sdk.d.ts         # 183 줄
diff package/manifest.json   <0.3.220>/manifest.json
```

타입 선언은 **컴파일 바이너리와 달리 완전히 읽히므로**([1.1절](01-패키지-구조와-프로세스-모델.md#11-실물-인벤토리)), wire 규약 변화는 이 diff 로 남김없이 잡힌다. 바이너리 내부 동작 변화는 잡히지 않는다(7.4절).

## 7.2 ★ 결론 — subagent/task/background 영역은 **무변경**

관심 영역의 타입을 블록 단위로 대조한 결과:

| 타입 | 0.3.215 ↔ 0.3.220 |
|---|---|
| `AgentOutput` 전체 (`completed` / `async_launched` / `remote_launched` 3-variant) | **완전 동일** |
| `AgentInput.run_in_background` (기본값 서술 JSDoc 포함) | **완전 동일** |
| `AgentDefinition` (`background` · `observer` 포함) | **완전 동일** |
| `SDKTaskStartedMessage` | **완전 동일** |
| `SDKTaskProgressMessage` | **완전 동일** |
| `SDKTaskNotificationMessage` | **완전 동일** |
| `SDKTaskUpdatedMessage` | **완전 동일** |
| `SDKBackgroundTasksChangedMessage` (level 신호 규약 JSDoc 포함) | **완전 동일** |
| `SDKControlBackgroundTasksRequest` | **완전 동일** |
| `SDKControlStopTaskRequest` | **완전 동일** |
| `TaskOutputInput` / `TaskStopInput` | **완전 동일** |

**즉 [5장](05-비동기-턴-전환-listen-모델.md)이 확정한 비동기 턴 전환 규약은 이번 구간에서 한 글자도 바뀌지 않았다.** 기본값(`run_in_background` = true), 런치 영수증 shape, `task_*` 이벤트 필드, level/edge 이중화, 제어 API 모두 그대로다.

`AgentInput` 의 유일한 변화는 **이미 deprecated 된 필드의 유니언 축소**다:

```diff
-  mode?: "acceptEdits" | "auto" | "bypassPermissions" | "default" | "dontAsk" | "plan" | "bubble";
+  mode?: "acceptEdits" | "auto" | "bypassPermissions" | "default" | "dontAsk" | "plan";
```
— `sdk-tools.d.ts:516`

`"bubble"` 이 빠졌다. 다만 이 필드의 JSDoc 은 양 버전 모두 *"Deprecated; ignored. Subagents inherit the parent session's permission mode"* 이므로 **런타임 영향 0**이다([4.3절](04-subagent-호출-규약.md#43-호출-스키마--agentinput)).

`sdk-tools.d.ts` 의 나머지 변경 2건도 무관하다 — `ArtifactOutput.liveSubscription?: string` 신설(`sdk-tools.d.ts:409`)과 Artifact `force` 필드 JSDoc 문구 개정.

## 7.3 그 외 영역의 변경 (참고)

`sdk.d.ts` 183줄 diff 중 의미 있는 것:

### 턴 큐 — `interrupt` 에 큐 취소 옵션 추가 ★

[2.3절](02-제어-프로토콜과-턴-큐.md#23-입력-큐와-drain-루프--5장의-기반)의 큐 구조에 **직접 닿는 유일한 변경**이다.

```ts
// 요청 쪽 신규 필드
cancel_queued?: boolean;
// 응답 쪽 신규 필드
cancelled?: string[];
```

새 capability 문자열이 생겼다:

| 버전 | `interrupt_*` capability |
|---|---|
| 0.3.215 | `interrupt_receipt_v1` |
| **0.3.220** | `interrupt_receipt_v1` + **`interrupt_cancel_queued_v1`** |

의미: 기존 `interrupt` 는 진행 중 턴만 중단하고 **큐에 남은 명령은 살려 뒀다**(`still_queued` 로 알려줌). 이제 `cancel_queued:true` 를 주면 큐 잔여분까지 함께 취소하고 취소된 uuid 를 `cancelled` 로 되돌려준다 — *"still_queued is always empty … including any uuid that was mid-fold at the interrupt instant"*.

[2.2절](02-제어-프로토콜과-턴-큐.md#capability-협상--버전-스니핑-대신)의 capability 협상 설계가 실제로 굴러가는 예시다. 소비자는 버전을 보지 말고 `capabilities` 배열에 `'interrupt_cancel_queued_v1'` 가 있는지로 판정해야 한다.

> **auto-resume continuation 과의 관계**: `still_queued` / `cancelled` 목록에는 *"internally-enqueued uuids the client never sent (cron triggers, auto-resume continuations)"* 가 섞일 수 있다는 서술이 **양 버전 모두 동일하게** 유지된다([5.5절](05-비동기-턴-전환-listen-모델.md#55-e-auto-resume-continuation--서버가-새-턴을-연다)). 즉 `cancel_queued:true` 는 백그라운드 완료 알림이 열 예정이던 턴도 함께 날릴 수 있다 — 취소 의미가 넓어진 것이므로 사용 시 주의가 필요하다.

### 훅 — `DirectoryAdded` 이벤트 신설

`HookEvent` 유니언이 30 → **31종**이 됐다. 추가분은 `DirectoryAdded` 하나.

```ts
export declare type DirectoryAddedHookInput = BaseHookInput & {
    hook_event_name: 'DirectoryAdded';
    /** Absolute path of the directory that was added. */
    directory: string;
    /** How the directory was added: "slash_command" for /add-dir,
     *  "register_repo_root" for the SDK control_request. */
    source: 'slash_command' | 'register_repo_root';
};
```

[3.4절](03-tool-calling-규약.md#34-hook-개입-지점)의 훅 목록에 한 줄 추가되지만 도구/서브에이전트 라이프사이클과는 무관하다.

### 나머지

| 변경 | 영역 |
|---|---|
| `FastModeDisabledReason` 타입 신설 + `fast_mode_disabled_reason` 필드 3곳 추가 | fast mode 텔레메트리 |
| `set_model` 의 `model?: string` → `string \| null` (*"Omitted, null, or 'default' resets to the session default model"*) | 런타임 설정 |
| 샌드박스 `strictAllowlist?: boolean` · `disabled?: boolean` 신설 | 샌드박스 정책 |
| `workflowSizeGuideline?: 'unrestricted'\|'small'\|'medium'\|'large'` | 워크플로 |
| 크로스세션 메시징 `fromSession` · `verifiedPeerPid`(SO_PEERCRED 기반) | 세션 간 메시징 |
| `add_dir` 가 *"strict subdirectory of cwd"* 로 문구 강화 | 워크스페이스 |
| `precomputeCompactionEnabled` · `voiceEnabled` · `emojiCompletionEnabled` 설정 | 설정 |
| 비용 항목에 `canonicalModel` · `provider` 추가 | 비용 추적 |
| mtime 관련 서술이 *"integer milliseconds"* 로 명확화 | 파일 |

**깨지는 변경(breaking change) 없음** — 관찰된 것은 전부 필드 추가, 옵셔널 확장, 문구 개정, deprecated 유니언 축소다.

## 7.5 재현·관측으로 좁히는 방법

위 목록을 정적 분석으로는 더 못 좁힌다. **패키지에서 확인된 관측 수단**만 정리한다(추측한 방법은 넣지 않았다).

### ① raw JSONL 덤프

가장 강력하다. `sdk.mjs` 는 stdin 쓰기를 앞 100자까지 로그한다:

```
[ProcessTransport] Writing to stdin: {"type":"control_response",…
```

출력 쪽 전량을 보려면 `pathToClaudeCodeExecutable` 에 **래퍼 스크립트**를 물려 stdio 를 tee 하면 된다 — `Options` 에 있는 공식 필드이므로 지원되는 경로다. 이것으로 다음을 직접 관측할 수 있다:

- auto-resume continuation 이 여는 턴의 **정확한 프레임 순서** (`task_notification` 이 턴 시작 전인지 후인지)
- `task_*` 와 `background_tasks_changed` 의 실제 도착 순서 (규약상 *"unspecified"*, [2.4절](02-제어-프로토콜과-턴-큐.md#24-관측-신호-edge-와-level))
- 배치 coalescing 이 실제로 몇 개를 묶는지

### ② `stderr` 콜백

`Options.stderr?.(line)` 콜백이 존재한다(`sdk.mjs` 의 `this.options.stderr?.(y)` 호출부). CLI 의 진단 출력을 호스트로 끌어올 수 있다.

### ③ 훅으로 라이프사이클 계측

[3.4절](03-tool-calling-규약.md#34-hook-개입-지점)의 31종 중 `TaskCreated` · `TaskCompleted` · `SubagentStart` · `SubagentStop` · `PreToolUse` · `PostToolUse` 를 전부 등록해 타임스탬프를 찍으면, **권한 평가와 훅의 실제 순서**를 실측으로 확정할 수 있다(3.5절이 "부분 순서만 확정" 으로 남긴 부분).

`Options.includeHookEvents: true` 를 켜면 훅 이벤트가 SDKMessage 로도 나온다(`sdk.d.ts:1626` 부근).

### ④ capability 배열 확인

`initialize` 응답의 `capabilities` 를 그대로 찍어 보면, 문서에 없는 capability 문자열까지 포함해 **그 CLI 가 실제로 지원하는 프로토콜 확장 전체**를 알 수 있다. 유니언이 아니라 open set 이므로 타입 선언만으로는 전수를 알 수 없다.

### ⑤ 버전 델타 재실행

다음 bump 때 7.1절 절차를 그대로 반복한다. 관심 영역만 빠르게 판정하려면:

```bash
# 서브에이전트/태스크 영역이 움직였는가 — 블록 단위 대조
for t in SDKTaskStartedMessage SDKTaskProgressMessage SDKTaskNotificationMessage \
         SDKTaskUpdatedMessage SDKBackgroundTasksChangedMessage \
         SDKControlBackgroundTasksRequest SDKControlStopTaskRequest AgentDefinition; do
  diff <(sed -n "/declare type $t = {/,/^};/p" OLD/sdk.d.ts) \
       <(sed -n "/declare type $t = {/,/^};/p" NEW/sdk.d.ts) >/dev/null \
    && echo "IDENTICAL  $t" || echo "CHANGED    $t"
done
diff <(sed -n '/export interface AgentInput/,/^}/p' OLD/sdk-tools.d.ts) \
     <(sed -n '/export interface AgentInput/,/^}/p' NEW/sdk-tools.d.ts)
# capability 신설 여부
diff <(grep -o '[a-z_]*_v[0-9]' OLD/sdk.d.ts | sort -u) \
     <(grep -o '[a-z_]*_v[0-9]' NEW/sdk.d.ts | sort -u)
```

## 7.6 스냅샷 고지

본 세트는 **`@anthropic-ai/claude-agent-sdk@0.3.220` (CLI 2.1.220, commit `4073f595…`, build 2026-07-24)** 스냅샷이다.

wrapper 와 CLI 는 독립 릴리스 트레인이고([1.2절](01-패키지-구조와-프로세스-모델.md#12-버전-좌표-sdk--cli)) 이 영역은 실제로 움직인 전례가 있다 — CLI 2.1.198 의 기본값 전환이 그것이다. 버전을 올릴 때는 7.5절 ⑤ 를 먼저 돌려 **이 문서의 5장이 아직 유효한지** 확인할 것.
