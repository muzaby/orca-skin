# 컴포저 상단 행 — 버튼 구성

컴포저 입력 **위** 에 붙는 행이다. 한 행이 저장소 하나이고, 행들이 세로로 쌓인다.

```
[상태] [PR] [저장소] [브랜치] ──────────── [diff] [CI] [닫기]
 초안  #397  orca-skin  claude/0205-…-suspend   +1,097 −24  ●CI▾  ×
```

## 1. 인벤토리 — 7자리, 6조작

| # | 자리 | 요소 종류 | 형태 | 무엇을 여는가 | 줄어드는가 | 툴팁 |
|---|---|---|---|---|---|---|
| 1 | 상태 | `<span role="img">` | 아이콘 글리프 | — (표시 전용) | `shrink-0` | ✅ |
| 2 | PR 번호 | **`<a target="_blank">`** | 텍스트 링크 | 브라우저(GitHub) | `shrink-0` | ✅ |
| 3 | 저장소 | `<button>` ghost | 텍스트 | `aria-haspopup="menu"` | `shrink`, `max-w-160px` | ✅ |
| 4 | 브랜치 | `<button>` ghost | 텍스트 | `aria-haspopup="menu"` | **`shrink-[9999]`** | ✅ |
| 5 | diff 수치 | `<button>` **채움** | 텍스트 `+1,097 −24` | (사이드 패널 토글) | `shrink-0` | ✅ |
| 6 | CI | `<button>` **채움** | 점 + `CI` + ▾ | `aria-haspopup="dialog"` | `shrink-0` | ✅ |
| 7 | 닫기 | `<button>` ghost | 아이콘 전용 | — (즉시 실행) | `shrink-0` | ❌ |

**1번은 버튼이 아니다.** 상태(초안/열림/병합/충돌)는 누를 것이 없으므로 `role="img"` +
`aria-label="초안"` 인 표시 전용 글리프다. 옆의 PR 번호가 그 상태의 대상이고, 그것만 누를 수 있다.

## 2. 배치 — 좌는 식별, 우는 조작

행은 두 덩어리다.

| | 자리 | 공통 성질 |
|---|---|---|
| **좌 (leading)** | 상태 · PR · 저장소 · 브랜치 | *이 행이 무엇인가* — 전부 배경 없음(ghost/표시), 남는 공간을 먹는다 |
| **우 (trailing)** | diff · CI · 닫기 | *이 행으로 무엇을 하는가* — 절대 줄지 않는다 |

경계는 눈에 보이는 구분선이 아니라 **shrink 성질**이다. 좌측만 `flex-1 min-w-0` 인 실제 박스이고,
우측 세 버튼은 래퍼가 `display:contents` 라 행의 직계 자식처럼 **각자 따로** 협상한다. 우측을 실제
박스로 묶으면 "그룹 전체" 가 한 단위가 되어 개별 버튼의 `shrink-0` 이 의미를 잃는다.

## 3. 순서 — DOM 순서가 곧 축소 순서다

좌측 네 자리를 **안정적인 것 → 가변적인 것** 으로 놓았다.

```
상태(고정)  →  #397(고정 자릿수)  →  orca-skin(중간, ≤160px)  →  브랜치(가변, 무제한)
shrink-0       shrink-0              shrink(1)                   shrink-[9999]
```

DOM 순서와 shrink 서열이 일치하므로 **잘림이 항상 행의 같은 지점(브랜치)에서만 일어난다.**
폭이 줄어도 앞쪽 세 자리는 픽셀 단위로 제자리에 남는다 — 여러 행이 쌓였을 때 `#397` · `#398` 이
세로로 정렬돼 읽히는 이유가 이것이다.

우측은 반대로 **자주 쓰는 것 → 드문 것** 이다: diff(항상 본다) → CI(상태 확인) → 닫기(끝낼 때).
닫기가 마지막인 것은 두 캡처에서 예외 없이 지켜진다.

## 4. 위계 — 채움은 두 자리에만 준다

| 형태 | 자리 | 뜻 |
|---|---|---|
| 배경 없음 (ghost) | 상태 · PR · 저장소 · 브랜치 · **닫기** | 읽는 자리, 그리고 종료 |
| 채움 (`bg-fill-secondary` + `shadow-field`) | **diff · CI** | 여기 정보가 더 있다 |

일곱 자리 중 **둘만** 떠 있다. 그 둘의 공통점은 *누르면 새 표면(사이드 패널 / 팝오버)이 열린다* 는
것이다 — 메뉴를 여는 저장소·브랜치는 채움을 받지 못했다. 즉 채움의 기준은 "누를 수 있는가" 가
아니라 **"화면이 얼마나 바뀌는가"** 다.

**닫기가 ghost 인 것이 이 규칙의 증거다.** 되돌리기 어려운 조작이지만 시각적으로 앞세우지 않는다.
강조는 정보 접근에 주고, 파괴·종료에는 주지 않는다.

## 5. 간격 — gap 이 아니라 각자의 패딩으로 만든다

좌측 컨테이너는 **`gap-g0`(간격 0)** 이다. 자리 사이의 공백은 전부 각 요소의 패딩에서 나온다.

| 지점 | 값 | 왜 |
|---|---|---|
| 저장소 · 브랜치 버튼 패딩 | `!px-p4` (기본 `px-md` 를 덮어씀) | 식별 칩끼리는 기본 버튼보다 촘촘하게 |
| PR 링크 패딩 | `px-p4` | 위 둘과 같은 값 — 셋이 한 줄기로 읽힌다 |
| PR 링크 뒤 | **`mr-[12px]`** | *번호* 와 *이름* 의 경계. 여기만 벌린다 |
| 좌측 그룹 끝 | **`mr-[32px]`** | 닫기 버튼(정사각 `w-control`) 자리 예약 |

gap 대신 패딩을 쓰면 **버튼의 hover 배경이 서로 닿지 않으면서 텍스트 간격은 균일하게** 유지된다.
gap 을 주면 hover 영역 사이에 죽은 틈이 생기고, gap 을 0으로 두고 패딩만 키우면 hover 배경이
붙어 하나의 띠처럼 보인다 — `px-p4` 는 그 사이 값이다.

`mr-[32px]` 는 우측이 `display:contents` 라 좌측 `flex-1` 이 행 끝까지 밀고 들어오기 때문에
필요하다. 닫기 버튼 폭을 마진으로 예약해 브랜치 이름이 그 밑으로 흐르지 않게 한다.

## 6. 무엇이 열리는지를 요소가 선언한다

| 결과 | 선언 | 자리 |
|---|---|---|
| 앱 밖(브라우저) | `<a target="_blank" rel="noopener">` | PR |
| 드롭다운 메뉴 | `aria-haspopup="menu"` | 저장소 · 브랜치 |
| 팝오버 다이얼로그 | `aria-haspopup="dialog"` + `data-base-ui-click-trigger` | CI |
| 사이드 패널 | (선언 없음) | diff |
| 즉시 실행 | (선언 없음) | 닫기 |

**`<a>` 는 행 전체에서 딱 하나** — 앱 밖으로 나가는 것만 링크다. 나머지는 전부 `<button>`.
"이게 나를 어디로 데려가는가" 가 스타일이 아니라 **요소 종류와 ARIA 속성**으로 갈린다.

## 7. 접근성 이름 — 잘림과 무관하게 온전하다

| 자리 | 보이는 것 | 접근성 이름 |
|---|---|---|
| 상태 | 글리프 | `aria-label="초안"` |
| 브랜치 | `claude/0205-…-ti` `le-suspend` (2조각) | `aria-label` 에 전체 문자열 |
| diff 수치 | `+1,097` `−24` (색으로 구분) | `sr-only` → `"1,097 추가 24 삭제"` |
| CI | 점 + `CI` | `aria-label="CI: 검사 진행 중"` |
| 저장소 | `orca-skin` | (텍스트 그대로 — CSS 잘림은 이름을 바꾸지 않는다) |

세 가지가 각각 다른 이유로 `aria-label` 을 갖는다: **글리프라서**(상태), **DOM 이 쪼개져
있어서**(브랜치), **색이 의미라서**(diff 수치). 저장소만 아무것도 없는데, 잘림이 CSS `truncate`
한 겹이라 텍스트 노드가 온전하기 때문이다 — 필요할 때만 붙인다.

닫기 버튼만 툴팁이 없다(다른 여섯은 전부 `data-base-ui-tooltip-trigger`). `aria-label="닫기"` 와
보편적인 × 아이콘으로 충분하다는 판단으로 보이는데, **diff 패널 헤더의 닫기 버튼은 툴팁을 갖는다** —
같은 조작에 대한 두 표면의 규약이 어긋나 있다.

## 8. 컨테이너 — 행이 여럿일 수 있다

```
nav[aria-label="저장소 및 풀 리퀘스트 제어"]
    .flex .flex-col .gap-g5
    .max-h-[50vh] .overflow-y-auto .overscroll-contain .empty:hidden
```

`flex-col` + `gap-g5` — **단수 UI 가 아니다.** 저장소/PR 이 여럿이면 행이 쌓이고, 많아지면
화면 절반 안에서 스크롤한다. `empty:hidden` 이라 행이 0개면 컨테이너 자신이 사라진다.

즉 이 행은 "현재 저장소 표시줄" 이 아니라 **작업 중인 PR 목록**이다. 각 행의 닫기 버튼이
"이 PR 을 목록에서 뺀다" 는 뜻인 것도 그래서다 — 단수 표시줄이었다면 닫기가 있을 이유가 없다.
