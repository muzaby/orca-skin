# 컴포저 상단 스택 — 저장소·PR·브랜치 행

컴포저 입력 **위** 에 붙는 행이다. 한 행이 저장소 하나이고, 행들이 세로로 쌓인다.

```
[상태] [PR] [저장소] [브랜치] ────────────── [diff] [CI] [닫기]
 초안  #397  orca-skin  claude/0205-cowork-…-suspend   +1,097 −24  ● CI  ×
```

## 1. 골격

```
nav[aria-label="저장소 및 풀 리퀘스트 제어"]
    .scroll-fade-y .flex .flex-col .gap-g5
    .max-h-[50vh] .overflow-y-auto .overscroll-contain .empty:hidden
└ div.epitaxy-branch-row.epitaxy-composer-aux-view
  ├ div.epitaxy-branch-leading   .flex-1 .flex .items-center .gap-g0 .min-w-0 .mr-[32px]
  │ ├ span[role=img][aria-label="초안"] .shrink-0 .text-git-draft      ← 아이콘 폰트 글리프
  │ ├ a[href=".../pull/397"][target=_blank][rel=noopener]
  │ │     .shrink-0 .px-p4 .mr-[12px] .tabular-nums .text-muted .hover:text-git-draft
  │ ├ button.epitaxy-branch-repo  .max-w-[160px] .shrink   [aria-haspopup=menu]   "orca-skin"
  │ └ span.epitaxy-branch-flow.contents
  │   └ button .min-w-0 .shrink-[9999] [aria-haspopup=menu][aria-label=<전체 브랜치명>]
  │     └ span[dir=ltr].flex.min-w-0.overflow-hidden
  │       ├ span.truncate                     "claude/0205-cowork-study-and-task-ti"
  │       └ span.max-w-full.shrink-0.truncate "le-suspend"
  └ div.epitaxy-branch-trailing.contents
    ├ button  "+1,097 −24"
    ├ button  [aria-haspopup=dialog][aria-label="CI: 검사 진행 중"]  ●CI ▾
    └ button  [aria-label="닫기"] iconOnly ghost
```

## 2. 여섯 가지 결정

### ① `display: contents` — 그룹은 짓되 레이아웃은 짓지 않는다

`epitaxy-branch-trailing` 과 `epitaxy-branch-flow` 는 **`contents`** 다. JSX 상의 의미 그룹(후행 조작,
브랜치 흐름)이 flex 계산에는 존재하지 않으므로, 세 트레일링 버튼이 행의 **직계 flex 자식처럼** 각자
shrink 협상에 참여한다.

그룹을 실제 박스로 두면 "그룹 전체" 가 하나의 shrink 단위가 되어 *브랜치만 골라 줄이는* 일이 불가능해진다.
컴포넌트 경계(누가 무엇을 렌더하는가)와 레이아웃 경계(무엇이 함께 줄어드는가)를 **분리한 것이 핵심**이다.

반대로 `leading` 만 실제 박스(`flex-1 min-w-0`)인 이유도 같다 — 남는 공간을 전부 먹고, 부족하면 그
*안에서* 다시 협상해야 하기 때문이다.

### ② shrink 계수로 줄임 우선순위를 서열화한다

| 요소 | shrink | 폭 제한 |
|---|---|---|
| 브랜치 | `shrink-[9999]` | — |
| 저장소 | `shrink` (=1) | `max-w-[160px]` |
| 상태 아이콘 · PR 번호 | `shrink-0` | — |
| diff 수치 · CI · 닫기 | `shrink-0` | — |

폭이 줄면 브랜치가 거의 전부를 흡수하고, 그래도 모자라면 저장소가 160px 안에서 마저 준다.
**식별자(#397)와 조작(diff·CI·닫기)은 절대 줄지 않고, 이름만 줄어든다.** 미디어 쿼리도 JS 측정도 없이
비율 하나로 우선순위를 표현했다.

### ③ 머리-자르기 + 꼬리-보존 2-span 트렁케이션

한 span 에 `truncate` 를 걸면 꼬리가 날아가 `claude/0205-cowork-study-and-…` 가 되고 브랜치가 서로
구분되지 않는다. 그래서 문자열을 둘로 쪼갠다.

| span | 클래스 | 역할 |
|---|---|---|
| 앞 | `truncate` | 줄어드는 쪽 — 여기서 `…` 가 난다 |
| 뒤 | `max-w-full shrink-0 truncate` | 끝까지 남는 쪽 |

같은 패턴이 diff 패널 파일 경로에도 그대로 쓰인다(`app/src/renderer/src/features/chat/` + `components`).
**분할 지점이 다르다**: 경로는 마지막 세그먼트라는 *의미 경계*이고, 브랜치는 `…-ti` / `le-suspend` 로
임의 문자 위치라 **문자 수 비율 분할로 추정**된다(규칙은 이 캡처로 확정 불가).

전체 문자열은 버튼의 `aria-label` 이 갖는다 — 시각적으로 잘려도 스크린리더는 온전한 이름을 읽는다.

### ④ `mr-[32px]` 는 닫기 버튼 자리다

트레일링이 `contents` 라 leading 의 `flex-1` 이 행 끝까지 밀고 들어온다. 닫기 버튼(정사각 `w-control`)
폭만큼을 마진으로 예약해 텍스트가 그 밑으로 흐르지 않게 한다. 예약 폭이 하드코딩된 32px 인 것은
컨트롤 높이 토큰이 고정이라 성립하는 결합이다.

### ⑤ 수치는 이중 표기 — 색과 문장을 나눈다

```html
<span class="sr-only">1,097 추가 24 삭제</span>
<span aria-hidden="true" class="contents">
  <span class="text-git-added">+1,097</span><span class="text-git-removed">−24</span>
</span>
```

색으로만 구분되는 정보(초록 추가 / 빨강 삭제)를 스크린리더에는 **문장으로** 준다. `−` 는 U+2212
(하이픈이 아니다), `tabular-nums` 로 숫자가 바뀌어도 자릿수가 흔들리지 않는다.

### ⑥ 상태는 세 개의 독립 축이다

| 축 | 표현 | 접근성 |
|---|---|---|
| PR 상태 | 아이콘 글리프 + `text-git-draft` | `role="img" aria-label="초안"` |
| CI | `span.status-dot[data-kind="running"]` | 버튼 `aria-label="CI: 검사 진행 중"` |
| 변경량 | `+1,097 −24` | `sr-only` 문장 |

하나의 배지로 합치지 않는다. 상태는 **CSS 클래스 조합이 아니라 `data-kind` 속성**으로 구동되므로
(`status-dot[data-kind=running|success|failure|…]`) 상태가 늘어도 클래스 조합이 폭발하지 않는다.

## 3. 컨테이너 — 스택의 성질

| 클래스 | 뜻 |
|---|---|
| `flex-col` + `gap-g5` | 행이 여럿 = 저장소/PR 이 여럿. 단수 UI 가 아니다 |
| `max-h-[50vh]` + `overflow-y-auto` | 많아지면 스크롤. 컴포저가 화면을 삼키지 않는다 |
| `overscroll-contain` | 끝까지 스크롤해도 뒤 대화록으로 전파되지 않는다 |
| `scroll-fade-y` | 잘린 위/아래 가장자리 페이드(구현 미관측) |
| `empty:hidden` | 자식이 없으면 **자기 자신이 사라진다** — 조건부 렌더가 필요 없다 |

`empty:hidden` 은 작지만 중요한 결정이다. "행이 0개면 nav 를 렌더하지 않는다" 를 JS 조건문이 아니라
CSS 선택자로 옮겨, 렌더 트리에서 빈 컨테이너의 gap/padding 이 남는 사고를 구조적으로 막는다.

## 4. 상호작용 표면

| 요소 | 요소 종류 | 팝업 |
|---|---|---|
| PR `#397` | `<a target=_blank rel=noopener>` | — (유일한 외부 이동) |
| 저장소 | `<button>` | `aria-haspopup="menu"` |
| 브랜치 | `<button>` | `aria-haspopup="menu"` |
| diff `+1,097 −24` | `<button>` (secondary 채움 + `shadow-field`) | — (패널을 연다) |
| CI | `<button>` (secondary 채움) | `aria-haspopup="dialog"` |
| 닫기 | `<button>` ghost iconOnly | — |

**채움이 곧 위계다.** 좌측(식별)은 전부 ghost 라 배경에 가라앉고, 우측(조작)의 diff·CI 만
`bg-fill-secondary shadow-field` 로 떠 있다. 같은 행에서 "무엇을 읽는 자리" 와 "무엇을 누르는 자리" 가
색 채도로 갈린다.

## 5. 버튼 프리미티브 (참고)

모든 버튼이 같은 구조다.

```html
<button class="cds-reset group/btn relative isolate …">
  <span aria-hidden class="absolute -z-[1] inset-0 cds-btn-squish">
    <span data-cds-part="paint" class="absolute inset-0 transition-[background-color,box-shadow,color] …"></span>
  </span>
  <span class="inline-flex min-w-0 items-center gap-1">…라벨…</span>
</button>
```

배경을 라벨 뒤의 별도 `paint` 층으로 분리해, hover/pressed/focus 전이가 텍스트 리페인트와 무관하게
일어나고 press 애니메이션(`cds-btn-squish`)이 라벨을 건드리지 않는다.
**Orca `shared/ui/Button` 이 이미 이 구조를 갖고 있다**(주석에 "Epitaxy" 명시) — 새로 볼 것은 없다.
