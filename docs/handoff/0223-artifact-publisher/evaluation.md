# Publisher 모델 선택 평가 — V1 rev.4 실행 기록

> [plan.md](plan.md) AC13·VP-13·VP-43·EP-12의 평가 설계다. **부분 실행·판정 보류**이며 기대 결과와 실제 관측을 혼합하지 않는다. 작성자: Codex.
> 제품에는 감지 hook·watcher·scan·별도 분류 모델을 넣지 않는다. 합성 fixture의 파일을 읽는 시험용 관찰은 제품의 자동 감지 기능과 구분한다.

## 1. 평가 조건

| 항목 | 규칙 |
|---|---|
| 입력 | 개인정보·실제 업무 데이터가 없는 합성 파일과 자연스러운 사용자 요청 |
| 모델 노출 | 고정된 publisher description/instructions/schema. 매 요청에서 도구 이름을 직접 지시하지 않음 |
| 기대 집합 | 실행 전에 필수 게시·게시 금지·허용 결과를 fixture 단위로 확정 |
| 반복 | 시나리오당 3회로 시작하는 안. 모델·SDK·지침 revision을 고정하고 첫 시도/재시도 모두 기록 |
| 외부 실행 | P02는 실제 SDK/CLI와 production runtime/mapper/writer/service를 조립한 fixture로 실행. 전체 ClaudeAdapter 설정·Electron renderer 종단은 미실행 |
| 비교 | 설명을 수정하면 새 revision으로 같은 과업표를 다시 실행. 좋은 결과만 선택하지 않음 |
| 결정 | 작은 표의 비율을 제품 전체 정확도로 일반화하지 않음. 후속 hook/watcher 도입은 사용자 판단 |

## 2. 고정 과업표

### 파일 수명·삭제 검증 — 모델 선택률과 별도

| ID | 조작 | 직접 기대 결과 |
|---|---|---|
| L01 | 게시 후 workspace 입력만 삭제, 재시작 | 지정 artifacts 루트 파일과 참조 유지. 입력 경로로 되돌아가지 않음 |
| L02 | 게시 원본을 외부에서 삭제/이동 | 카드 메타 유지, ‘파일 없음’, 파일 액션 제한. publisher 누락으로 집계하지 않음 |
| L03 | 권한 오류 주입 후 해소 | ‘접근할 수 없음’→정상. 삭제/휴지통 상태로 오분류하지 않음 |
| L04 | UI 휴지통 이동 취소/성공/실패 | 취소는 파일 불변, 성공은 기록 유지·파일 없음·이동 이력, 실패는 영구 삭제 대체 없음 |
| L05 | fork 후 부모/마지막 대화 삭제 | 파일 유지, 살아 있는 자식 참조 정상. 세션 없는 파일도 자동 GC하지 않음 |
| L06 | 휴지통 이동→같은 경로로 복원→외부 삭제 | 복원 확인 시 정상, 재삭제 시 파일 없음. 과거 lastTrashedAt를 이번 소실 원인으로 표시하지 않음 |
| L07 | 삭제 확인 중 세션 전환/삭제, 늦은 stat/삭제 응답 | 원래 ID 검증·중복 실행 방지, 이전 present로 되돌리거나 삭제된 세션 재생성 없음 |
| L08 | 휴지통 이동 성공 뒤 DB 기록 실패 | 이동 성공/기록 실패 분리, 재시작 후 파일 없음으로 표시, 실제 이동 중복 실행 없음 |
| L09 | 보관된 게시 원본을 외부 수정한 뒤 저장 | 선택한 기록의 경로에서 현재 수정된 바이트 저장. 게시 당시 내용 복원·손상/삭제 판정으로 바꾸지 않음 |
| L10 | HTML/MD 게시 후 카드·목록의 파일 액션 실행 | 본문 표시/실행 없이 원본 바이트 저장·탐색기 대상 일치. 과거 카드의 대상은 최신 목록과 독립. 뷰어용 빈 화면/버튼 없음 |

L01~L10은 임시 홈/보관 루트와 합성 파일에서 수행하며 실제 `~/.config/orca/artifacts`를 정리하거나 fixture로 사용하지 않는다. watcher 없이 알려진 경로만 확인하는 프로그램 시험이며 모델의 누락·오게시 분모에 합산하지 않는다.

## 4. 실패 분류와 분모

| 판정 | 직접 oracle | 분모/해석 |
|---|---|---|
| 생성 실패 | 필수 결과 자체가 만들어지지 않음 | publisher 누락으로 합치지 않음 |
| 게시 누락 | 필수 결과가 준비되고 실행이 게시 기회까지 완료됐으나 해당 결과의 publisher 호출이 없음 | 명확한 양성 중 유효 결과가 준비된 항목 |
| 오게시 시도 | 금지 항목을 모델이 publisher 대상으로 선택 | 전체 게시 시도와 음성 과업별 횟수를 함께 보고 |
| 오게시 확정 | 잘못 고른 항목이 실제 게시 원장/목록에 반영됨 | 시도와 확정을 분리 |
| 입력/파일 검증 실패 | 호출했으나 스키마·경로·형식·파일 상태 검사에 실패 | 호출 시도 중 해당 실패 |
| 저장 실패 | 검증 통과 후 게시 원본 FS/DB 확정 실패 | 검증을 통과한 게시 시도 |
| 연결/표시 실패 | 저장 성공이나 원래 대화·카드·목록·파일 상태·재조회가 틀림 | 저장 성공 항목 |
| 허위 성공 | 미확정/실패인데 도구 또는 최종 답변이 게시 성공을 주장 | 호출 결과와 모델 설명을 각각 기록 |
| 판정 보류 | 애매한 요청·실행 중단·환경 오류로 선택 품질 평가 불가 | 누락률에서 제외하고 건수/근거 공개 |
| 게시 후 파일 수명/액션 실패 | L01~L10의 수명·파일 액션 계약 불일치 | 게시 당시 모델 선택 오류와 별도 집계 |

`생성됨 → 호출됨 → 검증됨 → 저장됨 → 연결/표시됨` 각 단계의 실제 항목 집합을 남긴다. 총계만 맞춰 배분하지 말고 누락/오게시 대상의 차집합을 제시한다.

## 5. 후속 보완 판단

| 관측 원인 | 먼저 검토할 대응 | watcher 관련성 |
|---|---|---|
| 파일은 알지만 게시 도구를 잊음 | 도구 노출·설명·실패 결과·완료 지침 정정 후 같은 표 재평가 | watcher가 직접 해결하는 문제가 아님 |
| 내부 소스·중간 파일 오선택 | 게시/제외 예시와 과업 기준 보완 | 변경 알림 증가가 오게시를 늘릴 수도 있음 |
| 외부 생성기의 출력 경로를 발견하지 못함 | 제한된 경로 힌트·필요 시 hook에서 변경 관측 연계 | 후속 watcher 검토 대상 |
| 저장·세션 연결·카드/파일 상태 표시 실패 | 프로그램 결함 수정 | 감지 보완으로 우회하지 않음 |

사용자에게 실패 종류·반복성·실제 사례를 보고한다. “빈번함”에 대한 합격률을 임의로 만들어 감지 기능을 자동 활성화하지 않는다.

## 7. 재실행 방법과 남은 범위

`app`에서 Node SQLite ABI를 준비한 뒤 `ORCA_ARTIFACT_LIVE=1`인 자식 환경으로 `node node_modules/vitest/vitest.mjs run src/main/app/artifact-sdk-live.test.ts`를 실행한다. 일반 `npm test`에서는 모델 시험이 skip되며 비용을 발생시키지 않는다. 이 live fixture는 실제 SDK MCP·mapper·runtime·history·DB/FS를 조립하지만 전체 Electron 앱과 생산 ClaudeAdapter 옵션을 대신하지 않는다.

먼저 P02가 정상 종료하는 환경에서 게시 결과와 실제 original toolRunId 연결을 확인한다. 이어 나머지 고정 과업·반복·프로그램 실패 분류를 실행하고 미평가 결과를 선택 품질로 보고하지 않는다. native 파일 액션과 긴 transcript/키보드 인수는 [impl.md](impl.md)의 남은 항목이다. 후속 뷰어는 별도 계획으로 다룬다.
