# r1.3 선행 검토 — plan 보완과 부분 구현

유지 — ΔV1 rev.3은 PG-01의 결과 비교 경계, 열린 부모의 child 정착, 누락된 표시·패널 소비자를 명시한다. 사용자 지시로 Codex가 부분 구현 검토 후 구현을 이어받는다. 독립 verify 결과는 아니다.

| 검토 대상 | 관측 | 판정 / 구현 시 보완 |
|---|---|---|
| PG-01 | `parts.ts`의 `resultEquals`가 본문·오류·시간만 비교하고 `AssistantMessage`와 Work 투영이 이를 사용한다. ΔV1은 값 비교와 두 소비자 oracle을 선언한다. | 계획 보완 타당. EP-10은 아직 미구현 |
| child 정착 | `settle.ts`의 보존 집합은 명시 백그라운드 호출 및 후손을 보존하며, 정본 없음은 별도 분기한다. | D-015 구현 일치. 정본 유무의 coordinator 배선도 테스트됨 |
| terminal 순서 | `turn-coordinator.ts`는 telemetry/error 정착을 `commitConsumed` 앞에, 합성 telemetry 정착을 emit 앞에 둔다. | 구현 위치 타당. steer가 있는 error 순서 증거 추가 필요 |
| pending | `backgroundPending`은 task 절 전체에서 foreground를 제외한다. 기존 tracker 및 post-turn/Stop 소비자는 같은 술어를 사용한다. | 방향 타당. AC12의 Stop 후 새 전송까지 직접 확인 필요 |
| 비실행 사유 | mapper → 이벤트/part 타입 → writer/reader에 optional 값을 보존한다. renderer는 아직 받지 않는다. | 부분 구현 경계 명확. AC8·9·10 완료로 세지 않음 |

| 보고 | INDEX는 부분 구현 8/18인데 plan 구현자 보고는 첫 조사 0/18이다. | 선행 이력으로 보존하고 이번 턴 7개 보고 절과 보드를 함께 갱신 |
