# Part I — Product & UX Contract

## 1. Context / 목표

- **해결하려는 문제**: 문서 인용 게이트의 **완결성 주장이 반증 불가능하다**. 버킷 분류표가 산출에서 재생성되지 않고 산문으로 손유지돼, 6라운드 동안 `미분류 0` 이 참이 아닌 채 ✅ 로 보고됐다.
- **완료 후 달라지는 것**: `미분류 0` · `잔여 0` · 버킷별 사이트 수를 **사람이 적지 않는다.** 스크립트가 baseline 데이터와 현재 산출의 **양방향 차집합**을 내고, 비지 않으면 exit≠0 이다.
- **성공을 한 문장으로**: 다음 세션이 명령 하나를 돌려 "문서가 인용한 심볼·경로·시제가 지금 코드와 맞는가" 를 스스로 판정하고, 틀렸으면 **어느 줄이 틀렸는지** 를 받는다.

## 5. 동작 / 사용자 흐름

소비자는 **다음 세션의 에이전트**다. UI 는 없고 관측면은 명령의 표준 출력과 종료 코드다.

```text
[에이전트가 문서를 고친 뒤 / 코드가 움직인 뒤]
  → doc-gate.sh check
  → 세 축의 양방향 차집합 계산
  ↘ 어느 하나라도 비지 않음 → 어긋난 줄 목록 + exit 1
  → 전부 비었음 → 축별 산출 수 + 버킷별 사이트 수 + exit 0
```

### 상태와 전이

| 시작 상태/이벤트 | 시스템 동작 | 소비자에게 보이는 결과 |
|---|---|---|
| 문서가 없는 심볼을 새로 인용 | 산출에 뜨는데 baseline 에 없다 | `미분류: 1` + `심볼 사이트` 한 줄 + exit 1 |
| 코드가 심볼을 도입해 인용이 참이 됨 | 산출에서 빠지는데 baseline 에 남는다 | `잔류: 1` + 그 심볼 + exit 1 |
| 분류가 필요한 신규 심볼 | `regen` 이 `UNCLASSIFIED` 로 적는다 | `check` 가 `미분류 표식 1` 로 실패 — 조용히 통과하지 않는다 |
| 아무것도 안 바뀜 | 차집합 셋 다 공집합 | 축별 수 + 버킷별 사이트 수 + exit 0 |

### 파생 UX / 엣지케이스

- **error**: 스크립트가 SCOPE·CORPUS 경로를 못 찾으면 빈 산출로 "통과" 하지 말고 exit≠0 으로 죽는다 — 눈이 없는 장치의 0건이 전수로 읽히는 것을 막는다.
- **cancel / retry**: 없음. 읽기 전용 스윕이라 중단해도 잔여 상태가 없다. `regen` 만 파일을 쓴다.
- **concurrency**: 해당 없음 — 단일 프로세스, 단일 트리.
- **폐쇄망/오프라인**: 네트워크 의존 0. `grep`·`sed`·`find`·`sort`·`join` 만 쓴다(§14).

### AC 검증 주의사항

- **기존 테스트 재사용**: 없음. 코드 변경이 0 이라(D-101) `app/**` 테스트를 인수 수단으로 쓰지 않는다. AC13 만 기존 가드를 회귀 수단으로 쓴다.
- **사람 실기 항목**: 시제 축의 **참/거짓 판정**은 정규식이 못 가린다(0191 §19 가 확인). 산출 목록을 만드는 것까지가 기계이고 각 줄의 단언이 참인지는 육안이다 — 그 판정 결과가 `tense-sites.tsv` 의 값이다.
- **총량/0건 기준**: AC2·AC3·AC8·AC9 의 `0` 은 전부 **차집합의 크기**다. 합계가 총계와 맞는 것은 근거가 아니다 — 0191 두 라운드가 그 근거로 통과했고 실제 차집합은 비어 있지 않았다.
- **AC4 는 음성 게이트**다. 허용 대상과 제거 대상을 가른다: 축별 **총 산출 수**(`296` 같은 단일 수치, 재현 명령 1줄로 반증 가능)는 산문에 적어도 된다. 금지 대상은 **버킷별 내역**(6행 분해) — 손으로 배분할 수 있는 형태다.
- **AC4 의 대상은 0192 산출물이다.** 0191 `plan.md §19` 의 r6 시점 버킷표는 그 handoff 의 과거 관측이고 D-007 이 고치지 말라고 한다 — 대상이 아니다. 0192 는 그 표를 복제하지 않고 링크한다.
- **AC1 은 AC10 과 다르다.** AC1 은 *baseline 쪽* 에 결함을 심고, AC10 은 *스윕 쪽* 에 심는다. 둘 다 통과해야 장치에 눈이 있다.
- **AC11 은 설계 턴이 이미 한 번 만족시켰다** — plan/READY 커밋이 두 행을 그렇게 썼다(5·4문장). 그러나 구현·검증 턴이 같은 행을 다시 쓰므로 AC 는 **매 턴의 최종 상태**에 건다. O1 이 r5 773 → r6 841 로 늘어난 것이 그 이유다.

## 9. Architecture / Data & Control Flow — AS-IS → TO-BE

### AS-IS — 현재 구조와 문제 발생 경로

- **현재 책임 소유자**: `docs/handoff/0191-docs-code-resync/plan.md §19` 한 절이 스윕 정의·분류 결과·예외 목록·한계 기록을 **전부 산문으로** 갖는다.
- **현재 흐름**: 사람이 §19 의 bash 블록을 복사해 붙여넣고 → 산출을 눈으로 읽고 → 산문 표를 **손으로 고치고** → "미분류 0" 을 문장으로 적는다.
- **현재 오류 경로**: 표를 안 고쳐도 아무것도 실패하지 않는다. 합계만 총계에 맞추면 검산 줄이 통과한다.
- **직접 원인**: **판정의 정본이 실행 불가능한 텍스트다.** 산출과 표를 잇는 것이 사람의 성실성뿐이라, 6라운드 동안 L1·N1·N2·N3 이 살아남았다.

```text
§19 산문 (스윕 정의 + 분류 결과 + 예외 + 한계)
  → 사람이 복붙 실행
  → 사람이 표를 손으로 갱신
  → 사람이 "미분류 0" 을 적음        ← 검증 불가 지점
  → verify 가 총계로 재현 ✅
```

### TO-BE — 변경 후 목표 구조와 동작 경로

- **변경 후 책임 소유자**: `0192-.../doc-gate.sh` 가 *정의*를, `0192-.../baselines/*.tsv` 가 *판정 결과*를 갖는다. 산문은 어느 쪽도 복제하지 않고 링크한다.
- **변경 후 흐름**: `doc-gate.sh check` 가 세 축을 스윕하고 baseline 과 **양방향 차집합**을 내고 종료 코드로 답한다. 사람이 하는 일은 신규 항목의 **분류/판정 값을 채우는 것** 하나다.
- **변경 후 오류 경로**: 표를 안 고치면 `잔류`/`미분류` 가 뜨고 exit≠0. `regen` 이 신규를 `UNCLASSIFIED`/`UNJUDGED` 로 적으므로 조용한 통과가 없다.
- **유지하는 메커니즘**: 추출 4축 · CORPUS 정의 · 단어 경계 매칭 · 사이트 단위 분모 · 5버킷 이름 · 경로 3형태 · 시제 술어 — 0191 이 6라운드에 걸쳐 좁힘을 고친 정의를 그대로 승계한다.
- **대체하는 메커니즘**: 산문 표 → TSV. 사람의 합계 검산 → 스크립트의 차집합.
- **신설**: 후행 주석 판정(D-004) · 사이트 경로 기반 비범위 파생(D-005) · 3-pass 스윕(§14).

```text
doc-gate.sh sweep {symbols|paths|tense}   ← 정의의 정본 (실행 가능)
  → baselines/{symbol-buckets,path-exceptions,tense-sites}.tsv   ← 판정의 정본
  → doc-gate.sh check → 양방향 차집합 · 버킷별 사이트 수 · exit code
  → plan/verify/INDEX 는 재현 명령만 인용                        ← 사본 없음
```

### 테스트 가능성

- **electron/DB/native 의존 없음.** 스크립트는 POSIX 도구만 쓰므로 순수 실행이다 — 분리할 seam 이 필요 없다.
- **기존 메커니즘 재사용 적합성**: 0191 §19 의 스윕 정의를 그대로 옮긴다. 이번 세션에서 3-pass 재작성본이 1-pass 넓힘본과 **산출 0줄 차이**임을 실측했다(§14) — 재작성이 정의를 바꾸지 않는다.
- **순서 관측**: 필요 없다. 세 축은 서로 독립이고 `check` 는 축별로 독립 리포트를 낸다.

## 12. End-to-end 영향

### producer → consumer

```text
저장소 트리(코드+문서) → doc-gate.sh sweep → baselines/*.tsv 대조 → check 리포트 → 에이전트의 다음 행동
```

- **producer 기준**: 산출 한 줄 = `(종류, 심볼, 사이트)` 고유 조합. dedup 은 `sort -u` 뒤가 정본이다(0191 §19 r4 규칙 승계).
- **consumer 파생 규칙**: 버킷별 사이트 수는 **소비자가 세지 않는다** — `check` 만 낸다. 사람이 파생 가능한 합성값(합계)으로 정본을 우회하는 것이 0191 의 실패였다.
- **파생 합성값 차단**: AC4 가 산문에서 버킷별 내역을 금지한다. 축별 총 산출 수는 재현 명령 1줄로 반증 가능하므로 허용한다.

## 13. Lifecycle / 오류 / 정리

- **생성/시작**: `check` 는 SCOPE·CORPUS·TSV 3종의 실재를 먼저 확인하고, 하나라도 없으면 스윕 전에 exit≠0.
- **취소/중단**: `sweep`·`check` 는 읽기 전용이라 중단해도 잔여가 없다.
- **retry/partial failure**: `regen` 만 쓰기다. 중간에 죽으면 TSV 가 반만 쓰일 수 있다 → 임시 파일에 쓰고 마지막에 `mv` 한다.
- **cleanup**: 결함 심기(AC10) 후 `git status --short --untracked-files=all` 빈 출력을 구현 보고에 적는다.

**다중 저장소 쓰기 — 이 작업은 문서 산출물이고 판정의 사본이 세 곳에 산다.**

| 쓰기 지점 | 사이에서 멈추면 관측되는 것 | 설계로 없애는 방법 |
|---|---|---|
| `baselines/*.tsv` (정본) | TSV 만 갱신, 보드·verify 는 옛 판정 | 허용 — `check` 를 다시 돌리면 진실이 나온다 |
| `verify.md` 판정 | verify 는 PASS 라 적었는데 TSV 는 미분류 | **수치를 적지 않고 재현 명령을 적는다**(AC4) — 갈릴 사본이 없다 |
| `INDEX.md` 비고 + 커밋 trailer | 보드가 옛 라운드를 가리킨다 | 비고에 수치를 넣지 않고 5줄 이내 링크로 둔다(AC11). trailer `Criteria-Met` 은 AC 축이라 별개 — 합계 검산 줄을 쓴 **뒤** trailer 를 적는다 |

## 14. 성능 / 상한 / 최적화

- **원천 상한 × 배치 상한**: SCOPE 43파일 × 추출 4축 → 후보 쌍 **2013**, 고유 심볼 **922**. 실재 판정은 고유 심볼당 1회이므로 `grep -rnwF` 호출 상한은 **922**다.
- **실측**: 1-pass(쌍마다 grep) **22.6초** → 3-pass(고유 심볼마다 1회) **10.8초**. 같은 트리에서 산출 **0줄 차이**(`diff` 빈 출력).
- **최적화로 잃는 부수 효과**: 없다 — 산출 동치를 실측했다. 회귀 수단은 AC10 의 결함 심기다(지점 정의가 살아 있는지 매 라운드 확인).
- **구조적 목표 없음**: 줄 수·파일 수 목표를 두지 않는다.
