  관찰(우리 코드 주석)이 충돌할 때 2차를 택한 것**이다. 0169 의 조사 R5 가 이미 "`/data` 는
  업로드 좌표" 라고 적었는데도 R6(broker 주석의 302)을 근거로 순서를 반대로 뒀다.
  → 다음 plan 이 따라 할 형태: **"벤더 1차 문서와 저장소 내부 관찰이 충돌하면 1차를 기본으로
  삼고, 내부 관찰을 우선하려면 *그 관찰이 같은 배포·같은 엔드포인트에서 나온 것인지* 를 근거로
  적는다."** — `failure-patterns.md` 에 P28 로 추가한다.

## 결론 / 다음 단계

**PASS.** 사용자가 보고한 405 의 원인(GET 이 막힌 업로드 좌표)을 좌표 우선순위 반전으로 우회했고,
요청한 원본 URL 을 자산·manifest 양쪽에 남겼다.

**사람에게 남는 것 (AC9)**: 사내 페이지를 다시 받아 ⓐ `assets/` 에 이미지가 생기는지
ⓑ `manifest.json` 의 `assets[].sourceUrl` 이 `/download/attachments/…` 인지 확인.
ⓑ 가 전부 그 형태면 `/data` 좌표는 죽은 코드이므로 다음 라운드에서 제거할 수 있다(D1).
