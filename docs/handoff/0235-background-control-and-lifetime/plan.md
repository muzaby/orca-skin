# Part I — Product & UX Contract

## 1. Context / 목표

- 해결하려는 문제: 지금 Orca 의 응답 중지는 **전부 멈춤**이다. 백그라운드 작업만 남기고 메인 턴만
  멈출 방법이 없고, 특정 작업의 종료를 기다리겠다고 말할 방법도 없다.
- 완료 후 달라지는 것: "응답만 중지" 와 "전부 중지" 가 갈리고, 한 작업의 종료를 구독해 알림을
  받을 수 있다.
- 성공을 사용자 관점에서 한 문장으로: 긴 테스트는 계속 돌리면서 클로드의 답변만 끊을 수 있다.

## 4. 요구 비판적 검토

| 질문 | 판단 | 근거 |

| 요구가 원인을 겨냥하는가 | **부분** | F-20 은 충족이고 F-21 은 결함이 아니다. 실제 결손은 F-22 하나다 |
| 이미 기존 코드가 충족하는가 | 대부분 | `stopTask` · `backgroundTasks(toolUseId)` · 중단 수명주기(요청→ACK→정착) · 중단 실패 표시가 모두 있다 |

## 5. 동작 / 사용자 흐름 (D-501 = 예 일 때)

### 상태와 전이

| 시작 상태/이벤트 | 시스템 동작 | 사용자에게 보이는 결과 |
|---|---|---|
| "응답만 중지" | `interrupt()` — 백그라운드 Agent·Workflow 는 유지 | 메인 턴 종료. 백그라운드 실행 줄은 남는다 |
| "전부 중지" | 현행 경로(입력 차단 → 개별 중단 → 재확인) | 남는 항목을 명시한다 — 원자적 완료로 표시하지 않는다 |
| 작업 상세에서 "결과 기다리기" | 그 작업의 종료를 구독 | "완료되면 알려드립니다" |
| 구독 중 연결 끊김 | 확인 불가 표시 | 사용자가 대기를 해제할 수 있다 |
| 대기 취소 | 구독만 해제 | 작업은 계속 돈다 (D-505) |
| 전체 중단 중 새 작업 생성 | 최신 스냅샷 재확인 | 남은 항목을 숨기지 않고 말한다 |

## 6. 범위 / 비범위

- **범위(D-501 = 예)**: F-21 `perTaskStopAffordance` + 두 중지 어포던스와 문구 · F-22 결과
  기다리기/대기 취소 · 전체 중단의 잔여 재확인 표시.
- **범위(D-501 = 아니오)**: F-22 만. 이 handoff 를 닫고 0231 에 흡수한다.
- **비범위**: 일시정지/재개(D-503 — SDK 경계) · 원격 실행 취소 보장(0234) · `cancel_queued`
  제어 경로(스펙도 "검증 필요").

## 9~15

D-501 확정 후 작성한다. 고정된 설계 제약:

| 제약 | 이유 |
