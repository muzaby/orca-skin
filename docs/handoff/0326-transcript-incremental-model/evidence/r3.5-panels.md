## 철회 및 출력 재대조

다섯 기여(부모의 자식 텍스트, 사용자 첨부, 같은 run의 덮어쓴 결과·모델, 독립 에이전트, 셸 호출)를 각각 메시지 삭제와 해당 part부터의 교체로 철회했다. 구 전체조회 결과 외에도 7개 도메인별 revision의 기대 증가량, 부모별 revision, 과거 결과·프로세스 출력을 독립적으로 단언했다. 취소 결과·TaskUpdate 삭제·검색 결과의 철회도 구별했다. [추가 변이 명세](r3.5-panel-retractions.jsonl)

§19 삽입 크기·J1~J10 측정 함수·J9/J10 결과표가 이번 작업의 범위다. 빈 소스 트리를 지정해 실제 Node CLI의 --src 경로를 실행했다. 표준출력의 J9 표본 20행, 조립 2행 및 J10 12행(두 크기×6개 동작)을 파싱해 ID·입력 크기·호출 횟수·중앙값/최대 열과 +1 관계를 확인했다. 0325 I1~I9 입력별 생산 로직, PNG/patch 파일 내보내기(--write-inputs), 도움말·인자 오류 문구는 j1~j7 원문에 대응하는 좌표가 없다. 해당 분기들의 일반 CLI 동작을 J 측정의 추가 통과 건수에 넣지 않았다. 공통 measureCase의 예열 제외·중앙값/최대·함수 부재·예외와 표시 형식은 J도 사용하므로 m3/m4 및 j4/j7에서 직접 확인한다.

같은 revision에 메시지 배열만 다시 로드된 경우와 변경 로그 안의 명시적 reset을 각각 시험했다. 둘 다 과거의 부모 설명·자식·모델을 철회하고, 이전 뷰는 보존한다. J 공용 측정기는 매회 새로운 입력 준비 → 타이머 시작 → run 순서를 검사했다. 예열·준비 시간을 제외하고 임의 값으로 실패한 준비 단계도 N/A(실패)로 보고해야 한다.

추가한 철회·측정 변이 20건은 패널 13건과 측정 7건이다. 각 임시 app 복사본에서 기준 검사가 통과한 뒤 한 식씩 변경하여 모두 실패를 관측했고, 원본 바이트와 다시 일치함을 검증했다.
