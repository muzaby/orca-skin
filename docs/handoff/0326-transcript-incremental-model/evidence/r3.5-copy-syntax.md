# c/v 소스 조건 대조

구현자 r3.5 스캔 파일의 역할 좌표를 보존한다. 같은 식의 부모와 양쪽 항은 각각 한 역할로 센다. 테스트 파일 virtualizerOptions.test.ts는 오라클이며, 대응 제품 구현은 TranscriptViewport.tsx의 getItemKey·estimateSize·measureElement·shouldAdjustScrollPositionOnItemSizeChange다. [실행 치환](r3.5-copy-syntax.jsonl) · [규칙별 오라클](r3.5-copy.md)

| 파일 | 역할 | 기존 delta | 기존 context | 기존 none | 아래 대조 분모 |
|---|---:|---:|---:|---:|---:|
| copy.ts | 39 | 9 | 0 | 30 | 30 |
| range.ts | 20 | 18 | 0 | 2 | 2 |
| TranscriptViewport.tsx | 307 | 78 | 13 | 216 | 229 |

뷰포트의 소스 행 범위는 55–70, 138–198, 248–248, 272–274, 329–345, 372–405, 465–469, 501–521, 525–724, 878–953, 959–978이다. 스크롤 앵커의 포착·위치 보정·reserve gap은 a 계열이다. 아래 표는 기존 스캔의 none/context 역할을 누락 없이 소스 행으로 묶는다. 각 행의 설명과 ID는 해당 역할 중 의미가 있는 분기를 검증하는 방법을 보여준다. 경로의 부모와 자식을 같은 치환이 관측하는 경우 ID가 반복된다.

확인 대상 원래 역할은 366개다. 기존 delta 105개, context 13개, none 248개였으며 아래에 context와 none 261개를 모두 기록했다. 직접 실행한 추가 제거·교환은 62개이며 서로 다른 좌표다. 원문·치환·명령·실패 건수는 JSONL의 ID로 확인할 수 있다.

조사 과정에서 네 후보는 첫 테스트가 통과했다. 첫 조각의 남는 개행(`R35-cut-no-leading-seam`), 이미 제거된 소유 행(`R35-cut-distinct-owner`), 실패한 chunk의 완료 계측(`R35-cut-unmounted-error`), 기본 복사 직전 실제 DOM 오프셋 변화(`R35-cut-dom-lookup`)를 각각 재현해 네 후보 모두 검출했다. 이벤트 시점 스냅샷을 무시한 `R35-cut-copy-snapshot`은 실제 동작 수정의 역치환이다.

**별도 실행이 없는 잔여 조건**은 DOM 없는 SSR에서의 `document`/scroll ref, Chromium에서 `performance`가 없는 시계 fallback, 이미 `rangeCount>0`인데 한쪽 노드만 null인 비정상 Selection 객체, Canvas 등 focus 메서드가 없는 임의 activeElement 조합이다. 설정값 재지정 시의 구독자 알림 횟수와 빈 className 기본값도 c/v 출력 계약에 독립 기대가 없다. 진단용 빌드의 등록 및 오류 주입은 사용자 분기와 구분했다. 261은 검토한 소스 역할 수이고, 검출 수는 실제 실행한 치환 62개다.
