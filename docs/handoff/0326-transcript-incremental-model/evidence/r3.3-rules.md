## VP-16 500열×40단계

Code·Work·OpenCode 각각 500개의 독립된 시드로 40단계를 실행하여 공개 블록열을 전체 재구성과 매 단계 깊은 값 비교했다(총 60,000단계). 작성 후 바로 소비하는 모델과 1~70 revision마다 소비하는 모델이 각자 별도 전체 모델을 가진다. 전체 모델은 각 소비 시 reset을 거쳐 모든 메시지를 재구성하고 D-070 기존 대표 key의 이력을 보유한다. 입력은 역할별 메시지, 도구, 텍스트, Work 경계, 5종 기록, 한 단계 여러 기록 및 기존 id 제거→뒤에 다시 추가를 포함한다. prepend는 실제 reducer의 T 조건을 사용한다.

## OpenCode 중복 호출과 결과

- 같은 도구의 결과를 별도 턴의 앞 메시지·뒷 메시지에 놓고, 뒷 메시지에 결과 part를 두 개 넣었다. 앞 메시지를 나중에 편집해도 뒷 메시지의 마지막 part를 표시하고, part 철회·뒷 메시지 철회·남은 메시지 철회 때 활성 값이 한 단계씩 돌아가는지 증분 모델과 새 모델 각각에 같은 고정 기대값을 적용했다. Read와 AskUserQuestion 둘 다 수정 전에 실패했다. Read는 앞 메시지의 수정이 승리했고, AskUserQuestion은 원래 호출이 다른 턴의 결과를 최초 구성 때 받지 못했다.
- 같은 toolRunId의 Read와 AskUserQuestion을 각각 다른 턴에서 재송출했다. 앞 호출 한 곳에 가장 뒤 입력과 결과를 표시하고, 뒤 호출을 지우면 앞 입력이 복구되며, 다시 재송출한 뒤 앞 호출을 지우면 남은 호출이 동일 결과의 소유자가 된다. 이전 구현은 재송출 철회 후에도 뒤 입력이 남았다. 앞삽입으로 더 이른 호출이 생기면 소유자는 이동하고 가장 늦은 입력과 결과는 유지된다.

- x1~x9·x13 — 250쌍의 독립 세션, 세션마다 40단계(500열·20,000단계). 두 세션은 같은 형태의 메시지 번호와 호출 번호를 사용한다. 각 단계의 즉시 소비와, 별도 lineage에서 난수로 골라 늦게 소비한 시점·마지막 단계의 뷰 9종을 전체 스캔 사본과 비교한다. 무작위 중첩 도구에 Agent·Bash·Read를 포함한다.
- x9 — 중첩 Bash 도구의 부모 A→B 이동에서 OpenCode의 평탄한 process.call과 call.result에 부모 번호가 남아 이전 전체 스캔과 달랐다. 기존 전용 테스트는 중첩 Read만 만들어 잡지 못했다. 새 테스트가 수정 전 실패, 수정 후 통과. process 출력과 revision은 이동 전후 같고 transcriptResults 쪽에는 B가 남는다.
