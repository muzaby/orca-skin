# D4 규칙 구현의 변경 분기 대조

2026-11-20 구현자 조사에서 `5b489f82`와 현재 작업 트리를 비교했다. 조사 시점의 치환 962개는 경로·원문·중복 발생 순번으로 모두 찾았다. 변경 파일 96개 중 22계열 소유 후보 81개에서 AST 후보 4,858개, 중복된 문법 역할을 합친 고유 소스 구간 4,392개를 수집했다. 문법 역할을 기준으로 치환의 실제 변경 범위와 겹치는 문법 역할 701개, 원문 문맥만 겹치는 역할 129개, 불명확한 중복 위치 0개, 원문의 위치와도 겹치지 않는 역할 4,028개다. 마지막 수치는 D4의 실패 건수를 뜻하지 않는다. §10 규칙 268개의 도달 가능한 의미 분기와 AST 표현식 사이에는 일대일 대응이 없다.

## 재실행

저장소 루트에서 다음을 실행한다. 코드·corpus·미추적 구현이 바뀌면 수치와 줄 번호가 달라진다. 두 번째 명령의 출력에 모든 위치, 줄·열, 표현식 종류, 계열, 매칭 ID가 있다. `start/end`는 TypeScript가 계산한 UTF-16 구간이다.

```sh
node docs/handoff/0326-transcript-incremental-model/evidence/r3.3-sweep.mjs
node docs/handoff/0326-transcript-incremental-model/evidence/r3.3-sweep.mjs --rows > /tmp/0326-d4-rows.jsonl
jq -c 'select(.family != [] and .match == "none") | {file,line,col,kind,family,expression}' /tmp/0326-d4-rows.jsonl
```

- 비교 대상은 `git diff --no-renames --unified=0 5b489f82`의 새 쪽 줄과 현재 미추적 구현이다. 전체 `app/src` 및 J 계측 스크립트에서 테스트·픽스처·선언·삭제된 파일을 제외한다. 타입 전용 파일은 AST 후보가 0일 수 있다. SQL, 실제 바이너리/Windows 실행, 변경되지 않은 피호출부와 경로 배선의 함수 호출 자체는 이 조사 밖이다.
- 조건식, switch/case, for/while/do 조건, 함수의 최종 직접 return 이외의 반환, 3항의 조건/양쪽 값, `&&`·`||`·`??`의 전체식과 양쪽 후보, 배열·객체·JSX spread를 수집한다. 예를 들어 `if (A && B) return x`의 조건, 논리식, 두 피연산자, 조기 반환은 서로 다른 역할이다. 부분 hunk와 겹친 복합식에는 기존 조건도 섞인다. 암묵 반환 화살표 자체, 모든 평범한 함수 호출/배열 원소 및 상수는 자동 열거 대상에서 제외했다.
- `delta`는 지정한 파일에서 `old`를 찾아 치환 전후의 공통 접두/접미를 제외한 범위가 후보와 겹친 것이다. 여러 위치를 바꾸는 한 치환은 최소 양끝 구간으로 잡으므로 그 사이의 미변경 부분이 포함될 수 있다. `context`는 원문 위치에 들어가지만 치환의 변경 범위 밖이다. `none`에는 같은 조건을 옆에서 결정한 치환이나 종단 통합 테스트로 이미 검출되는 분기도 들어간다. `occ`는 0 기반, `replace_last`는 마지막 일치로 처리한다. 각 ID가 어떤 단언으로 red였는지는 해당 JSONL을 대조한다.
- 계열 소유는 §10·§7-A를 바탕으로 파일명으로 넓게 설정했다. 공통 store·reducer·Timeline·TranscriptViewport는 여러 행에 걸친다. 따라서 계열 행 합은 고유 전체 수와 다르다. 소유 후보 밖 15개 파일에는 78개의 후보가 남았다. 예를 들어 진단용 선택 범위 생성, dev 시작 및 테마 기본값이 있다. 전체 경로는 요약의 `outside`에서 확인할 수 있다.

## 새로 구분한 D4 분기 두 개

`TranscriptViewport`는 보존한 선택 양 끝을 현재 스냅샷의 인덱스로 다시 변환한다. 행이 사라지면 `selectionBlockIndex`가 −1을 돌려준다. 이 값을 받아들이는 `selectionMountSet`에서 두 끝의 하한 검사는 서로 다른 일을 한다. 한쪽만 사라진 입력과 2행 overscan을 사용해 정상 출력과 구별했다.

| 치환 ID | 기존 연관 2파일에서 새 단언을 뺀 상태 | 새 단언을 추가한 상태 |
| --- | --- | --- |
| R33-sweep-c1-missing-anchor | 원문 대신 치환을 넣어도 copy/viewport selection 30/30 green | 마운트 집합에 존재하지 않는 −1이 들어가 red |
| R33-sweep-c1-missing-focus | 동일 30/30 green | 사라진 focus 주변으로 0과 1이 추가되어 red |

원본 대조는 새 단언 green, 격리 사본에서 각 치환 단독 실행은 1 failed·9 skipped였다. 기존 30개는 이 두 파일에 한정한 생존 대조다. 다른 모든 간접 테스트의 감도를 증명하지 않는다. [치환 원문·테스트 명령](r3.3-sweep.jsonl)

보고된 AST 수를 D4 잔여 결함 수로 환산할 수 없다. rule→소스→도달 입력→치환 실패를 확인한 두 건은 해당 칸의 추가 증거다. 나머지 후보는 규범상 필수 여부, 같은 조건의 상대 항/형제 교환, 원문 바깥에서 이미 판단한 경로를 구별해야 하며 이 표로 전수 완료를 판정하지 않았다.
