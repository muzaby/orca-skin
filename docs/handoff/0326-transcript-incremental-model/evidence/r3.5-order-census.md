# 메시지 순서·part 색인 q1–q7의 구문 대조

기준 파일은 [messageOrder.ts](../../../../app/src/renderer/src/features/chat/lib/transcript/messageOrder.ts)다. 최초 구문 조사에서 조건·피연산자·반환 후보 중 치환 영역과 직접 겹치지 않은 노드는 77개(미일치 75, 문맥 일치 2)이며, 서로 다른 소스 행은 44개다. 아래 첫 열에 44개를 한 번씩 배정했다. 한 행의 조건·반환식이 같은 동작을 나타내면 같은 시험 결과를 가리킨다. 추가 변이 ID에서 공통 접두어 `R35-order-`를 생략했다.

| 소스 행 | 규칙 | 정상 동작과 비동치 후보의 관측값 | 동치·타 규칙 경계 |
|---|---|---|---|
| 27, 31 | q1/q6 | clientId 없는 서로 다른 user가 별도의 renderer ID를 얻고 reset 후 같은 객체는 같은 ID를 쓴다. `user-client`, `fallback-new`. role/client 및 canonical 분기는 기존 R34-block-q 계열. | renderer ID 문자열 생성·escape 규약은 i 계열. |
| 40, 41, 42, 43, 44, 45, 46 | q7 | 동일 provider ID로 tool·response begin·notice가 서로 다른 메시지를 반환한다. response end에는 owner가 없다. `part-call`, `part-response`, `part-notice`, 기존 R33-q7-call/response/notice/begin. | 삼항의 각 결과 문자열은 공개 조회의 네임스페이스와 짝을 이룬다. 동일 문자열을 다른 형식으로 조립하는 것에는 별도 동작이 없다. |
| 48, 184 | q2/q7 | tool은 owner만, result는 merge만, response begin은 둘 다, text는 둘 다 없다. 저장된 실제 세 slot과 owner·merge 공개 결과를 확인했다. `part-empty`, `part-both`, `skip-empty`. | 형제 OR는 둘 중 하나만 가진 part를 잘못 버린다. partMergeKey의 다른 provider별 키 형식은 mergeKey 쪽 소유다. |
| 66, 69, 70, 71 | q3/q6 | 같은 배열·revision 재사용은 parts read 0. 같은 배열의 reset revision은 재구축, 같은 revision의 다른 배열도 재구축한다. 최초 cursor 없는 호출과 로그 보존 창을 넘긴 호출은 현재 전체 배열을 색인한다. `same`, `revision`, `snapshot`, `reset-event`, `no-change`, `reset-window`. | 초기·유실 cursor가 reset sentinel을 만드는 조건은 l 계열 changesSince. q는 sentinel 수신 시 현재 배열로 재구축하는 동작을 담당한다. |
| 76, 77, 80, 84 | q1/q4/q5 | append와 prepend 디스패치를 상호 교환하면 10,000번째 추가의 위치가 달라진다. 삭제 후 재추가에서는 새 순번 및 owner가 필요하다. `append-swap-prepend`, `remove-id`, 기존 R33-q1-rank/q4-prefix/q5-dirty. | replace는 기존 rank를 보존한다. 실제 part 편집은 아래의 fold 경로에서 처리한다. |
| 90, 112, 117, 216, 221 | q2/q3/q6 | 미요청 색인의 초기/추가 read 0, 첫 활성화 때 각 메시지당 read 1, 다시 요청할 때 read 0. 기존 lineage는 같은 order를 쓰고 다른 lineage는 다른 순서를 보유한다. `cold`, `rebuild-cold`, `ensure`, `lineage`, `parts-opt-in`. | WeakMap 대 강한 참조의 수명은 l7의 P33-l7-strong-order. |
| 93, 180 | q2/q7 | 삭제된 ID는 모든 기여를 철회하고 존재하는 메시지만 parts를 읽는다. `remove-choice`, `remove-msg`, 기존 M11-q7. | 정상 Message[]에서 음수 인덱스의 값은 undefined이므로 삼항을 messages[position] 하나로 줄이는 후보는 동치다. 첫 메시지를 고르는 후보는 비동치다. |
| 123, 124 | q5 | 없는 메시지는 -1이고 rank를 쓰지 않는다. 첫 생존 조회만 순번을 다시 쓴다. `unknown`, `delete-dirty`, 기존 R35-q5-reindex-once. | 없는 항목의 lookup과 정렬 여부를 별도로 관측했다. |
| 137, 139 | q7/q4 | 후보가 없으면 owner 없음. 나중에 삽입된 prepend의 메시지가 더 이르면 그 ID를 반환한다. `owner-none`, `earliest`. | next가 undefined면 JS의 next < rank가 이미 false다. 이 피연산자의 명시적 undefined 검사만 제거하면 동치다. |
| 161, 168, 169, 188 | q2/q7 | 없는 slot은 undefined, 기존 기여·키·중복 slot은 유지, 신규 키에는 실제 위치를 등록한다. `missing-slot`, `prior`, `prior-slots`, `merge-set`, `new-matches`, 기존 R33-q2-slots. | 빈 Set은 마지막 요소 삭제 때 해제되므로 공개 조회에서 !slots와 !slots?.size는 동치다. |
| 173, 176, 187, 194, 196 | q2/q7 | merge가 있는 part만 slot을 만들고 철회한다. 마지막 위치를 지운 키, 마지막 기여·slot이 사라진 메시지도 Map에서 제거한다. 살아 있는 다른 메시지는 유지된다. `release-merge`, `install-merge`, `release-set`, `release-prior`, `release-slots`. | 빈 Map 누수는 공개 조회값으로 구별할 수 없어 삭제 후 실제 Map의 키와 크기를 검사했다. |
| 182 | q2/q3 | partsFrom에서 마지막 part까지 처리한다. `last-part`, 기존 R33-q2-suffix/q3-index. | 기록을 접어 partsFrom을 정하는 것은 l 계열 foldChanges. |
| 201, 202, 204, 206 | q2/q7 | owner 없는 키를 저장하지 않는다. 복수 owner와 중복 기여 수를 유지하고 마지막 기여 시 메시지 및 빈 owner Map을 철회한다. `owner-key`, `owner-map`, `owner-count`, `release-owner`, 기존 R33-q2-refcount. | undefined를 키로 저장한 누수도 Map 키 검사로 구별했다. |

원본 회귀 파일의 9개 테스트가 통과했다. 단일 소스 변이 42개는 각각 테스트 기대값 불일치로 검출했다. 명령·치환·종료 관측값은 [실행 자료](r3.5-order-extra.jsonl)에 있다. [기존 q1–q7 규칙별 원장](r3.5-blocks.md)과 [회귀 테스트](../../../../app/src/renderer/src/features/chat/lib/transcript/messageOrder.test.ts)를 함께 사용한다.
