# 0326 r3.5 앞삽입·보류 재생의 추가 분기 대조

§10 g1~g16의 규칙별 판정은 [식별·보류·앞삽입 대조표](r3.5-identity.md)에 있다. 이 추가 실험에서는 변경 줄 AST에서 PREPEND_HISTORY의 페이지 승인부터 최종 확정까지, 그리고 보류를 합치는 mergeHeldParts·finishHeldParts를 읽었다. 이 버전의 공개 진입점은 chatActions.prependHistory이고 대기 이벤트 적용 함수는 mergeHeldParts다.

기준 커밋 5b489f82와의 변경을 2026-11-20에 추출한 목록에는 PREPEND_HISTORY 구간의 문법 행 31개(직접 문자열 겹침 22, 문맥 2, 없음 7), heldParts.ts의 문법 행 69개(직접 32, 문맥 3, 없음 34)가 있었다. 하나의 && 식이 전체·좌·우 세 행으로 나뉠 수 있다. 이 수치는 이번에 비교한 두 파일의 범위를 재구성할 때만 사용한다.

## 입력과 판정

부분 이력에 user 한 행을 둔 뒤 두 경우를 실행했다. 패치만 있는 경우에는 앞 페이지의 assistant와 끝까지 오지 않는 assistant에 도구 결과를 하나씩 보류했다. 출력만 있는 경우에는 앞 페이지의 실제 도구와 끝까지 오지 않는 응답에 publication을 하나씩 보류했다. 두 경우 모두 같은 마지막 페이지에 일부러 slot 0의 기존 결과와 도구 호출을 넣고 reachedStart를 보냈다.

시험은 현재 결과 또는 publication이 올바른 자리에 온 점, 입력 페이지의 parts와 이전 상태의 두 대기 항목이 그대로인 점, 기존 user 객체의 동일성, 앞삽입 기록의 실제 ID, 최종 complete와 빈 보류 맵, 고아 진단 1건을 각각 단언한다. 별도 기존 시험은 publication의 중복 범위를 소유자 앞·뒤 인접 assistant 및 user 너머로 나눈다. 기존 g2/g9/g10/g14의 페이지 유효성 341입력, g4/g5의 이음부 역할 네 조합, g7/g8/g15/g16의 페이지 먼저·이벤트 먼저, g12/g13의 빈/중복 끝 표식은 원래의 g 대조표에서 추적한다. 이번 보충은 두 파일의 여덟 치환을 뽑은 것이다. Map 조회의 null 병합과 객체 펼침을 포함한 100개 문법 행 각각의 모든 가능한 치환이나, 임의의 여러 비동기 페이지 순서에 대한 전수 결과는 남기지 않았다.

현 구현은 message.reasoning, message.completed, tool.call.started, session.compacted, subagent.task에도 명시 owner 표식을 전달한다. 따라서 키 없는 reasoning A/B도 실제 보류·페이지·재생 경로에서 별도 part로 이어진다. 이 변경을 반영한 100개 문법 역할의 상세 판정은 [앞삽입·재생 변경 분기 전체 대조](r3.5-prepend-ast.md)에 있다.
