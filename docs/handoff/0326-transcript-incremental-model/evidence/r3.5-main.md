k1은 같은 이벤트 객체의 키를 재사용하지 않도록 복제한 입력을 쓴다. 각 8종이 새 턴의 첫 이벤트일 때와 그 뒤에 8종이 오는 경우를 피어 통지에서 관찰한다. message.completed만 번호를 처음 만들 수 있게 하면 기존 순서에서는 통과했고, 여덟 시작점을 모두 실행하면 실패했다.
질문 답의 기존 상태를 곧바로 사용하는 fast path를 빼도 모든 정상 관측은 같다(R35-sender-ask-fresh-state). stateOf는 같은 WeakMap에서 같은 turn을 조회해 그대로 반환하며, 기존 상태가 없을 때만 turn.begin을 보낸다. 두 경로에서 실제 turnKey와 시작·중계·피어 통지 순서를 검사했다.

k4/k25의 큐 배출 중 send에서 재진입하는 경우에는 pending이 0이어도 아직 줄에 있는 이벤트가 먼저다. 반대로 실패 상태에서 확인을 기다리는 동안 들어온 relay는 나중에 피어가 응답해도 화면에 도달하지 않는다. 두 상태를 분리해 최종 화면의 이벤트 배열과 순서를 비교했다.
