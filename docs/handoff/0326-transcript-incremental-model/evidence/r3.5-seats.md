## 원본 통제와 새 치환

생성기 원본 테스트 3개 파일 48개와 SQLite queries 원본 테스트 33개가 통과했다. Claude Code 결합 text/독립 reasoning의 실제 key 배열과 같은 세션에 있는 다른 messageKey의 role·없는 조합을 직접 단언하도록 보완했다. 8개 치환은 서로 다른 임시 복사에서 각각 assertion 실패를 관측했다. 비정상 종료나 단순 소스 문자열 출현을 실패로 세지 않았다.

```sh
cd app
./node_modules/.bin/vitest run --maxWorkers=1 claudeCodePartKeys.test.ts claudeBlocks.test.ts openCodeBlocks.test.ts src/main/infra/db/queries.test.ts workActivity.test.ts
```

EP-10의 두 제어기는 정책에 따라 공통 writeScrollTop을 호출한다. 두 제어기의 production 파일에는 scrollTop 대입이나 element.scrollTo 호출이 없다. 이 표는 정책별 선택과 공통 쓰기로의 전달을 대조한다. EP-15의 카드와 Work는 세션 삭제를 구독하는 별도 정리기를 갖지 않는다. 해제 시 세션 키별 store 삭제, complete reset 후 보존된 key 집합으로의 정리는 EP-15 ⑥의 실행과 공유한다.

EP-4 ③의 일곱 개 이벤트는 기존 S04-3의 일곱 실제 실행에 각각 대응한다. 반복 인용 자체는 누락 건수에 넣지 않았으며 각 자리의 입력과 결과가 다른 경우에만 위 표에 별도 실행을 붙였다.

병행 변경을 합친 생성기·SQLite·Work·writer 원본 통제도 6개 파일 138/138 통과했다.
