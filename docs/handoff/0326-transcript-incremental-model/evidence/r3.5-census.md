# ⑦ 구현자 후보 분류와 값 비교 재검색

`r3.3-sweep.mjs`는 `5b489f82` 이후 변경·추가된 제품 파일과 측정 스크립트를 모으고, 변경 hunk와 겹치는 TypeScript 구문을 가족별로 열거한다. 각 JSONL 치환은 원문과 교체문의 공통 접두·접미를 제외한 구간을 계산한다. `delta`는 실제로 바뀌는 글자와 구문 범위가 겹치고, `context`는 원문 좌표의 주변만 겹친다. `none`은 양쪽에 겹치는 등록 좌표가 없다는 뜻이다. 논리식 전체와 좌·우 항, 중첩 구문 등은 서로 겹칠 수 있다. 기존 파일의 변경 hunk 밖, 삭제된 구문, 해당 AST 열거기가 수집하지 않는 API 호출은 별도 경로·규칙 대조가 필요하다. 166자리·268규칙·39경로의 검사는 각 원문 행과 실제 oracle을 연결해 확인한다.

이 대조 시점의 진단 결과는 변경 파일 97개 모두에 가족을 배정했다. 등록 좌표 1,379개가 모두 선택됐고 AST 역할은 delta 1,101개, context 192개, none 3,980개였다. 평행 작업에서 추가되는 뒤의 치환은 같은 명령으로 다시 계산할 수 있다.

## x10 값 동등성과 패널 입력

구현 수정 전, 같은 도구 호출의 structuredOutput이 Map에서 빈 객체로 바뀌면 결과 패널 hook이 이전 Map을 반환했다. Map의 열거 가능한 레코드 키가 비어 있어 일반 레코드 비교까지 진행한 것이 원인이었다. 수정 후 왼쪽 Map은 오른쪽도 Map인지 검사한다. 실제 `useTranscriptView('transcriptResults')`의 참조 재사용과 값 갱신, 장착한 `CanonicalBackgroundContent`가 `BackgroundTaskCard`에 전달한 구조화된 결과까지 검사한다. 현재 전송 타입의 structuredOutput은 unknown이다. 이 입력은 렌더러 저장소에서 주입했으며 SDK가 실서비스에서 Map을 전송하는 빈도는 이 검사의 측정 대상 밖이다.

| 구분 | 직접 기대값과 형제 | 실행 ID (접두어 R35-x10-eq-) |
|---|---|---|
| 동일 참조·원시값·null | NaN, 부호가 다른 0, 객체↔수, null↔객체 양방향, 서로 다른 두 문자열 | identity, signed, type, null-left, null-right, primitive |
| 배열 | 배열↔레코드 및 배열처럼 길이 0인 레코드, 길이 변화, 길이가 같고 순서만 바뀐 배열, 같은 중첩 배열 | array-kind, array-size, array-cells, array-success |
| Map | Map↔빈 객체, 빈 Map↔한 항, 크기는 같고 undefined 값의 키만 다른 Map, 동일 키의 상이한 값, 키와 값의 lookup 교환, 순서만 다른 동일 Map | map-kind, map-size, map-presence, map-lookup, map-key-value, map-success |

## 기존 7개 green 재검토

선행 빈 줄을 비공백 줄 뒤의 빈 줄로 잘못 기록하면 최종 Markdown은 같아도 공개 스캐너 캐시 필드가 바뀐다. 캐시의 false → false → true 순서를 직접 확인하는 검사를 추가하자 R35-stream-f8-appended-blank가 실패했다. 남은 여섯 조건의 입력 불변식과 관측 범위는 [스트림 대조표](r3.5-stream.md)에 있다. 탭 없는 본문에서 정규식 탐색을 추가한 경우에는 결과 문자·오프셋이 같으며 실행 시간은 동등성 판정에 포함하지 않았다.
