# Part I — 제품과 사용자 동작

## 1. 목표

긴 대화를 열었을 때 첫 화면 비용은 표시할 턴의 첫 묶음에 비례해야 한다. 같은 최신 턴 앞에 이력만 더 쌓아도 data 호스트의 본문 읽기, 포트 전송, 창의 검증·변환량이 증가하지 않아야 한다.

### 같은 대화에서 사용자가 보게 될 변화

예시는 Claude Work이며, 저장된 대화가 ‘최근 대화’에 보이고 현재 다른 대화가 열린 상태를 가정한다. 예시 대화에는 100턴이 있다. 63턴에는 검색어 “센서 A”가 있고, 100턴은 두 줄짜리 마지막 답변이다.

17턴에서 Claude가 실제 작업 도구 `TaskCreate`로 **테스트 수정**을 등록해 작업 ID 7을 받았다. 41턴에는 `TaskUpdate`가 같은 작업의 완료를 성공으로 돌려줬다. 현재 작업 목록은 이런 도구 호출과 짝이 맞는 구조화된 결과를 읽어 상태를 만들며, 대화에 ‘테스트 수정’이라는 문장만 쓴 경우에는 항목을 만들지 않는다. [작업 목록 계산](../../../app/src/renderer/src/features/chat/lib/transcriptIndex.ts#L665)

| 사용자가 하는 일 | 현재(AS-IS) | 계획(TO-BE) |
|---|---|---|
| 왼쪽 **최근 대화**에서 이 대화의 제목을 누른다 | 캐시가 없으면 data가 저장 이력 전체를 조립하고 창이 모든 조각을 받은 뒤 본문을 표시한다. 캐시가 있으면 기존 본문을 먼저 보여 주고 재검증한다. | 100턴 두 줄이 준비되면 메타·본문을 한꺼번에 표시하고 하단에 둔다. 위로 한 번 당기면 머리에 스피너가 나오고 99턴만 앞에 붙는다. 휠을 놓으면 98턴 요청도 멈춘다. |
| 대화를 연 뒤 Work 우측 **작업 → 진행 상황**에서 어제 끝낸 일을 확인한다 | 전체 이력에 작업 생성·완료 기록이 있으면 “테스트 수정”이 완료 상태로 보인다. | 새 로딩 방식에서는 최신 턴만 가져온 상태에서도 같은 완료 항목을 볼 수 있다. 17턴을 손으로 찾아 열 필요가 없다. 작업이 많은 세션에서는 목록을 나눠 보내더라도 모든 현재 항목에 접근할 수 있어야 한다. |
| 상단 **검색**에서 “센서 A”를 입력하고 결과를 누른다 | 현재는 해당 세션이 열리고, 사용자가 63턴의 메시지를 다시 찾아야 한다. | 해당 메시지가 화면에 들어오고 행이 잠시 강조된다. 선택한 메시지 주변을 읽다가 “최신 대화로”를 눌러 100턴으로 돌아간다. |
| 99턴을 읽다가 네트워크/호스트가 끊기거나 다른 대화로 간다 | 진행 중 세션의 live 상태와 전환 보호가 있다. 전체 로드 방식에는 “같은 이전 턴만 다시 요청”하는 화면이 없다. | 오류가 난 머리에서 같은 99턴을 재시도한다. 다른 대화로 간 뒤 도착한 응답은 그 대화에 섞이지 않는다. 원본 보관 기한 만료 후 다시 전송하면 실행 호스트는 1~100턴의 복구 자료를 쓰므로 창에 100턴만 열어 둬도 시작·중간 문맥을 보존한다. |

### 5-B. 큰 한 턴을 열 때 — D-009 = 유휴 자동 채움(사용자 결정)

**언제 생기나.** Claude Code에 “리팩터링 끝까지 진행해줘”를 맡겨 에이전트가 두 시간 동안 파일 읽기·수정·테스트를 300번 반복하면 그 한 턴은 메시지 약 600개·part 약 900개다. 한 응답 한도(메시지 128·part 256·256 KiB, §14)를 넘는다. 4 MiB 로그가 든 메시지 하나는 이 경우가 아니라 ‘본문 열기’(§10 본문)다.

| 사용자가 하는 일 | 버튼안(PR 권고) | 유휴 자동 채움안 |
|---|---|---|
| 대화를 연다 | 두 안 공통: 그 턴의 끝(최종 답변과 마지막 도구 호출 묶음)이 하단에 보인다. 내가 처음 보낸 요청은 아직 위에 없다. | 같음. 첫 본문이 보인 뒤 같은 턴의 나머지를 유휴 구간마다 한 묶음씩 조용히 붙인다. |
| 위로 올라간다 | 머리의 ‘이 턴의 앞부분 더 보기’ 또는 상단 위 입력 한 번에 같은 턴의 앞 묶음 하나. 턴 시작(내 요청)까지 여러 번 당긴다. 그 뒤 위 입력부터 이전 턴. | 대개 이미 붙어 있다. 붙는 동안 스크롤바 길이가 바뀌지만 읽던 글줄은 유지한다. 이전 턴은 위 입력으로만 읽는다. |
| 위를 보지 않고 다른 대화로 간다 | 추가로 읽은 것 0. | 그때까지 읽은 묶음 수만큼 data 읽기·전송이 이미 일어났다. 전환·취소에서 멈추고, 직접 스크롤 중에는 붙이지 않는다. |

사용자는 오른쪽 열(유휴 자동 채움)을 골랐다(D-009). 같은 규칙은 위 입력으로 읽은 이전 턴이나 검색 대상 턴이 큰 경우에도 그 턴 안에서만 적용한다(§10 한 턴과 조각).

### 상단 검색의 현재 배선과 rev 4에서 추가할 경로

검색 결과와 B의 가상 뷰포트가 서로 다른 키를 사용한다. D-013은 data의 위치 해소 → E의 대상 주변 조회 → 가시 행 강조를 연결한다.

| 단계 | 현재 동작 | rev 4 채택 경로 |
|---|---|---|
| 1. 결과 찾기 | 로컬·native SQLite FTS5, 검색 입력 debounce 150ms·최대 결과 30. `SearchHit`은 `sessionId, messageId, role, createdAt, snippet` 등을 담는다. 24토큰 발췌에는 `<mark>`가 있고 본문 좌표는 없다. | 결과 생성 시 세션과 안정 메시지 키 또는 출처 식별자·투영 세대를 함께 보관한다. 클릭한 결과 하나에만 위치 해소·주변 조회를 요청한다. |

| 5. 복귀·앞뒤 이동 | 현행 검색 클릭은 일반 세션 진입이다. | 검색 위치는 최신 연속 이력과 창의 별도 읽기 상태로 유지한다. 앞·뒤 이동은 명시 요청에 한 묶음씩, “최신 대화로”는 기존 현재 턴/live 상태로 돌아간다. 뒤로/앞으로 탐색에 저장하는 것은 세션·메시지·앵커이며 재진입 때 세대를 확인한다. |

검색에 잡히는 텍스트와 표시 본문은 다를 수 있다. native 검색은 부모 없는 text, 복구 검색은 연결한 text를 사용한다. D-013의 단위는 **메시지 행**이다. FTS 접두어·반복 구절·Markdown의 정확한 부분문자열 좌표는 구현 범위에 포함하지 않는다.

**외부 설계 사례.** Matrix의 메시지 검색은 한 결과와 함께 돌려줄 전후 이벤트 수를 `event_context.before_limit`·`after_limit`로 선택한다. Orca에도 결과 식별 후 제한된 문맥만 가져오는 구조를 적용할 수 있다. [Matrix Client-Server API v1.14 · Search](https://github.com/matrix-org/matrix-spec/blob/v1.14/data/api/client-server/search.yaml#L97-L118)

### 상단 검색 결과 선택 비용 · 로컬 SQLite 실험

한 대화의 중간 메시지에만 있는 단어를 찾아, 검색 결과를 클릭한 **뒤**의 두 데이터 경로를 비교했다. 전량 경로는 앱의 `loadSession`으로 대화 전체를 조립해 이미 아는 표시 키를 찾는다. 색인 경로는 실험용 `(세션, 세대, 검색 행) → (표시 키, 턴)` 표로 같은 턴의 메시지를 읽고 앱의 `localMessages`로 조립한다. 두 경로가 반환한 대상 키와 대상 턴의 내용이 같은지 단언한다.

|---:|---:|---:|---:|---:|
| 1,000 | 4.657 / 7.283 | 0.015 / 0.043 | 178,505 → 358 | 4.5 ms / 73,728 B |
| 10,000 | 48.945 / 100.275 | 0.016 / 0.051 | 1,815,006 → 364 | 55.9 ms / 671,744 B |
| 100,000 | 555.350 / 1,153.493 | 0.014 / 0.022 | 18,450,007 → 370 | 613.3 ms / 7,176,192 B |

- **조건.** Linux x64 Xeon Platinum 8573C, Electron 내 Node 22.22.1, SQLite 3.53.2. 실제 앱 마이그레이션을 적용한 임시 DB에 짧은 text part가 하나인 user·assistant 메시지 두 개씩 한 턴으로 넣었다. 같은 대상·준비된 DB에서 각 쿼리를 한 번 예열한 뒤 전량 11회·색인 501회 측정했다. 바이트는 메시지 배열을 JSON으로 표현한 크기다.
- **독립 재실행.** 같은 명령을 새 임시 DB에서 다시 실행해 3개 크기의 행 수·응답 바이트·증가한 DB 바이트와 식별자 5건이 모두 같음을 확인했다. 10만 건의 두 번째 중앙값은 전체 435.704 ms, 해당 턴 0.015 ms였고 최초 구축은 330.5 ms였다.
- **검색 목록 생성 비용.** 기존 FTS5로 10만 메시지 중 하나에만 맞는 단어는 중앙 0.195 ms(101회), 거의 모든 행에 맞는 단어는 80.064 ms(9회)였다. 위치표는 검색 결과를 선택한 뒤 쓰며, 기존 검색의 순위 계산 시간은 별도로 남는다.
- **적용 범위.** 시간·공간 수치는 로컬 이력의 DB 읽기·JS 조립까지다. Windows의 클릭→페인트 시간, IPC 비용, 복잡한 native/복구 이력의 색인 구축 시간은 별도 측정 대상이다. E의 공통 색인이 같은 키와 턴 위치를 제공하면 표의 구축량을 검색만의 비용으로 다시 더하지 않는다.
- **식별자 확인.** 로컬·원본·복구의 서로 다른 다섯 표본에서 실제 검색 행과 현재 앱에서 열리는 메시지 키를 대조했다. 예컨대 로컬 행 `+2`의 키는 `m:2`, 원본 행 `−1`의 키는 로컬 소유 키 `u:request-a`, 복구 행 `−4`의 키는 `x:1`이었다. 이 대조는 원본·복구에 대한 직접 이동의 전 구간 성능 측정과 구분한다.
- **재현.** 앱 의존성이 설치된 저장소 루트에서 `node docs/handoff/0329-turn-history-paging/evidence/search-jump-cost.cjs`를 실행한다. 합성 자료만 담은 임시 DB를 만들고 종료할 때 제거한다. [측정 코드](evidence/search-jump-cost.cjs)

**겹치는 후보.** 0327 완료 text 파싱과 0326 B28 승인 요청은 페이지의 상태 입력으로만 쓴다. 검색·복구 원본·뷰포트에서 이 후보의 파서/승인 교정 동작을 변경하지 않는다.

## 10. 계약·타입·강제 지점

**페이지 wire 형상.** `shared/ipc.ts`에 `latest`·`earlierTurn`·`laterTurn`·`withinTurn{direction:'before'|'after'}`·본문 범위·검색 위치(`target`)·세션 패널 요약(`panelSummary`·`panelDetail`) 조회 판별합을 둔다. data 소유의 요청·응답 입력 검증·IPC 타입·창 transport를 함께 갱신하며 전체 복구 호출은 유지한다. D-009(유휴 자동 채움)는 같은 턴 잔여를 **언제** 요청하는지만 정하고 요청 모양은 `withinTurn`과 같다.

| 계약 | 규칙 |
|---|---|
| 요청 / 응답 | 세션 키·창별 요청 id·창 열기 세대는 모든 응답에서 echo. 논리 커서는 `{v,session,projectionGeneration,kind,absoluteOrder/tieBreak}`를 data가 발급한 불투명 값이다. `ok`·`missing`·`stale`·`invalid`·`unavailable`·`cancelled`로 나눈다(rev 4의 `indexing` 응답은 쓰지 않는다 — 미출판 세션은 아래 ‘미색인 세션 열기’대로 요청을 보류한 뒤 `ok`). 세션/세대/종류 혼용·과대 입력은 data에서 거부하고 창도 일치 여부를 검사한다. |
| 결정적 경계 | 정렬 키는 투영 내 절대 순번+안정 식별자. 시각·상대 배열 인덱스·SQL OFFSET을 커서로 쓰지 않는다. 마지막 turn의 직전 role/lookahead는 본문 없이 읽는다. `earlierTurn`은 이전 턴 하나, `laterTurn`은 다음 턴 하나에 한정(각각 그 턴이 크면 가까운 쪽 끝 묶음 + `moreInTurn`). `withinTurn`은 커서가 가리키는 논리 턴의 지정 방향 잔여만 반환. 형제 세션·다른 턴·다른 세대의 참조는 무효. |
| 한 턴과 조각 (D-009) | 가장자리 턴이 크면 보일 쪽 끝 묶음과 `moreInTurn{direction,cursor}`을 준다(최신·이전 턴은 끝, 다음 턴은 처음, 검색 대상은 대상을 포함한 묶음). 창은 첫 본문 commit 뒤 유휴 콜백(`requestIdleCallback`)마다 그 턴 잔여 1묶음을 요청한다 — 같은 세션·같은 보기가 활성, 직전 유휴 요청 완료, 오류 없음, 사용자 입력 중 아님(아래 제스처 경계)일 때만. 잔여가 끝나면 멈추고 이전·다음 턴 커서로 넘어가지 않는다. 잔여가 남은 동안 그 방향 끝 입력은 같은 턴 다음 묶음을 읽는다. 세션 전환·보기 닫기·취소에서 예약을 지운다. 한 응답을 완전히 검사한 뒤 한 번만 적용. non-T 앞삽입은 B의 `reset{complete:false}`·안정 선택/앵커를 지킨다. |
| 본문 | 큰 메시지의 ID·role·createdAt 및 최소 소유 메타와 `BodyRef`를 보낸다. ref는 세션·세대·메시지/part 키·kind·원문 바이트 길이에 결합. 지연 표시는 창의 명시적 상태로 보존한다. 저장된 빈 parts나 빈 문자열과 구분. 주문한 조각만 읽고 UTF-8 경계에서 복원하며 종료·오류·취소 시 부분 자료를 완성본으로 승격하지 않는다. |
| B의 끝 표식·응답 합류 | latest는 0326 합의대로 `complete:false`로 LOAD. 앞쪽 누락이 실제로 없으면 같은 store 공개 묶음 안에서 `prependHistory([], {reachedStart:true})`로 끝 처리. 이전 턴·같은 턴의 나머지 양쪽이 없는 최종 응답에서만 `reachedStart:true`. BodyRef가 가린 도구 소유는 data에서 안정 소유 키로 복원 가능해야 하며 유효한 보류를 고아로 버릴 수 없다. |
| 빈 결과·겹침·오류 | 0326의 순서 검사 뒤 적용/정당한 중복/거부를 액션 결과로 구분한다. 거부는 커서·끝 갱신 0, 재조회는 사용자 재시도 1회/동작. 순서가 맞는 전부 중복이나 빈 마지막 페이지는 끝 표식을 적용한다. |
| 검색 locator | FTS 결과가 만들어질 때 data가 `{v, sessionId, sourceGeneration, sourceIdentity, projectedKeyAtSearch}`에 해당하는 불투명 locator를 발급한다. local 저장키/원본 alias/보관세대+절대순번은 출처별로 검증한다. 숫자 rowid·snippet·시각 단독 매칭은 허용하지 않는다. |
| target 요청·응답 | `target(locator, navigationId, cachedTarget?: { generation, messageKey })`은 출처·세션 가시성·현재 투영 세대를 한 읽기 트랜잭션에서 검사한다. 같은 출처를 추적할 수 있으면 재해소 1회. 창이 보낸 후보 한 건과 정본 키·세대가 모두 맞을 때만 `useCached`, 나머지 성공은 정본 키·세대·turn key와 목표를 포함한 `context`를 준다. 실패는 stale/missing/invalid/unavailable/cancelled. |
| 캐시와 문맥 | 창은 실제로 보유한 세대/메시지 키를 함께 보내고 data의 확인 뒤에만 재사용한다. 완전 이력·부분 캐시 모두 이 조건 적용. 없는 키는 같은 탐색의 제한 조회 한 번으로 받아 표시하며 cold open에서 전체·최신 턴을 먼저 요구하지 않는다. 재접속 및 live 쓰기는 별도 세션 엔트리에 유지한다. |
| 표시되는 지점 | 우측 패널 확장으로 ChatTile이 inert이면 사용자의 명시적 검색 선택 시 채팅을 볼 수 있게 전환한다. 묶인 Work 활동·접힌 긴 발화는 대상 소유 ID를 가진 표시 행까지 최소한으로 드러내고 같은 텍스트를 가진 형제는 강조하지 않는다. 지연 본문은 해당 소유 ID의 대표 행을 사용하며 본문 인출·임의 접힘 해제는 불필요하다. |
| 행 강조 수명 | 행이 마운트되고 실제 가시영역과 겹치며 숨김·inert가 아닌 첫 프레임을 t=0으로 한다. 색상 외에 대비되는 윤곽으로 행을 2,000ms 식별한다(감소된 모션에서는 정적 윤곽). 시각 변화를 읽을 수 없는 사용자를 위해 화면 읽기 도구에 이동 완료를 한 번 알린다. Enter로 선택한 직후 포커스가 검색 탐색에 있고 사용자가 옮기지 않은 경우에만 행에 `focus({preventScroll:true})`. 마우스는 강제 포커스 0, 기존 텍스트 선택 보존. |
| 사용자 제어·실패 | 새 선택/화면 전환/언마운트/최신 복귀는 이전 번호의 timer·pending request·스크롤을 취소한다. 사용자가 먼저 스크롤하거나 다른 곳을 선택·포커스하면 늦은 완료가 화면을 가져가지 않는다. 강조·만료 시각은 메모리 전용. 위치 소실은 중단 없는 상태 안내와 재검색을 제공하고, 존재·접근 확인된 대화에만 최신 열기를 제공한다. |

## 11. 구현 설계

1. 기존 `isTurnStart(previous,current)`를 shared의 순수 함수로 옮겨 SQL용 턴 시작 색인을 만드는 writer와 B의 reducer가 같은 정의를 부른다. 시작 없음·선두 assistant·assistant→user·user→user·assistant→assistant 입력을 같은 표로 시험한다.
2. 원본 테이블은 보존하고 append-only migration으로 `(session, generation, order)` 투영, `(session,generation,turn,order)`와 메시지 키·source alias·소유 조회 색인, 길이와 바이트 오프셋을 가진 제한 크기 본문 조각, 활성 세대 포인터를 둔다. 고정 정렬은 복구 보관 → native 투영 → orphan → frontier 이후 local 순. 빈 parts 메시지도 헤더에 한 행을 가진다. archive ID는 저장 번호 또는 archive의 절대 위치에서 유도한 B의 `x:` 번호를 사용한다.
3. 신규 local append/같은 번호 갱신/part upsert·native binding·복구/분기 복제의 source 변경과 영향받은 읽기 키를 같은 DB 트랜잭션에 쓴다. 단순 tail append는 앞 커서 순서를 보존한다. 기존 본문 재배치·native replace·source 교체는 새 투영 세대에 기록하고 검증 완료 때 포인터만 한 번 바꾼다. 재구성 중인 세대에 발생한 쓰기는 변경 로그로 재적용하고 원본 revision이 여전히 맞을 때만 출판한다.
4. 구 DB 변환은 data의 전용 색인 작업으로 처리한다(D-018 · §10 미색인 세션 열기 · EP9). 업그레이드 뒤 세션을 최근 활동 순으로 `INDEX_SLICE_MS` 조각마다 양보하며 색인하고, 열기·검색 요청이 온 미출판 세션은 맨 앞으로 올려 그 요청을 출판까지 보류한다. 진행 위치를 저장해 재기동 뒤 잇고 원본 revision 변경 시 그 세션을 다시 하며 세션 삭제 시 취소한다. 구버전 전체 reader는 원본 해석 입력으로만 쓰고 화면 응답 fallback으로 호출하지 않는다. 미출판 세션 첫 클릭은 AC11로 따로 보고한다.
5. 호스트 handler는 현재 출판된 세대에서 한 read transaction으로 세션 가시성, 턴 경계, 메시지·part 헤더와 실제 읽을 본문 범위만 읽는다. 최대 한도+1개 메타로 계속 여부를 판정하며 이전 이력 payload를 미리 열지 않는다. 전체 합계가 필요한 사용자 메타(비용·인계용 user 수)는 갱신 시 계산한 집계나 인덱스 질의를 써서 클릭당 전체 원장을 훑지 않는다.
6. 최신·이전·같은 턴 나머지·본문을 창의 상태별 요청으로 등록해 성공 때만 커서·메시지를 한꺼번에 반영한다. 거대 본문을 원 ID의 명시적인 지연 표시 모델로 연결한다. 메타에 다 담기 어려운 결과·산출물 소유는 세션·세대를 확인하고 B의 병합 키로 해소한 뒤 끝을 처리한다.
7. 0326의 `prependHistory`가 이미 쓰는 diagnostic에 적용 결과를 전달할 수 있는 얇은 반환을 더한다. 기존 호출자·fixture는 종전 행동을 유지하고 `prependRejected`에서는 커서를 진행하지 않는다. `isCurrent`의 첫 LOAD 보호와 이전 턴 조회의 live 교차 허용은 다른 상태로 둔다.
8. 세션 패널 요약 4종을 투영과 같은 출판 경계에서 갱신한다(D-010·D-012). 작업은 호출과 결과를 toolRunId로 짝지어 `shared/task-tool.ts:readTaskToolObservation`의 created/upserted/removed/snapshot 규칙으로 접는다. 서브에이전트·OpenCode 에이전트/프로세스·컨텍스트 소스는 지금 창의 `transcriptIndex` 파생(`subagentTasks`·`openCodePanelModel`·`taskContextSources`)과 같은 규칙을 순수 모듈로 옮겨 data와 창이 함께 부른다(§11 1의 `isTurnStart` 이전과 같은 방식). 요약마다 기준점(출판 순번)·원본 revision을 기록하고 부분 본문 재조회가 요약을 거꾸로 덮지 않도록 세대와 처리 순서를 비교한다.
9. 기존 저장본은 색인 작업이 투영과 함께 요약 4종을 재생한다. source 세대 변경 때 각 목록의 추가·삭제/스냅샷을 포함해 한 번에 교체한다. 응답은 종류별 keyset 페이지·전체 개수·끝 표식을 분리하고, 창은 `panelDetail`로 요청한 항목의 상세만 받는다. 창 표시 = 요약 상태 + 기준점 이후 창 메시지 fold. 준비·실패·재시도·끝을 구분해 부분 값을 ‘작업 없음’으로 표시하지 않는다.
10. WU-1의 세션 투영·턴 범위·출처 식별자가 준비된 뒤 FTS 결과에 locator를 싣고 결과 한 건 선택에 `target` 조회를 연결한다. 대상 메시지가 거대 턴 가운데이면 그 메시지가 반드시 포함되는 묶음을 만들고 앞·뒤에 읽을 것이 있는지 별도로 알려 준다. 최신 세대의 캐시에 있으면 검증과 재사용만 수행한다.
11. `SearchModal.goto → OverlayLayer → route intent → chatStore → TranscriptViewport`로 검색 선택을 전달한다. 클릭과 Enter가 같은 `goto(hit)`로 locator를 넘긴다. 일반 URL·활성 세션 비교와 별개로 탐색 번호를 소비해 동일 세션 재선택도 처리한다. 현재 가시 행·세션·탐색 번호가 일치한 경우만 강조하고, timer 만료·언마운트 때 표지와 listener를 정리한다.
12. chatStore에 세션별 `searchView`를 두고(§10 검색 보기) 방향별 flight·오류·커서를 둔다. `earlierTurn`·`laterTurn`·`withinTurn` 응답은 검색 보기 앞·뒤에만 붙이고, `reachedLatest`는 `prependHistory` 결과(§11 7의 반환)로 합류를 판정한다. 공통 뷰포트에 하단 슬롯과 아래 입력을 더하되 머리와 같은 상태 표시 모듈을 쓴다.
13. 제스처 경계와 유휴 채움 예약은 React 밖 순수 모듈(`lib/transcript/historyGesture.ts`)에 두고 뷰포트가 wheel·키·버튼·commit·전환 이벤트를 넣는다(Q4 UT 진입점). 요청은 store 액션 하나로만 나간다. ΔV1: 당김 표시·스피너는 고정 높이 머리 슬롯 안에서 바뀌어 보정 자체가 필요 없고, 같은 분류기가 앵커 보정 취소 여부도 정한다(§20 D — rev 5의 “`:597` 복원 재사용” 문장 대체).
14. 컴포저는 바꾸지 않는다. Q5b가 E의 응답 적용 경로와 0328 송신 경로의 비접촉을 잠근다(D-017).

## 13. 수명주기·오류·정리

| 전이 | 처리 |
|---|---|
| `idle → loading(key,generation,cursor) → applied/end` | 같은 (세션,세대,종류,커서)는 단일 flight. A에 오래된 응답을 수신한 시점에 A가 다시 활성이어도 세대가 다르면 무시. 항목별 busy·자료·오류를 일치시키고 finally에서도 같은 요청만 정리. |
| `loading → retryable / stale / cancelled` | retryable은 같은 커서를 보존한다. stale은 동일 stable anchor 기준으로 새 세대에 재위치해 최신 범위와 동등성 확인 후 한 번 교체한다. 앵커가 삭제되었으면 인접 존속 위치와 갱신 사실을 표시. 재위치 실패는 기존 일관된 화면 유지. |
| `open / resume / sync` | §5의 세 진입 원인을 유지한다. 늦은 refresh라면 unpin 독자의 거리·선택을 보존하며, 읽던 메시지의 stable anchor로 새 세대를 조회한 뒤 원자 교체한다. busy 캐시·더 새로운 live가 이긴다. |
| `search → resolving → mounted/visible → highlighted → reading → (before/after loading)* → joined \| latest` | 같은 세션 재클릭도 새 번호를 사용한다. 대상이 보이기 전에는 표시/타이머 0. 2초 뒤에는 위치와 포커스를 그대로 두고 윤곽만 없앤다. 새 클릭·뒤로·직접 입력은 이전 번호를 취소하며 이미 보던 live 세션 상태는 계속 갱신한다. before/after는 방향별 단일 flight이고 `reachedLatest` 적용 시 `joined`, ‘최신 대화로’는 `latest`로 끝나 검색 보기를 지운다. |
| `committed → idleWait → filling → committed …` (D-009) | 첫 본문 commit 뒤 유휴 콜백 1회마다 같은 턴 잔여 1묶음. 사용자 입력 중이면 `idleWait`에 머문다. 오류는 `retryable`로 머리에 남기고 자동 재시도 0. 잔여 끝·전환·닫기·취소에서 `idle`. |
| `unindexed → queued → building(slice)* → published` (D-018) | 열기 요청이 오면 `queued` 맨 앞. 재기동은 `building`의 저장 위치에서 잇는다. 원본 revision 변경은 그 세션 `queued`로 되돌린다. 출판 전 보류 요청은 창 취소(`cancelLoad`)만 받아들이고 색인은 계속한다. |
| 검색 위치가 사라짐 | 최초 locator의 세션·출처만 같은 투영에서 한 번 다시 찾는다. 실패 시 이전의 일관된 화면·선택을 유지하고 상태만 알린다. 다른 키나 동일 발췌문으로 대체하지 않는다. |
| 이력 삭제·호스트 끊김·취소 | generation 폐기, 포트 pending·body 청크·중복 억제 키·스피너 해제. 다른 세션의 flight는 유지한다. 삭제 후 같은 세션 ID가 나타나도 오래된 bodyRef/커서 거부. |
| 데이터 손상 | legacy native 해석 실패는 기존 유효한 local/archive 투영과 `nativeSync` 안내로 귀결. 잘린 본문을 빈 완성본으로 쓰거나 이미 출판된 최신 세대를 반쪽으로 교체하지 않는다. |

## 14. 성능 예산과 한계

| 측정 | 제안한 계약 |
|---|---|
| 1회 응답 한도 | 새 페이지는 메타 포함 UTF-8 JSON 표현 **256 KiB**, 메시지 헤더 **128**, part 설명 **256** 이내. 마지막 한도에 닿기 전 자르고 1개 lookahead는 본문 없는 키/길이로 한다. 기존 0325 문자/조각 한도는 전량 경로에서 유지한다. |
| 거대 본문 | 요청당 원문 최대 **64 KiB**. 본문 길이와 조각 경계를 쓰기 시 기록하고 건너뛸 payload에 JSON.parse/전체 stringify를 수행하지 않는다. wire escaping 포함 총 응답 한도도 별도 적용하며 같은 논리 offset에서 진척하는 양수 바이트를 반환한다. 원문은 명시 요청으로 전체 내용을 복원·내보낼 수 있다. |
| 첫 paint 전 | 일반 열기에서 page 응답 1개·실제 본문 commit 1회. 세션 제어 메타(제목 등)도 envelope의 UTF-8 예산에 포함한다. 과대 가변 메타는 참조·유효한 축약 표시 후 별도 조회. DB 본문 인출/직렬화/검증·reducer 방문·wire bytes를 독립 계수하고 동일 최신 턴에 과거 payload 읽기 0을 확인한다. |
| 검색 클릭부터 첫 표시 | data에서 캐시 검증+세대 변경 시 안정 출처 재해소 1회 이내. cold/부재면 목표를 담는 §14 예산의 응답 ≤1묶음, 확인된 캐시면 본문 재전송 0. 최신/중간의 무관 턴 본문 읽기 0. 측정 구간은 클릭→locator 전달→DB seek→응답 bytes→창 반영→올바른 행의 첫 가시 paint이다. 이후 위/아래 끝 입력은 조작당 응답 ≤1묶음이고 합류는 추가 요청 0(이미 받은 메시지를 넘긴다). |
| 유휴 채움 (D-009) | 묶음당 위 1회 응답 한도. 한 턴의 자동 읽기 총량은 그 턴 전체이며 원천 상한이 없다 — 묶음 수 = max(⌈메시지/128⌉, ⌈part/256⌉, ⌈bytes/256 KiB⌉). AC2의 20만 빈 메시지 단일 턴은 1,563묶음, 600메시지·900part 턴은 5묶음이다. 유휴 콜백 1회에 1묶음, 직전 commit 전 다음 요청 0, 사용자 입력 중 0. |
| 제스처 경계 | ΔV1: 보정 취소 분류에도 같은 값을 쓴다(D-020). OpenCode `ScrollController.tsx:141`의 250 ms `gestureUntil`(pin 판정)은 별개 창이며 바꾸지 않는다. `HISTORY_GESTURE_GAP_MS` 기본 200 ms(100~400). Linux Chromium의 Q4b 관성 열로 요청 1회를 확인하고, Windows 정밀 터치패드·휠 값은 S-E2가 기록해 0330에 넘긴다. |
| 패널 요약 | 종류별 페이지는 위 1회 응답 한도와 같은 256 KiB·항목 128 이내, 상세는 항목 1개 요청. 첫 화면 패널은 첫 페이지 1개만 요청하고 나머지는 패널 스크롤에서 keyset으로 읽는다. 요약 갱신은 쓰기 트랜잭션당 바뀐 항목만 upsert한다. |
| 입력 증가 | §8 분모에 동일한 최신 턴을 붙여 1/100/10,000턴 변화를 본다. 1턴에 20만 빈 메시지면 첫 요청은 ≤128개. 4MiB 한 part면 본문 열기 전 payload 읽기 0, 이후 실제 조각 수·원문과 일치 여부를 비교. B 앞삽입 비용은 1턴·100턴에 각각 1턴을 추가해 기존 방문·할당과 프레임을 기록한다. |
| 구 DB의 첫 실행 (D-018) | 단일 `payload_json/archive_json`에는 과거 전체를 한번도 해석하지 않고 정확한 안정 키·소유·전후 턴을 제공할 색인이 없다. 그래서 미출판 세션 첫 클릭의 data 쪽 비용은 그 세션 원본 전량 해석 + 투영 쓰기다(1회). wire·창 쪽은 그 클릭에도 위 1회 응답 한도를 지킨다. Q10이 작은 DB·긴 DB의 색인 전/중/후 변환 시간·DB/WAL 증가·읽은 과거 본문 bytes·IPC bytes·클릭→첫 본문과 재기동 재개를 기록한다. 준비 중 화면·스피너·빈 틀은 성공 paint가 아니며, 미출판 세션 첫 클릭은 AC1에 넣지 않고 AC11로만 적는다. |
| 나눌 수 없는 해석 (선언 경계) | 한 세션의 단일 `payload_json` 해석(`JSON.parse`)은 조각으로 나눌 수 없어, 그 시간만큼 data의 다른 요청이 기다린다. §8 실험의 10만 메시지 local 전체 조립 중앙값 555 ms가 같은 차수의 기준이다. Q10이 긴 DB의 최대 해석 시간을 기록하고 허용치는 0330이 정한다. 이 경계 안의 지연은 AC11 기록 대상이지 EP9 ③ 위반이 아니다. |
| 저장 비용 | 새 투영은 디스크를 더 쓴다. 변경 세대 출판까지 직전 정상 투영만 제공하고 커서는 stale로 재시작 가능하므로 오래된 세대는 사용하는 트랜잭션을 마친 뒤 회수한다. 실기 p95/최대 허용치는 W에서 결정한다. |

## 15. 외부/공개 계약

`SearchHit`에 안정 locator를 추가하고 기존 숫자 ID·발췌·검색 순위를 보존한다. `shared/{ipc,protocol,data-host,channel-owner}.ts`·창 `sessionApi`·data handler·`docs/IPC_CONTRACT.md`에 target 요청, 출처/세대 검사, 제한 문맥/캐시 재사용 판별, 취소·소실을 함께 명시한다. rev 5에서 `laterTurn`·`withinTurn{direction}`·`before/after`·`reachedLatest`, `panelSummary`·`panelDetail`, 미출판 세션의 요청 보류와 `prepared` 진단을 같은 문서에 더한다. 채널 접두사는 `oo:`(`shared/ipc.ts:89` `oo:session:load` 관례). 전량 보관 복구 계약은 독립적이다.
